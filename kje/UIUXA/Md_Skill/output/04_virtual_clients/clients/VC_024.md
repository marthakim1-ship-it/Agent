# VC-024 — 노현석

## 1. 생성 정보
- Client ID: VC-024
- 생성 유형: synthetic virtual client
- 기반 Source: SRC-BRAND-001, SRC-PDF-001, SRC-PDF-002, SRC-REF-003
- 기반 Evidence: EVD-0037
- Evidence Confidence: Medium

## 2. 기본 정보
- 역할: 기업·캠퍼스 복지 도입 책임자
- 담당 영역: 단체 도입 검토와 구성원 안내
- 프로젝트 관점: 개인 구매 정보와 기관 검토 정보를 분리
- 핵심 타깃: 사내 복지·학교 매점·행사 간식 도입 담당자와 실제 이용자
- 주요 사용 상황: 공급 제안 검토, 구성원 공지, 대량 배포
- 사업 목표: 검증된 제품·운영 조건을 기반으로 기관 도입 가능성 판단
- 전환 목표: 요구 조건 확인 후 공식 문의 또는 자료 요청

## 3. 핵심 사용자 문제
- 개인용 홍보 정보만으로는 공급 단위·알레르기·보관·운영 책임을 판단할 수 없다.

## 4. 중요하게 보는 가치
- 적용 범위, 공급 안정성, 안전 정보, 담당자 연결, 문서화

## 5. 정보 우선순위
- 제품 범위 → 대상·주의 → 보관·배포 조건 → 공급 상태 → 문의

## 6. 기능 요구
- 기관용 자료 목록, 조건 체크리스트, 담당 문의 후보

## 7. UX 요구
- 개인 소비자 흐름과 기관 도입 흐름을 혼합하지 않음

## 8. UI 요구
- 결정 조건·미확정 항목·필요 문서를 표로 비교

## 9. 콘텐츠 요구
- 단체 도입 사례는 실제 계약·승인 후에만 공개

## 10. 비주얼 요구
- 실제 배포·보관 환경을 설명하는 승인 자산 사용

## 11. 신뢰 요구
- 공급 수량·가격·납기·인증을 임의 확정하지 않음

## 12. 전환·구매 요구
- 도입 조건이 확정된 경우에만 담당 문의 CTA 제공

## 13. 반응형·디바이스 요구
- 모바일 1차 검토와 데스크톱 문서 비교를 모두 지원

## 14. 금지·회피 사항
- 존재하지 않는 B2B 계약·납품·할인·공급 보장 생성
