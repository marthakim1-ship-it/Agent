# VC-031 — 류지민

## 1. 생성 정보
- Client ID: VC-031
- 생성 유형: synthetic virtual client
- 기반 Source: SRC-BRAND-001, SRC-BRIEF-001
- 기반 Evidence: EVD-0044, EVD-0045, EVD-0046
- Evidence Confidence: High

## 2. 기본 정보
- 역할: 상품 정보 아키텍처·카탈로그 거버넌스 책임자
- 담당 영역: 상품 판매 단위·구성 분류·통합 식별자·페이지 간 상품 정보 정합성
- 프로젝트 관점: 카드 수가 아니라 같은 기준으로 구분되는 고유 상품·추천 조합·구성 옵션을 관리
- 핵심 타깃: 메인·카테고리·브랜드 소개 페이지에서 상품 체계를 이해하고 비교하는 방문자
- 주요 사용 상황: 상품군 정의, 페이지 콘텐츠 작성, 구성 선택 UI 검토, 공개 전 교차 검수
- 사업 목표: 하나의 상품 기준표를 통해 중복 생성·잘못된 상품 수·미확정 판매 정보 노출을 방지
- 전환 목표: 사용자가 구성 방식을 이해한 뒤 추천 조합을 검토하고, 확정된 경우에만 구매 단계로 이동

## 3. 핵심 사용자 문제
- 같은 구성 요소가 페이지마다 다른 상품명·번호·상품군·상태로 보이면 실제 판매 상품과 선택 옵션을 구분하기 어렵다.

## 4. 중요하게 보는 가치
- 단일 기준, 식별 가능성, 상태 투명성, 비교 가능성, 변경 추적성

## 5. 정보 우선순위
- 판매 단위 근거 → 분류 → 통합 식별자 → 이름·상품군 → 용량·구성 → 핵심 특징 → 상태

## 6. 기능 요구
- 상품 통합 기준표, 고유 식별자, 상태 필드, 페이지 간 정합성 검사, 변경 승인 기록

## 7. UX 요구
- 독립 상품·추천 조합·구성 옵션을 먼저 구분하고, 모든 항목을 동일한 정보 순서로 비교

## 8. UI 요구
- 대표 영역은 선정 이유를, 전체 목록은 비교 정보를 보여주며 같은 항목을 중복 상품으로 세지 않음

## 9. 콘텐츠 요구
- 상품 또는 구성 이름 → 상품군 → 용량·구성 → 핵심 특징 → 상태 순서를 공통 규칙으로 사용

## 10. 비주얼 요구
- 회색 와이어프레임·큰 제목·넓은 여백을 유지하고 제품 패키지·원형·곡선은 브랜드 인상을 회수하는 구간에 선택적으로 사용

## 11. 신뢰 요구
- 확인되지 않은 용량·판매 단위·가격·영양·알레르기·운영 정책을 확정 정보처럼 만들지 않음

## 12. 전환·구매 요구
- 구성 이해 → 추천 조합 확인 → 향후 구매·정기배송 순으로 CTA 확정성을 단계화

## 13. 반응형·디바이스 요구
- 좁은 화면에서도 상품명·상품군·상태가 먼저 식별되고 용량·구성과 특징의 대응 관계가 깨지지 않음

## 14. 금지·회피 사항
- 화면 카드 수를 상품 수로 계산, 페이지별 임의 번호 확장, 미확정 구성을 독립 판매 상품으로 단정, 준비 중 서비스를 즉시 구매 CTA로 표현
