# VC-028 — 배지훈

## 1. 생성 정보
- Client ID: VC-028
- 생성 유형: synthetic virtual client
- 기반 Source: SRC-BRAND-001, SRC-PDF-001, SRC-PDF-002, SRC-REF-001
- 기반 Evidence: EVD-0041
- Evidence Confidence: Medium

## 2. 기본 정보
- 역할: 주문 후 문제 해결 책임자
- 담당 영역: 오배송·파손·변질 의심·환불·교환 안내
- 프로젝트 관점: 구매 이후 문제를 제품 안전 이슈와 일반 주문 문제로 구분
- 핵심 타깃: 주문·배송 결과에 문제가 있어 빠른 해결이 필요한 사용자
- 주요 사용 상황: 상품 수령, 주문 확인, 사진·정보 제출, 처리 상태 확인
- 사업 목표: 반복 문의와 불안 감소, 정확한 담당 경로 연결
- 전환 목표: 문제 유형 확인 후 공식 지원 절차 완료

## 3. 핵심 사용자 문제
- 판매 채널과 정책이 미확정이면 사용자는 브랜드·판매처 중 어디에 문의해야 하는지 알기 어렵다.

## 4. 중요하게 보는 가치
- 책임 범위, 긴급도, 최소 입력, 처리 상태, 복구

## 5. 정보 우선순위
- 안전 긴급 여부 → 문제 유형 → 주문·제품 식별 → 제출 정보 → 상태·다음 행동

## 6. 기능 요구
- 문제 유형 분기, 최소 정보 입력, 접수 상태, 판매처 연결

## 7. UX 요구
- 안전 이슈는 일반 환불보다 먼저 안내하고 동일 내용을 반복 입력시키지 않음

## 8. UI 요구
- 현재 단계·필요 자료·예상 다음 행동을 텍스트로 표시

## 9. 콘텐츠 요구
- 실제 환불·교환·보상 범위를 정책 없이 단정하지 않음

## 10. 비주얼 요구
- 제품 식별·손상 확인용 이미지 예시는 승인 자료만 사용

## 11. 신뢰 요구
- 제출 데이터 목적·보관·담당 주체를 명시

## 12. 전환·구매 요구
- 해결 전 추가 구매를 우선 권유하지 않음

## 13. 반응형·디바이스 요구
- 모바일 촬영·입력 중 임시 저장과 오류 복구 후보

## 14. 금지·회피 사항
- 존재하지 않는 환불·교환·보상 약속, 과도한 개인정보 요구
