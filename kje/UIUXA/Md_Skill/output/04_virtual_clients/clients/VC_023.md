## 2. 기본 정보
- 역할: 냉장 유통·보관 정보 책임자
- 담당 영역: 배송 수령부터 보관·섭취까지 상태 정보
- 프로젝트 관점: 신선식품의 보관 조건과 이상 상태를 사용자 행동으로 연결
- 핵심 타깃: 배송·이동 후 제품 상태와 안전한 섭취 조건을 확인하는 사용자
- 주요 사용 상황: 배송 수령, 냉장고 보관, 이동 중 휴대, 개봉 전후
- 사업 목표: 보관 정보 오해와 불필요한 폐기·문의 감소
- 전환 목표: 보관 조건 확인 후 적합한 제품·지원 경로로 이동

## 3. 핵심 사용자 문제
- 실제 보관 온도·시간·유통기한이 미확정이면 이동 편의 메시지를 안전한 보관 가능성으로 오해할 수 있다.

## 4. 중요하게 보는 가치
- 안전, 시간·온도 조건, 상태 판별, 복구, 출처

## 5. 정보 우선순위
- 보관 조건 → 개봉 상태 → 이상 징후 → 행동 지침 → 문의

## 6. 기능 요구
- 상태별 보관 안내, 수령 점검표, 이상 제품 문의 연결

## 7. UX 요구
- 정상·주의·폐기·문의 조건을 행동 중심으로 구분

## 8. UI 요구
- 온도·시간을 색상만이 아닌 숫자·단위·문장으로 표시

## 9. 콘텐츠 요구
- 이동 상황 이미지와 실제 보관 가능 시간을 별도 근거로 관리

## 10. 비주얼 요구
- 냉장·개봉·이상 상태를 식별하는 실제 승인 이미지 우선

## 11. 신뢰 요구
- 시험·유통 자료 없는 상온 유지·신선도 주장을 금지

## 12. 전환·구매 요구
- 배송·판매 조건 확정 전 도착 보장 문구를 활성화하지 않음

## 13. 반응형·디바이스 요구
- 제품 옆에서 모바일로 빠르게 보관·이상 상태를 확인

## 14. 금지·회피 사항
