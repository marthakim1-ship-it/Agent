# VC-021 — 김서준

## 1. 생성 정보
- Client ID: VC-021
- 생성 유형: synthetic virtual client
- 기반 Source: SRC-BRAND-001, SRC-REF-001, SRC-REF-002, SRC-REF-003
- 기반 Evidence: EVD-0034
- Evidence Confidence: Medium

## 2. 기본 정보
- 역할: 검색 유입·콘텐츠 발견성 책임자
- 담당 영역: 검색 의도와 검증된 제품 정보의 연결
- 프로젝트 관점: 외부 검색에서 유입된 사용자가 기대한 질문과 YOVIA의 실제 제품 정보를 같은 페이지에서 확인하도록 조정
- 핵심 타깃: 브랜드명·그릭요거트·락토프리·무가당·간편 아침 관련 정보를 검색해 들어온 첫 방문자
- 주요 사용 상황: 모바일 검색 결과, 공유 링크, 제품·사용법·성분 페이지 직접 진입
- 사업 목표: 검증된 정보의 발견 가능성과 페이지별 목적 명확화
- 전환 목표: 검색 의도에 맞는 정보 확인 후 관련 제품·사용법·검증 정보로 이동

## 3. 핵심 사용자 문제
- 검색 결과의 제목·설명과 도착 페이지 내용이 다르거나 페이지마다 같은 정보가 반복되면 사용자는 YOVIA의 실제 제품 범위와 근거 상태를 판단하기 어렵다.

## 4. 중요하게 보는 가치
- 검색 의도 일치, 페이지 고유성, 검증된 사실, 맥락 있는 내부 연결, 미확정 정보의 색인 통제

## 5. 정보 우선순위
- 사용자 질문 → 한 문장 답변 → 제품·사용법·성분 근거 → 관련 페이지 → 다음 행동

## 6. 기능 요구
- 페이지별 고유 제목·설명 후보, 관련 콘텐츠 링크, 현재 페이지와 제품 맥락, 검증 상태 표기

## 7. UX 요구
- 검색으로 상세 페이지에 직접 들어와도 브랜드 정의와 현재 정보 범위를 이해하고 상위·관련 정보로 이동

## 8. UI 요구
- 질문과 답을 가까이 배치하고 제목 계층·링크 이름·상태 라벨을 일관되게 제공

## 9. 콘텐츠 요구
- 중복 카피를 줄이고 페이지마다 하나의 검색 질문과 검증 가능한 답을 중심으로 구성

## 10. 비주얼 요구
- 검색 의도와 무관한 장식보다 제품·구성·사용 과정의 설명 자산을 우선

## 11. 신뢰 요구
- 구조화 데이터·리뷰·가격·재고·효능에는 실제 승인 자료만 사용

## 12. 전환·구매 요구
- 정보 질문을 해결한 뒤 관련 제품·사용법·검증 정보로 연결하고 판매 채널 미확정 시 구매 CTA를 활성화하지 않음

## 13. 반응형·디바이스 요구
- 모바일 검색 유입에서 제목·한 문장 답변·핵심 근거·관련 링크 순서를 유지

## 14. 금지·회피 사항
- 모든 페이지에 같은 제목·설명 사용, 검색용 키워드 반복, 미확정 가격·재고·리뷰·효능의 구조화 데이터 생성
