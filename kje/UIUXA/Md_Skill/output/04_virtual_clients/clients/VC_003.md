# VC-003 — 이수민, 성분·영양 신뢰 책임자

## 1. 생성 정보
- Client ID: VC-003
- 생성 유형: synthetic virtual client
- 기반 Source: SRC-BRAND-001, SRC-PER-001, SRC-PER-002, SRC-PDF-003
- 기반 Evidence: EVD-0005, EVD-0010, EVD-0013, EVD-0014
- Evidence Confidence: High (경계 원칙), Medium/Low (세부 요구)

## 2. 기본 정보
- 역할: Ingredient Transparency & Trust Lead (synthetic)
- 담당 영역: 원료·영양·알레르기·인증·효능 정보 거버넌스
- 프로젝트 관점: 건강식 신뢰를 높이되 검증되지 않은 수치와 효능을 차단하는 발주자
- 핵심 타깃: 성분을 비교하고 유당·첨가물·알레르기 가능성을 확인하는 사용자
- 주요 사용 상황: 구매 전 모바일 비교, 제품 상세 확인
- 사업 목표: 과장 없는 정보 투명성으로 구매 불안을 낮춤
- 전환 목표: 신뢰 정보를 확인한 사용자의 제품 검토·구매 의향 형성

## 3. 핵심 사용자 문제
- 건강식 마케팅 문구만으로는 실제 성분과 적합성을 판단하기 어렵다.
- 락토프리·무가당과 실제 영양 수치·인증 범위가 혼동될 수 있다.
- 장 건강·이너뷰티 등 다수 효능 요구는 검증되지 않았다.

## 4. 중요하게 보는 가치
- 투명성, 정확성, 알레르기 배려, 근거 수준 표시

## 5. 정보 우선순위
1. 확정 제품 정의 2. 원료·성분 3. 영양·알레르기 4. 인증 범위 5. 효능 검증 상태

## 6. 기능 요구
- 정보 상태와 출처를 구분하고 사용자가 세부 정보를 찾을 수 있게 한다.

## 7. UX 요구
- 핵심 성분은 빠르게, 상세 근거는 단계적으로 확인하게 한다.

## 8. UI 요구
- CONFIRMED·CANDIDATE·NOT_VERIFIED를 혼동하지 않는 상태 표현을 사용한다.

## 9. 콘텐츠 요구
- 건강·의료 효능을 암시하거나 임의 수치를 만들지 않는다.

## 10. 비주얼 요구
- 의료기관처럼 보이지 않는 정돈되고 친근한 정보 표현을 사용한다.

## 11. 신뢰 요구
- 모든 인증·시험·영양 수치는 실제 문서와 연결되어야 한다.

## 12. 전환·구매 요구
- 신뢰 정보가 구매 흐름을 방해하지 않으면서도 숨겨지지 않게 한다.

## 13. 반응형·디바이스 요구
- 모바일에서 표와 주석을 읽기 쉬운 계층으로 변환한다.

## 14. 금지·회피 사항
- 장 건강 개선, 붓기 완화, 목 보호, 피부 개선 등을 검증 전 사실처럼 표현하지 않는다.
