> 이 문서는 `.agents/skills/analyze/SKILL.md`의 필수 출력 구조에 맞춘 분석 작성용 MD다.

- **Phase 1·누적 20개**: `초기 가설` 또는 `초기 결론`
- **Phase 2·누적 70개**: `중간 검증` 또는 `중간 결론`
- **Phase 3·누적 200개**: `최종 분석` 또는 `최종 결론`
- Phase 1과 Phase 2의 결과를 `200개 전체 경향`으로 표현하지 않는다.

## 1. 분석 개요

### 1.1 분석 목적

- 리서치 원본과 분류 결과의 버전·수량·ID 연결을 확인한다.
- 분류 단계에서 집계한 공통 디자인 패턴을 원본 리서치로 검증한다.
- 검증된 분류 집계값을 재사용한다.
- 제품 관련성과 디자인 적합도에 따른 공통점과 차이를 분석한다.
- 선정 디자인 콘셉트의 타당성·모바일 적합성·구현 가능성을 검토한다.
- YOVIA 적용 방향·우선순위·난이도·위험·대안을 도출한다.

- [ ] 제외·보류·중복 기준이 명확하다.
- [ ] 두 분류 축의 수량 공식이 성립한다.
- [ ] 선정 콘셉트·선정 방식·주·보조 역할이 존재한다.

### 분류 집계 검증

- [ ] 분류의 공통 디자인 집계값을 먼저 읽었다.
- [ ] 핵심 집계의 분자·분모·출처를 원본과 대조했다.
- [ ] 검증된 집계값을 재사용했다.
- [ ] 불일치를 임의 수정하지 않고 `분류 재검토 필요`로 기록했다.
- [ ] 중복·dead·failed·partial 처리 기준이 일치한다.

### 분석 정확성

- [ ] 전체 공통점이 실제 유효 대상에 기반한다.
- [ ] 각 핵심 패턴에 관찰 수 또는 집계 불가 사유가 있다.
- [ ] 대표 출처와 예외 출처가 연결된다.
- [ ] 단일 사례를 전체 경향으로 과장하지 않았다.
- [ ] 직접·인접·주변의 차이를 구분했다.
- [ ] 핵심·보조·요소 참고·비적합의 차이를 구분했다.
- [ ] 제품 관련성과 디자인 적합도를 교차 분석했다.
- [ ] `partial`과 미확인 정보를 확정 사실로 사용하지 않았다.

### 선정 콘셉트 타당성

- [ ] 선정 방식이 정확히 기록되었다.
- [ ] 공통 패턴과 대표 출처가 선정 콘셉트를 지지한다.
- [ ] YOVIA 핵심 경험과 연결된다.
- [ ] 모바일 확장성과 유지 가능성을 검토했다.
- [ ] 구현 난이도와 필요한 자산을 기록했다.
- [ ] 위험·중단 조건·대안 콘셉트를 포함했다.

### 적용 타당성

- [ ] 관찰·해석·YOVIA 적용 제안을 분리했다.
- [ ] 데스크톱과 모바일을 구분했다.
- [ ] 구현 난이도와 위험을 함께 기록했다.
- [ ] 우선순위마다 이유가 있다.
- [ ] 확정되지 않은 수치·기능을 만들지 않았다.

### 문서 완성도

- [ ] 핵심 주장마다 출처 ID가 있다.
