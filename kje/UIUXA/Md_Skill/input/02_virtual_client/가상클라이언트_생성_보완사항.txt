[가상 클라이언트 생성 보완 지침]

(문서 성격)
- 이 문서는 YOVIA의 브랜드 확정 사실을 추가하는 정본이 아니라, 기존 가상 클라이언트가 놓친 상품 정보 구조와 페이지 간 정합성 관점을 보완하는 발주 브리프다.
- 기존 클라이언트와 관점이 일부 겹치더라도 같은 요구를 반복 생성하지 않고, 상품 단위·통합 번호·분류 기준·페이지 간 일치 여부처럼 더 구체적인 책임으로 확장한다.
- 기존 클라이언트를 대체하거나 삭제하지 않는다. 새 관점이 독립적인 의사결정 책임을 가질 때만 별도 클라이언트로 생성하고, 그렇지 않으면 관련 기존 클라이언트의 Requirement 보완 근거로 사용한다.

(보완 역할)
- YOVIA의 판매 단위와 구성 단위를 정의하고, 메인·카테고리·브랜드 소개에 동일한 상품 체계가 적용되도록 관리하는 상품 정보 아키텍처·카탈로그 거버넌스 책임자
- 일반적인 콘텐츠 최신성 관리보다 상품의 고유성, 옵션 관계, 추천 조합, 번호 체계와 페이지별 표현 일치를 중점적으로 판단한다.

(기존 관점과의 연결)
- 제품 이해와 전환 관점은 기존 제품 경험·전환 책임자의 요구를 반복하지 않고, 상품 구조가 다음 행동을 오해 없이 지원하는지 검증하는 기준으로 연결한다.
- 제품 중심 비주얼과 브랜드 기억 관점은 기존 브랜드 콘텐츠·크리에이티브 책임자의 요구를 반복하지 않고, 상품군이 길어져도 공통 시각 언어가 유지되는지 검증하는 기준으로 연결한다.
- 용량·가격 투명성 관점은 기존 가치·가격 투명성 책임자의 요구를 반복하지 않고, 용량이 독립 상품인지 옵션인지 구분하는 선행 기준으로 연결한다.
- 콘텐츠 단일 출처 관점은 기존 콘텐츠 운영·자산 거버넌스 책임자의 요구를 반복하지 않고, 상품 전용 Single Source of Truth와 통합 번호 관리로 구체화한다.
- 정기배송 관점은 기존 반복 구매·정기배송 경험 책임자의 요구를 반복하지 않고, 상품 구성 이해보다 미래 서비스 CTA가 앞서지 않는지 검증하는 기준으로 연결한다.
- 출시 QA 관점은 기존 출시 전 경험 QA 책임자의 요구를 반복하지 않고, 세 페이지의 상품명·번호·상품군·상태를 교차 검사하는 완료 조건으로 구체화한다.

(현재 문제)
- 상품 수는 충분하지만 독립 판매 상품, 용량 변형, 구성 옵션, 추가 선택 옵션과 추천 조합을 세는 기준이 섞여 있다.
- 동일한 상품 또는 구성이 메인·카테고리·브랜드 소개에서 서로 다른 번호·이름·상품군·상태로 표현된다.
- 화면 번호와 실제 상품·구성 번호가 혼용되어 카드 수가 상품 수처럼 해석될 수 있다.
- 대표 상품 영역과 전체 상품 영역이 같은 설명을 반복해 각각의 역할이 약해진다.
- 첫 화면의 원형·곡선·제품 패키지 중심 인상이 긴 상품 비교 구간에서 약해진다.
- 실제 구매 기능이 아닌 구성 예시에서 정기배송 CTA가 앞서면 서비스 확정 단계가 실제보다 높아 보일 수 있다.

(보완 목표)
- YOVIA에서 무엇을 하나의 독립 상품으로 세고 무엇을 옵션이나 추천 조합으로 세는지 먼저 정의한다.
- 상품 또는 구성마다 하나의 통합 번호와 표준 명칭을 부여하고 세 페이지가 같은 기준을 참조하게 한다.
- 대표 3종은 선정 이유를 설명하고, 전체 영역은 상품군 안의 위치와 차이를 비교하도록 역할을 분리한다.
- 확인된 사실과 제안·보류·확인 필요 정보를 구분하되 상태 표시가 핵심 브랜드 문장과 상품 차이보다 강해지지 않게 한다.
- 원형·곡선·제품 패키지라는 공통 시각 언어를 상품군 전환과 주요 장면에 선택적으로 이어간다.

(유지 요구)
- `바쁜 하루, 한 팩에 담은 세 가지 구성`이라는 제품 중심 첫 문장
- 제품 패키지와 원형·곡선 그래픽을 크게 사용한 첫 화면
- 베이스 팩, 생과일 퓨레와 견과류 토핑의 관계를 상품보다 먼저 설명하는 구조
- 출근·등교 전, 업무 사이, 캠퍼스와 활동 후의 네 가지 일상 장면
- `이번 아침은 내 취향대로`에서 베이스·퓨레·토핑 관계를 보여주는 구성 탐색 예시
- 120g 모닝 파우치, 7AM 갓생 팩과 스타터 팩을 서로 다른 역할의 대표 항목으로 사용하는 방향
- 대표 항목을 전체 상품 체계에 다시 포함하되 전체 수량에는 중복 계산하지 않는 방식
- 기본 팩, 퓨레, 토핑, 시그니처 팩과 스타터 팩의 현재 분류 명칭
- 확정·제안·보류·확인 필요를 구분하고 미확인 가격·영양·알레르기·판매 정책을 확대하지 않는 기준
- 회색 와이어프레임, 둥근 카드, 넓은 여백과 큰 제목을 사용하는 디자인 방향

(상품 정보 구조 요구)
- 기본 팩 120g·400g·800g이 각각 독립 상품인지 하나의 상품 안의 용량 옵션인지 근거와 함께 판정한다.
- 생과일 퓨레 10개가 단독 판매 상품인지 기본 팩의 구성 옵션인지 구분하고, 확인되지 않은 용량과 판매 단위를 만들지 않는다.
- 견과류 토핑 5개가 단독 판매 상품, 팩 내부 구성 옵션 또는 추가 선택 옵션 중 어디에 해당하는지 구분한다.
- 시그니처 팩과 스타터 팩이 독립 판매 상품인지 추천 조합 또는 제안 상품인지 상태와 함께 구분한다.
- 상품 수는 화면 카드 수가 아니라 동일 기준으로 구분되는 고유 상품·추천 조합·구성 옵션을 기준으로 계산한다.
- 최소 수량을 맞추기 위해 이름만 다른 항목이나 의미 없는 카드를 추가하지 않는다.

(Single Source of Truth 요구)
- 통합 번호, 상품 또는 구성 이름, 상품군, 용량·구성, 핵심 특징, 분류, 상태와 판단 근거를 포함한 상품 통합 기준표를 작성하도록 요구한다.
- 통합 번호는 화면 번호와 구분되는 별도 체계를 사용한다.
- 동일한 상품 또는 구성은 모든 페이지에서 같은 통합 번호·명칭·상품군·분류·상태를 사용한다.
- 메인페이지에서만 새로운 상품명이나 번호를 확장하지 않는다.
- 상품 정보의 기본 표시 순서는 `이름 → 상품군 → 용량·구성 → 핵심 특징 → 상태`로 통일한다.
- 미확인 용량·판매 단위·구성 수량은 임의 숫자로 채우지 않고 `용량 확인 전`, `판매 단위 확인 전` 또는 이에 준하는 상태로 남긴다.

(페이지별 역할 요구)
- 대표 영역은 왜 대표로 선정했는지, 어떤 라이프스타일과 조합 경험을 대표하는지를 설명한다.
- 전체 상품 영역은 상품명·상품군·용량 또는 구성·핵심 차이·현재 상태를 빠르게 비교하게 한다.
- 브랜드 소개는 브랜드 시작 이유를 유지하면서 퓨레와 토핑을 독립 상품처럼 과장하지 않고 현재 분류와 상태를 보여준다.
- 메인페이지는 건강한 식사를 따로 준비하는 번거로움과 `기본 팩 + 생과일 퓨레 + 견과류 토핑` 구조를 짧게 연결한다.
- 구성 선택 UI는 실제 구매 기능이 아니라 설계 예시임을 명확히 하고 `구성 이해 → 추천 조합 확인 → 향후 구매·정기배송` 순서로 행동 강도를 조정한다.

(디자인 보완 요구)
- 대표 상품과 일반 상품의 크기·여백·정보량 차이를 강화한다.
- 기본 팩, 생과일 퓨레, 견과류 토핑, 시그니처 팩과 스타터 팩의 상품군 전환이 느껴지도록 구간을 나눈다.
- 반복 카드가 필요한 비교 구간과 큰 장면이 필요한 브랜드·사용 상황 구간을 구분한다.
- 원형·곡선은 장식처럼 무조건 반복하지 않고 상품군 전환, 구성 관계 또는 핵심 장면을 설명하는 지점에 사용한다.
- 상태 라벨은 유지하되 브랜드 문장, 상품명과 핵심 차이보다 시각적 우선순위를 낮춘다.

(완료 기준)
- 전체 상품 수를 독립 상품·추천 조합·구성 옵션의 동일한 계산 기준으로 한 문장에 설명할 수 있다.
- 통합 기준표의 모든 번호와 상품 정보가 메인·카테고리·브랜드 소개에서 일치한다.
- 대표 3종이 서로 다른 역할과 선정 이유를 가지며 전체 상품 체계 안의 위치와 연결된다.
- 대표 영역과 전체 영역에서 동일 설명을 반복하지 않고 각각 가치 설명과 비교·탐색 역할을 수행한다.
- 구성 예시의 CTA가 현재 서비스 확정 수준을 넘지 않는다.
- 확정되지 않은 가격·영양·알레르기·용량·판매 단위·정기배송 정책이 확정 사실처럼 표현되지 않는다.
- 상품 비교가 길어져도 필요한 지점에서 YOVIA의 원형·곡선·제품 패키지 시각 언어가 이어진다.
- 외부 레퍼런스의 원리는 YOVIA의 문장·상품·분류·상태 기준으로 다시 표현한다.
- 기존 클라이언트와 의미가 같은 Requirement를 새 ID로 반복 생성하지 않고, 새 책임과 판단 기준이 있는 요구만 추가한다.
