# 01. 가상 사용자 모니터링 결과

## 1. 모니터링 개요

- **대상 파일**: `디자인/웹디자인_수정본.html`
- **모니터링 일자**: 2026-08-28
- **공통 과제**: 그릭요거트 베이스, 생과일 퓨레, 견과류 토핑을 선택하여 원하는 구성을 확인하고 구매 다음 행동을 찾는다.
- **방법**: 현재 HTML의 화면·코드를 직접 확인한 후, 서로 다른 행동 목표를 가진 5개 가상 페르소나로 휴리스틱 모니터링했다.
- **한계**: 실제 사용자 테스트나 실제 결제 테스트가 아니다. 가격·재고·판매·배송 정책은 확인되지 않아 구매 완료는 검증 범위에서 제외했다.

## 2. 모니터링 대상 선정

| Persona ID | 유형 | 서로 다른 핵심 행동 |
|---|---|---|
| P-01 | 직접 조합형 | 모든 구성을 처음부터 직접 선택 |
| P-02 | 비교 후 선택형 | 퓨레·토핑 후보를 읽고 비교한 후 조합 |
| P-03 | 빠른 구매형 | 최소한의 탐색으로 구성 완성과 다음 CTA 확인 |
| P-04 | 초보 탐색형 | 세 구성 요소의 관계와 선택 순서부터 학습 |
| P-05 | 추천 후 수정형 | 추천 조합을 불러온 후 특정 퓨레나 토핑만 변경 |

## 3. 가상 페르소나

### P-01 — 김서연 / 직접 조합형

- **나이**: 29세
- **직업**: 그래픽 디자이너
- **생활 패턴**: 평일 아침은 간단히 먹지만 맛과 식감 취향이 분명함
- **홈페이지 이용 환경**: 데스크톱 Chrome, 마우스와 키보드 병행
- **YOVIA 방문 목적**: 아침에 먹을 개인 취향 조합 확인
- **구매 목적**: 120g 모닝 파우치+청포도 퓨레+피스타치오 토핑
- **제품 선택 기준**: 개인 용량, 상큼한 풍미, 경쾌한 식감
- **디지털 숙련도**: 높음

#### 예상 행동 경로

1. 히어로에서 `제품 구성 보기`를 누른다.
2. 베이스·퓨레·토핑 역할을 확인한다.
3. 구성 예시에서 청포도 퓨레를 선택하려고 한다.
4. 피스타치오 토핑을 선택하려고 한다.
5. 요약에서 구성을 확인하고 구매 다음 행동을 찾는다.

- **문제 발생 지점**: 3단계. 옵션이 `span`이며 클릭 이벤트가 없어 선택이 바뀌지 않는다.
- **Complaint C-01**: “청포도랑 피스타치오를 고르고 싶은데, 단어는 보여도 눌러서 바꿀 수가 없어요. 위의 요약도 계속 딸기와 아몬드로만 보여요.”
- **기대 결과**: 각 단계에서 하나를 선택하고 요약이 즉시 갱신되기를 기대한다.
- **UX 문제 유형**: 제품 선택, 인터랙션, 선택 상태

### P-02 — 박준호 / 비교 후 선택형

- **나이**: 36세
- **직업**: 영업 매니저
- **생활 패턴**: 주 3회 운동, 한 번 선택할 때 여러 후보를 비교
- **홈페이지 이용 환경**: 13인치 노트북
- **YOVIA 방문 목적**: 퓨레 10개와 토핑 5개의 차이를 읽고 조합
- **구매 목적**: 업무 중 먹을 구성 후보 결정
- **제품 선택 기준**: 풍미·식감 설명과 선택 결과의 일치
- **디지털 숙련도**: 보통 이상

#### 예상 행동 경로

1. 전체 상품군 요약에서 퓨레와 토핑 이름을 읽는다.
2. 퓨레 카드를 위아래로 탐색한다.
3. 토핑 카드를 탐색한다.
4. 고른 후보를 구성 영역에서 선택하려고 한다.
5. 선택한 조합을 한 번에 비교·확인한다.

- **문제 발생 지점**: 4~5단계. 상품 설명 카드와 구성 예시 영역이 연결되지 않고, 요약은 고정 텍스트다.
- **Complaint C-02**: “퓨레 설명을 읽고 감귤로 정했는데 다시 위로 올라가서도 선택이 되는지 알 수 없어요. 조합 결과를 확인할 방법도 없고요.”
- **기대 결과**: 후보를 선택하면 현재 조합에 반영되고 선택된 상태가 명확히 남기를 기대한다.
- **UX 문제 유형**: 정보 구조, 탐색, 상태 확인

### P-03 — 이민지 / 빠른 구매형

- **나이**: 24세
- **직업**: 대학생
- **생활 패턴**: 등교 중 모바일로 빠르게 탐색
- **홈페이지 이용 환경**: 390px 너비 스마트폰, 터치
- **YOVIA 방문 목적**: 권장 구성을 빠르게 고르고 다음 단계로 이동
- **구매 목적**: 당일 아침용 구성 확인
- **제품 선택 기준**: 속도, 명확한 버튼, 최소한의 입력
- **디지털 숙련도**: 높음

#### 예상 행동 경로

1. 모바일에서 구성 영역으로 이동한다.
2. 기본으로 보이는 조합을 확인한다.
3. 필요하면 한 가지만 바꾼다.
4. 완성 상태를 확인한다.
5. 구매 버튼을 찾는다.

- **문제 발생 지점**: 3~5단계. 모바일에서 옵션이 줄바꿈되지만 터치해도 반응하지 않고, 구매 CTA가 없다.
- **Complaint C-03**: “딸기와 아몬드로 먹을 건데 이게 이미 선택된 건지 예시인지 모르겠어요. 다 골랐다고 해도 어디로 가야 사는 건지 안 보여요.”
- **기대 결과**: 현재 선택을 즉시 확인하고 구매 다음 행동을 한 번에 찾기를 기대한다.
- **UX 문제 유형**: 모바일 사용성, CTA, 구매 흐름

### P-04 — 최영숙 / 초보 탐색형

- **나이**: 53세
- **직업**: 행정직
- **생활 패턴**: 온라인 식품 구매 경험은 있지만 새로운 구성 방식은 천천히 확인
- **홈페이지 이용 환경**: 태블릿, 터치
- **YOVIA 방문 목적**: 팩·퓨레·토핑의 관계를 이해하고 실수 없이 선택
- **구매 목적**: 가정에서 먹을 구성 후보 확인
- **제품 선택 기준**: 순서 안내, 선택 완료 표시, 되돌리기 가능성
- **디지털 숙련도**: 보통 이하

#### 예상 행동 경로

1. `한 팩을 이루는 세 가지 역할`을 읽는다.
2. `구성 예시`가 실제 선택 영역인지 판단한다.
3. 1·2·3 순서로 선택한다.
4. 빠진 항목이 없는지 확인한다.
5. 최종 구성을 읽는다.

- **문제 발생 지점**: 2단계. `구성 예시`라는 표현과 선택된 모양이 같이 보이지만 실제 작동이 없어 화면 의미를 오해한다.
- **Complaint C-04**: “1번부터 3번까지 고르라는 것 같은데, 지금 녹색으로 보이는 게 선택된 건지 예시인지 구분이 안 돼요.”
- **기대 결과**: 선택 순서, 현재 단계, 완성 여부가 명확히 표시되기를 기대한다.
- **UX 문제 유형**: 정보 위계, 상태 확인, 행동 순서

### P-05 — 정하늘 / 추천 후 수정형

- **나이**: 32세
- **직업**: 콘텐츠 마케터
- **생활 패턴**: 새로운 제품은 추천안으로 시작하고 비선호 재료만 변경
- **홈페이지 이용 환경**: 노트북과 모바일 병행
- **YOVIA 방문 목적**: 시그니처·스타터 팩에서 시작해 특정 재료 변경
- **구매 목적**: 아침 추천 조합에서 아몬드를 호두로 변경
- **제품 선택 기준**: 추천의 편의성, 부분 수정 가능성
- **디지털 숙련도**: 높음

#### 예상 행동 경로

1. 시그니처·스타터 팩 카드를 확인한다.
2. `7AM 갓생 팩`을 선택하려고 한다.
3. 구성 영역으로 가서 추천 조합을 불러온다.
4. 아몬드 토핑만 호두 토핑으로 바꿄다.
5. 수정된 조합을 확인한다.

- **문제 발생 지점**: 2단계. 추천 조합 카드는 설명만 제공하고 구성 영역으로 값을 전달하지 않는다.
- **Complaint C-05**: “7AM 팩이 괜찮아 보이는데 아몬드만 호두로 바꾸고 싶어요. 카드를 봐도 이 조합을 고르기 화면으로 가져오는 방법이 없어요.”
- **기대 결과**: 추천 조합을 한 번에 불러온 후 선택한 항목만 변경하기를 기대한다.
- **UX 문제 유형**: 추천 흐름, 제품 선택, 페이지 내 연결

## 4. 모니터링 결과 종합

### 공통 문제

1. 모든 페르소나가 구성 옵션을 보지만 실제로 선택·변경할 수 없었다.
2. 우측 요약은 딸기·아몬드 고정 텍스트로, 사용자 행동을 반영하지 않았다.
3. 구성 예시가 완성됐는지와 다음 행동이 무엇인지 확인할 수 없었다.

### 특정 사용자 문제

- P-02는 상품 설명을 비교한 후 그 결과를 조합에 옮기는 연결이 부족했다.
- P-03은 모바일에서 선택과 CTA를 빠르게 확인할 수 없었다.
- P-04는 `예시`와 `현재 선택`을 구분하기 어려웠다.
- P-05는 추천 조합에서 시작해 부분만 수정할 수 없었다.

### 가장 심각한 문제

`C-01`, `C-03`, `C-04`에서 확인된 **실제 선택 작동 부재**다. 이는 사용자가 원하는 조합을 만든다는 핵심 목표 자체를 막는다.

### 클라이언트 요구와 연결되는 문제

- 베이스→퓨레→토핑을 선택하는 작동이 없다.
- 현재 선택 내용이 갱신·유지되지 않는다.
- 추천 조합을 개인 조합의 출발점으로 사용할 수 없다.
- 구매 다음 행동이 없다. 단, 실제 결제는 판매 정책 확인 전이므로 현재 수정 범위는 `선택 구성 확인·구매 준비 상태 안내`까지로 한정한다.
