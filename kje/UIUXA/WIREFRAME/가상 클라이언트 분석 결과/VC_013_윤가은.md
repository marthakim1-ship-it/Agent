# 가상클라이언트 기반 분석 결과 — VC-013 (윤가은)

## 1. 가상 클라이언트
- **프로젝트 주제**: 검증 FAQ와 고객지원 연결 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 사용법·보관·성분·구매 질문을 검증된 답변으로 분류하고 해결되지 않은 문제를 책임 있는 문의 경로로 연결한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0026`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

## 4. 내비게이션
- **시작 화면**: 주요 질문 유형과 중요한 알레르기·주의 정보를 먼저 보여준다. (VC013-REQ-001~002; SITE-001, SITE-024)
- **이동 경로**: 질문 유형 선택 → 검증 답변 → 관련 제품·주의 확인 → 미해결 시 문의 → 접수 상태 확인. (VC013-REQ-001~005; SITE-001, SITE-024, SITE-082)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC013-REQ-003~005; SITE-024, SITE-082)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC013-REQ-003~005; SITE-001, SITE-082)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `도움말`, `FAQ`, `문의`, `주의 정보` 접근 후보를 제공한다. (VC013-REQ-001~002; SITE-001, SITE-024)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC013-REQ-004~005; SITE-024, SITE-082)
- **핵심 콘텐츠**: 사용법·보관·성분·구매 질문별 승인 답변과 중요 주의사항. (VC013-REQ-001~003; SITE-001, SITE-024, SITE-082)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC013-REQ-003~005; SITE-024, SITE-082)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC013-REQ-006; SITE-001)

## 6. 검토 결과
- **누락 항목**: 승인 FAQ 원문, 실제 문서량, 검색 기준, 문의 채널·처리 상태와 책임자.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 답변을 찾지 못한 사용자가 막히지 않고 문의 조건과 처리 상태를 확인할 수 있어야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 승인되지 않은 보관·효능·품질 답변과 미확정 문의 기능은 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
