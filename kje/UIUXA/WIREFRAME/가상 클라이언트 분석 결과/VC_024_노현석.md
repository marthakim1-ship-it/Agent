- **이동 경로**: 메인페이지 → 카테고리 → 상품 후보 → 기관 도입 검토 → 도입 자료 확인 → 결과 확인·이전 단계 (VC024-REQ-001~005; SITE-001, SITE-012, SITE-017)
- **연결 페이지**: 브랜드 소개, 카테고리, 기관 도입 검토, 도입 자료 확인 (VC024-REQ-003~005; SITE-012, SITE-017)
- **검색 및 위치 안내**: 현재 위치와 상태를 텍스트로 표시하며 최종 GNB·URL은 확정하지 않음 (VC024-REQ-003~005; SITE-001, SITE-017)

## 5. 화면 구성

- **헤더**: 브랜드·제품 정보에서 기관 도입 안내로 진입하는 후보를 검토한다. (VC024-REQ-001~002; SITE-001, SITE-012)
- **내비게이션**: 도입 조건, 필요 문서, 검토 상태와 담당 연결의 관계를 단계별로 안내한다. (VC024-REQ-004~005; SITE-012, SITE-017)
- **핵심 콘텐츠**: YOVIA 정의, 기업·캠퍼스 복지 도입 핵심 조건, 근거·기준일·상태 (VC024-REQ-001~003; SITE-001, SITE-012, SITE-017)
- **보조 콘텐츠**: 기관 도입 자료, 책임 체크리스트, 담당 채널과 미확정 공급 조건. (VC024-REQ-003~005; SITE-012, SITE-017)
- **푸터**: 사업자·문의·개인정보 정책은 실제 운영 주체와 접수 방식이 확정된 경우에만 연결한다. (VC024-REQ-006; SITE-001)

## 6. 검토 결과

- **누락 항목**: 공급 범위, 최소 수량, 가격, 일정, 계약·정산·보관 조건과 실제 문의 절차가 필요하다.
- **중복 항목**: 제품 설명과 기관 도입 조건을 분리하고 여섯 Requirement를 검토 순서로 묶었다.
- **사용자 관점의 개선점**: 기관 담당자가 도입 가능 여부와 준비 문서를 문의 전에 판단할 수 있어야 한다.
- **수정 사항**: MENU는 기관 도입, CONTENT는 도입 조건·근거·상태, FUNCTION은 조건표·문서 체크리스트 후보로 정리했다. 유효 리서치 197개를 기준으로 failed/dead 자료를 정상 근거에서 제외했다.
- **보류·충돌·근거 부족**: 가격·수량·공급·계약·담당자 정보는 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 확정되지 않은 B2B 조건을 신청 가능 상태로 표현하지 않는다.
