# 가상클라이언트 기반 분석 결과 — VC-019 (권세아)

## 1. 가상 클라이언트
- **프로젝트 주제**: 최소 측정과 안전한 실험 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 제품 이해·사용법 확인·판매처 이동을 별도 목표로 측정하고 동의 상태와 품질 기준을 지키는 최소 실험 체계를 구성한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0032`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `제품`, `사용법`, `판매처`, `측정 안내`이다. CONTENT 후보는 사용자 목표, 측정 이벤트 목적, 동의 상태, 실험 범위와 오류 구분이다. FUNCTION 후보는 목표별 이벤트 구분, 비필수 측정 제한, 실험 변형 통제, 흐름 단절 원인 구분다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 제품 이해에 필요한 정보를 우선 제공하고 비필수 측정은 동의 상태에 따라 제한한다. (VC019-REQ-001~002; SITE-001, SITE-017)
- **이동 경로**: 제품 이해 → 사용법 확인 → 판매처 이동의 목표별 행동과 결과·오류를 구분한다. (VC019-REQ-001~005; SITE-001, SITE-017, SITE-032)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC019-REQ-003~005; SITE-017, SITE-032)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC019-REQ-003~005; SITE-001, SITE-032)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `제품`, `사용법`, `판매처`, `측정 안내` 접근 후보를 제공한다. (VC019-REQ-001~002; SITE-001, SITE-017)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC019-REQ-004~005; SITE-017, SITE-032)
- **핵심 콘텐츠**: 사용자 목표, 필요한 최소 이벤트, 동의 상태, 실험 기준과 결과 해석 범위. (VC019-REQ-001~003; SITE-001, SITE-017, SITE-032)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC019-REQ-003~005; SITE-017, SITE-032)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC019-REQ-006; SITE-001)

## 6. 검토 결과
- **누락 항목**: 실제 측정 계획, 이벤트 정의, 동의 체계, 기준선, 실험 표본·기간과 오류 분류.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 측정이나 실험이 제품 정보 접근을 방해하지 않고 각 행동의 목적과 실패 원인을 구분해야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 측정 설계 전 전환율·개선 효과와 실험 성과는 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
