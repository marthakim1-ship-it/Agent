# 가상클라이언트 기반 분석 결과 — VC-010 (임재희)

## 1. 가상 클라이언트
- **프로젝트 주제**: 다양한 입력·인지 조건에서도 YOVIA 핵심 정보와 다음 행동을 놓치지 않는 정보 접근성 후보를 분석한다.
- **제작 목적**: 색상·이미지 중심 브랜드를 유지하되 키보드·보조기술·확대·상태·오류 복구를 별도 품질 축으로 둔다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-PDF-001`, `SRC-PDF-002`, `SRC-PDF-003`; `EVD-0006`, `EVD-0007`, `EVD-0014`, `EVD-0023`; 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹과 키보드·보조기술 환경.

## 4. 내비게이션
- **시작 화면**: 건너뛰기·논리적 제목과 핵심 제품·CTA 순서를 유지하는 후보. (VC010-REQ-001~002; SITE-029, SITE-037)
- **이동 경로**: 제품 정의→핵심 정보→상태·주의→목적 CTA→결과·복구. (VC010-REQ-001~005; SITE-029, SITE-037, SITE-125)
- **연결 페이지**: 오류·빈 상태에서 이전 유효 화면과 홈으로 복구한다. (VC010-REQ-003~005; SITE-037, SITE-125)
- **검색 및 위치 안내**: 전체 검색은 근거 부족; 현재 위치는 텍스트로 인지 가능해야 한다. (VC010-REQ-003~005; SITE-029, SITE-125)

## 5. 화면 구성
- **헤더**: 키보드 접근 가능한 내비게이션과 명확한 레이블 후보. (VC010-REQ-001~002; SITE-029, SITE-037)
- **내비게이션**: 색상·호버만으로 상태나 하위 메뉴를 전달하지 않는다. (VC010-REQ-004~005; SITE-037, SITE-125)
- **핵심 콘텐츠**: 논리적 제목·대체 설명·정보 순서·명확한 CTA. (VC010-REQ-001~003; SITE-029, SITE-037, SITE-125)
- **보조 콘텐츠**: 로딩·빈·오류·완료 상태와 복구 행동. (VC010-REQ-003~005; SITE-037, SITE-125)
- **푸터**: 접근성 문의·정책은 운영 책임이 확정된 경우에만 검토. (VC010-REQ-006; SITE-029)

## 6. 검토 결과
- **누락 항목**: 접근성 감사, 키보드·스크린리더·확대·대비·터치 테스트.
- **중복 항목**: 키보드 탐색·비시각 정보·확대·상태·오류 복구를 정보 접근성이라는 공통 목적 아래 묶되 각각의 검증 항목은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 아름다운 컬러와 이미지가 없어도 정보와 행동 의미가 유지되어야 한다.
- **수정 사항**: 명시적 접근성 표현은 3/197로 제한적이며 상태 관련 직접 표현도 3/197이므로 낮은 근거를 숨기지 않았다.
- **보류·충돌·근거 부족**: 실제 준수·인증 주장은 `NOT_VERIFIED/HOLD`.
- **검증 결론**: 조건부 완료. MENU 6, CONTENT 8, FUNCTION 8 후보.
