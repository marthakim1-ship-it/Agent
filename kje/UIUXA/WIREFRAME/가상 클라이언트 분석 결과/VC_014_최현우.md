# 가상클라이언트 기반 분석 결과 — VC-014 (최현우)

## 1. 가상 클라이언트
- **프로젝트 주제**: 개인정보 동의와 데이터 최소화 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 개인정보 수집 목적과 필수 여부를 행동 전에 설명하고 비필수 동의를 거부해도 핵심 제품 정보 접근을 유지한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0027`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `개인정보 안내`, `동의 설정`, `지역 선택`이다. CONTENT 후보는 수집 항목·목적·필수 여부, 보관기간, 동의 상태, 변경·철회 방법이다. FUNCTION 후보는 동등한 수락·거부 선택, 위치 권한 대안, 동의 확인·변경·철회, 핵심 정보 접근 유지다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 개인정보가 필요한 행동 직전에 수집 목적·항목·필수 여부를 설명한다. (VC014-REQ-001~002; SITE-029, SITE-037)
- **이동 경로**: 기능 목적 확인 → 수집 항목 검토 → 수락 또는 거부 → 대안 이용 → 동의 설정 확인·변경. (VC014-REQ-001~005; SITE-029, SITE-037, SITE-125)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC014-REQ-003~005; SITE-037, SITE-125)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC014-REQ-003~005; SITE-029, SITE-125)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `개인정보 안내`, `동의 설정`, `지역 선택` 접근 후보를 제공한다. (VC014-REQ-001~002; SITE-029, SITE-037)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC014-REQ-004~005; SITE-037, SITE-125)
- **핵심 콘텐츠**: 수집 목적, 필수·선택 구분, 거부 영향, 보관기간과 동의 상태. (VC014-REQ-001~003; SITE-029, SITE-037, SITE-125)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC014-REQ-003~005; SITE-037, SITE-125)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC014-REQ-006; SITE-029)

## 6. 검토 결과
- **누락 항목**: 실제 수집 항목, 처리 목적, 보관기간, 동의 도구, 정책·책임자와 철회 경로.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 수락과 거부가 동등하게 이해되고 거부해도 제품 정보 열람이 막히지 않아야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 정책·보관기간·동의 도구 확정 전 준수 문구는 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
