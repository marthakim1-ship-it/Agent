# 가상클라이언트 기반 분석 결과 — VC-012 (강태윤)

## 1. 가상 클라이언트
- **프로젝트 주제**: 정확한 판매처·채널 전환 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 제품별 확정 판매 채널과 지역·재고 상태를 구분해 사용자가 과장된 약속 없이 다음 행동을 선택하도록 판매처 정보를 구성한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0025`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `제품`, `판매처`, `구매 안내`, `채널 상태`이다. CONTENT 후보는 제품별 판매 채널, 지역·재고 확인 범위, 기준일, 결과 없음·외부 이동·오류 안내이다. FUNCTION 후보는 판매처 연결, 지역 직접 선택, 채널·재고 상태 표시, 결과 없음·오류 복구다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 현재 제품과 확인 가능한 판매 채널 범위를 먼저 제시한다. (VC012-REQ-001~002; SITE-001, SITE-002)
- **이동 경로**: 제품 확인 → 지역 선택 → 판매 채널·상태 확인 → 외부 이동 또는 복귀. (VC012-REQ-001~005; SITE-001, SITE-002, SITE-017)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC012-REQ-003~005; SITE-002, SITE-017)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC012-REQ-003~005; SITE-001, SITE-017)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `제품`, `판매처`, `구매 안내`, `채널 상태` 접근 후보를 제공한다. (VC012-REQ-001~002; SITE-001, SITE-002)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC012-REQ-004~005; SITE-002, SITE-017)
- **핵심 콘텐츠**: 제품별 채널, 지역, 확인 기준일, 재고 상태의 적용 범위와 다음 행동. (VC012-REQ-001~003; SITE-001, SITE-002, SITE-017)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC012-REQ-003~005; SITE-002, SITE-017)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC012-REQ-006; SITE-001)

## 6. 검토 결과
- **누락 항목**: 실제 판매 채널, 지역 범위, 재고·배송 데이터, 기준일과 외부 이동 정책.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 위치 권한을 거부해도 지역을 직접 선택하고 결과가 없을 때 이유와 대안을 알 수 있어야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 판매 채널 확정 전 재고·배송 가능성과 구매 CTA는 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
