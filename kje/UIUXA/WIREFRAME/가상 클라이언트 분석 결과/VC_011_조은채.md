# 가상클라이언트 기반 분석 결과 — VC-011 (조은채)

## 1. 가상 클라이언트
- **프로젝트 주제**: 첫 방문 제품 이해와 교육 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 첫 방문자가 YOVIA의 정의·제품 구성·사용법을 단계적으로 이해하고 검증 정보와 다음 행동으로 이동하도록 입문 정보를 구성한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0024`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `제품 소개`, `제품 구성`, `사용법`, `검증 정보`이다. CONTENT 후보는 브랜드·제품 한 문장 정의, 파우치·빌트인 스푼·토핑 관계, 용어 도움말, 단계별 사용법, 검증 상태이다. FUNCTION 후보는 단계형 제품 설명, 용어 도움말, 상세 정보 연결, 모바일 순서 유지, 미확정 사양 공개 통제다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 브랜드 정의와 제품 편익을 한 문장으로 제시하고 제품 구성 설명으로 연결한다. (VC011-REQ-001~002; SITE-001, SITE-012)
- **이동 경로**: 브랜드 정의 → 제품 구성 → 사용법 → 검증 정보 → 확정된 다음 행동. (VC011-REQ-001~005; SITE-001, SITE-012, SITE-017)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC011-REQ-003~005; SITE-012, SITE-017)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC011-REQ-003~005; SITE-001, SITE-017)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `제품 소개`, `제품 구성`, `사용법`, `검증 정보` 접근 후보를 제공한다. (VC011-REQ-001~002; SITE-001, SITE-012)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC011-REQ-004~005; SITE-012, SITE-017)
- **핵심 콘텐츠**: 한 문장 제품 정의, 실제 구성 요소의 관계, 초심자용 단계 설명과 용어 도움말. (VC011-REQ-001~003; SITE-001, SITE-012, SITE-017)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC011-REQ-003~005; SITE-012, SITE-017)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC011-REQ-006; SITE-001)

## 6. 검토 결과
- **누락 항목**: 확정 제품 사양, 실제 제품 자산, 용어집, 사용 과정과 다음 행동 자료.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 첫 방문자가 낯선 제품 용어 때문에 이탈하지 않고 정의·구성·사용 순서를 따라 이해할 수 있어야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 미확정 제품 사양과 효능·가격·판매 정보는 `NOT_VERIFIED/HOLD`로 유지한다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
