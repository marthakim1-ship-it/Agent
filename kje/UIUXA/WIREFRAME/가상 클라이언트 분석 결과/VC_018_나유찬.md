# 가상클라이언트 기반 분석 결과 — VC-018 (나유찬)

## 1. 가상 클라이언트
- **프로젝트 주제**: 캠페인과 상시 제품 경험 연결 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: SNS·광고의 캠페인 약속을 검증된 제품 사실과 연결하고 종료·품절·오류 시 상시 정보로 안전하게 복귀시킨다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0031`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `캠페인`, `제품`, `이용 조건`, `캠페인 상태`이다. CONTENT 후보는 캠페인 메시지, 적용 제품, 기간·대상·조건·상태, 종료·품절 안내이다. FUNCTION 후보는 유입 메시지 일치, 딥링크 맥락 유지, 상태 표시, 종료·품절·오류 대체 경로다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 유입 메시지와 동일한 캠페인 약속, 적용 제품, 기간·대상·상태를 먼저 제시한다. (VC018-REQ-001~002; SITE-005, SITE-017)
- **이동 경로**: 유입 약속 확인 → 제품 근거 → 기간·대상·조건 → 다음 행동, 종료·오류 시 상시 제품 정보. (VC018-REQ-001~005; SITE-005, SITE-017, SITE-032)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC018-REQ-003~005; SITE-017, SITE-032)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC018-REQ-003~005; SITE-005, SITE-032)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `캠페인`, `제품`, `이용 조건`, `캠페인 상태` 접근 후보를 제공한다. (VC018-REQ-001~002; SITE-005, SITE-017)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC018-REQ-004~005; SITE-017, SITE-032)
- **핵심 콘텐츠**: 캠페인 약속, 검증 제품 사실, 기간·대상·상태·조건과 다음 행동. (VC018-REQ-001~003; SITE-005, SITE-017, SITE-032)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC018-REQ-003~005; SITE-017, SITE-032)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC018-REQ-006; SITE-005)

## 6. 검토 결과
- **누락 항목**: 실제 캠페인 메시지, 적용 제품, 기간·대상·혜택·재고와 종료 정책.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 광고에서 본 약속과 랜딩 첫 화면이 일치하고 종료된 캠페인에서도 길을 잃지 않아야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 확정되지 않은 할인·재고·효능 캠페인은 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
