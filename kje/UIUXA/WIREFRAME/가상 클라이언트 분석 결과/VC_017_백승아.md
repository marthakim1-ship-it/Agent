# 가상클라이언트 기반 분석 결과 — VC-017 (백승아)

## 1. 가상 클라이언트
- **프로젝트 주제**: 콘텐츠와 자산 수명주기 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 제품 사실과 이미지 자산을 승인 출처에서 관리하고 변경·만료 시 관련 사용법·영양·CTA까지 일관되게 갱신한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0030`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

## 4. 내비게이션
- **시작 화면**: 승인된 제품 사실과 현재 자산 상태를 함께 식별하도록 한다. (VC017-REQ-001~002; SITE-001, SITE-005)
- **이동 경로**: 제품 사실 확인 → 자산 상태 확인 → 사용법·영양 → 관련 CTA → 갱신 정보. (VC017-REQ-001~005; SITE-001, SITE-005, SITE-017)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC017-REQ-003~005; SITE-005, SITE-017)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC017-REQ-003~005; SITE-001, SITE-017)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `제품`, `사용법`, `검증 정보`, `자산 상태` 접근 후보를 제공한다. (VC017-REQ-001~002; SITE-001, SITE-005)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC017-REQ-004~005; SITE-005, SITE-017)
- **핵심 콘텐츠**: 승인 제품 사실, 자산 유형, 소유자·기준일·갱신 조건과 관련 콘텐츠 상태. (VC017-REQ-001~003; SITE-001, SITE-005, SITE-017)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC017-REQ-003~005; SITE-005, SITE-017)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC017-REQ-006; SITE-001)

## 6. 검토 결과
- **누락 항목**: 단일 승인 출처, 콘텐츠 소유자, 자산 권리·만료일, 제품 변경 및 배포 절차.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 사용자가 오래되거나 콘셉트인 자산을 실제 최신 제품으로 오해하지 않아야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 승인되지 않았거나 만료된 제품 사실·이미지·CTA는 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
