## 4. 내비게이션

- **시작 화면**: 메인페이지 또는 품질 검증 관련 직접 진입 후보 (VC030-REQ-001~002; SITE-001, SITE-006)
- **이동 경로**: 메인페이지 → 카테고리 → 상품 후보 → 출시 검증 → 결함·재검증 상태 → 결과 확인·이전 단계 (VC030-REQ-001~005; SITE-001, SITE-006, SITE-010)
- **연결 페이지**: 브랜드 소개, 카테고리, 출시 검증, 결함·재검증 상태 (VC030-REQ-003~005; SITE-006, SITE-010)
- **검색 및 위치 안내**: 현재 위치와 상태를 텍스트로 표시하며 최종 GNB·URL은 확정하지 않음 (VC030-REQ-003~005; SITE-001, SITE-010)

## 5. 화면 구성

- **헤더**: 품질 검증 상태와 대상 버전을 식별하는 후보를 두되 일반 사용자용 내비게이션과 혼합하지 않는다. (VC030-REQ-001~002; SITE-001, SITE-006)
- **내비게이션**: 검증 대상, 체크 항목, 결함·재검증 상태와 이전 단계 복귀를 일관되게 안내한다. (VC030-REQ-004~005; SITE-006, SITE-010)
- **핵심 콘텐츠**: YOVIA 정의, 출시 전 경험 QA·릴리스 핵심 조건, 근거·기준일·상태 (VC030-REQ-001~003; SITE-001, SITE-006, SITE-010)
- **보조 콘텐츠**: 테스트 환경, 승인 버전, 결함 심각도·소유자와 재검증 이력. (VC030-REQ-003~005; SITE-006, SITE-010)
- **푸터**: 릴리스 승인·결함 이력·책임자 자료는 실제 QA 운영 권한과 저장 정책이 확정된 경우에만 연결한다. (VC030-REQ-006; SITE-001)

## 6. 검토 결과

- **누락 항목**: 실제 출시 범위, 테스트 환경·기기·담당자·심각도 기준·승인 버전과 릴리스 권한이 필요하다.
- **중복 항목**: 여정 검증, 상태 검증, 콘텐츠 승인과 결함 재검증을 각각 독립 체크 항목으로 유지했다.
- **사용자 관점의 개선점**: 출시 전 직접 진입·로딩·빈 상태·오류·완료·복귀까지 끊김 없이 검증되어야 한다.
- **수정 사항**: MENU는 품질 검증, CONTENT는 대상·조건·버전·상태, FUNCTION은 여정 체크리스트·결함 상태표 후보로 정리했다. 유효 리서치 197개를 기준으로 failed/dead 자료를 정상 근거에서 제외했다.
- **보류·충돌·근거 부족**: 테스트 미실행, 중대 결함, 미확정 정책과 승인 버전 불일치는 `HOLD`다.
- **검증 결론**: 조건부 완료. QA 운영 기준과 실제 검증 결과 없이 출시 승인 상태를 생성하지 않는다.
