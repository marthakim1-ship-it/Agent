# 가상클라이언트 기반 분석 결과 — VC-016 (송예진)

## 1. 가상 클라이언트
- **프로젝트 주제**: 언어·지역별 정보 일관성 관점에서 YOVIA 리서치 사이트를 분석한다.
- **제작 목적**: 공통 브랜드 정보와 지역별 제품·판매·정책 정보를 구분하고 언어·지역 변경 후에도 현재 제품 맥락을 유지한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-REF-001~003`, `EVD-0029`; dead 3개를 제외한 유효 리서치 197개.
- **적용 매체**: 모바일 우선 반응형 웹.

MENU 후보는 `언어·지역`, `제품`, `판매 정보`, `지역별 정책`이다. CONTENT 후보는 공통 브랜드 정의, 지역별 제품·영양·판매·법정 정보, 출처·기준일·적용 범위이다. FUNCTION 후보는 언어·지역 전환, 현재 제품 맥락 유지, 텍스트 언어 선택, 번역 확장 대응, 지역 상태 표시다. 이는 최종 사이트맵·화면 배치·구현 사양이 아니라 가상 클라이언트 요구에서 도출한 후보다.

## 4. 내비게이션
- **시작 화면**: 현재 언어·지역과 적용 가능한 제품 정보 범위를 명확히 표시한다. (VC016-REQ-001~002; SITE-002, SITE-010)
- **이동 경로**: 언어·지역 확인 → 제품 선택 → 지역별 정보 검토 → 판매 정보 또는 정책 확인. (VC016-REQ-001~005; SITE-002, SITE-010, SITE-025)
- **연결 페이지**: 각 상태와 행동을 해당 제품·검증 정보에 연결하며 종료·오류 시 이전 유효 화면 또는 상시 정보로 복귀한다. (VC016-REQ-003~005; SITE-010, SITE-025)
- **검색 및 위치 안내**: 현재 위치와 상태는 텍스트로 병기한다. 전체 검색은 실제 문서량과 운영 체계가 확정된 뒤 검토한다. (VC016-REQ-003~005; SITE-002, SITE-025)

## 5. 화면 구성
- **헤더**: 현재 제품과 주요 탐색 맥락을 유지하면서 `언어·지역`, `제품`, `판매 정보`, `지역별 정책` 접근 후보를 제공한다. (VC016-REQ-001~002; SITE-002, SITE-010)
- **내비게이션**: 현재 제품·조건·상태를 잃지 않고 이전 단계와 관련 정보로 이동하도록 한다. (VC016-REQ-004~005; SITE-010, SITE-025)
- **핵심 콘텐츠**: 공통 브랜드 정의와 지역별 제품·영양·판매·법정 정보의 차이. (VC016-REQ-001~003; SITE-002, SITE-010, SITE-025)
- **보조 콘텐츠**: 출처·기준일·적용 범위·미확정 상태와 오류·복귀 안내. (VC016-REQ-003~005; SITE-010, SITE-025)
- **푸터**: 정책·문의·운영 책임이 실제로 확정된 항목만 연결한다. (VC016-REQ-006; SITE-002)

## 6. 검토 결과
- **누락 항목**: 지원 언어·지역, 번역 원문, 지역별 제품·판매·영양·법정 표시와 기준일.
- **중복 항목**: 목적이 같은 정보는 묶되 여섯 Requirement의 조건·상태·행동은 독립적으로 유지했다. 다른 Client 결과를 근거로 사용하지 않았다.
- **사용자 관점의 개선점**: 언어·지역을 바꿔도 보고 있던 제품과 탐색 목적을 잃지 않아야 한다.
- **수정 사항**: 지정 양식에 따라 일반화된 분류명과 반복 문장을 클라이언트별 MENU·CONTENT·FUNCTION, 내비게이션, 화면 구성, 검토 항목으로 다시 작성했다.
- **보류·충돌·근거 부족**: 판매·영양·법정 표시가 확정되지 않은 지역은 `NOT_VERIFIED/HOLD`다.
- **검증 결론**: 조건부 완료. 모든 Requirement를 정보 구조와 화면 후보에 연결했으며 미확정 운영 정보는 확정하지 않았다.
