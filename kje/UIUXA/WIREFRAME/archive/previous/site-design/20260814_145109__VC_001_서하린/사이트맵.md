# VC-001 서하린 — 사이트맵 초안

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 설계 대상 | YOVIA 반응형 웹 |
| 분석 기준 | VC-001 서하린 |
| 핵심 목표 | 바쁜 사용자가 제품을 빠르게 이해하고, 사용법과 신뢰 정보를 확인한 뒤 확정된 행동으로 이동 |
| 입력 | `가상 클라이언트 분석 결과/VC_001_서하린.md`, `Md_Skill/output/04_virtual_clients/clients/VC_001.md` |
| 상태 | VC-001 단독 정보구조 초안 |

이 문서는 VC-001의 요구를 독립적으로 구조화한 결과다. 다른 Client의 사이트맵이나 기존의 `MAIN/CATEGORY/BRAND/TASK` 고정 구조를 사용하지 않았다.

## 2. 구조화 원칙

1. 첫 진입에서 브랜드 정의, 실제 제품 형태, 사용 이유를 함께 이해시킨다.
2. `제품 구조`, `사용 방법`, `사용 상황`은 서로 다른 질문에 답하므로 올인원 경험 아래에서 구분한다.
3. `원료·성분`, `영양`, `알레르기`, `근거 상태`는 빠르게 찾을 수 있는 독립 정보 목적지로 둔다.
4. 실제 제품 선택지·판매 채널·시험 자료가 필요한 항목은 조건부 또는 `HOLD`로 분리한다.
5. 미확정 가격·효능·인증·구독·제품 사양은 페이지나 CTA의 확정 근거로 사용하지 않는다.

## 6. 핵심 이동 경로

### 빠른 제품 이해

`홈 → 제품 개요 → 제품 구조 → 사용 방법 → 제품 정보`

### 사용 상황 중심 탐색

`홈 → 올인원 경험 → 사용 상황 → 제품 개요`

### 신뢰 정보 확인

`홈 또는 제품 상세 → 제품 정보 → 원료·성분 / 영양 / 알레르기 → 근거·검증 상태`

### 전환 경로

`제품 상세 → 판매처 확인`은 판매 채널·CTA·정책이 확정된 뒤에만 활성화한다.

## 8. 추적성 검토

- VC-001의 Requirement 13개를 필수·조건부·HOLD·제외 항목에 모두 연결했다.
- 기존 공통 3화면과 `TASK-001/002` 구조를 재사용하지 않았다.
- `제품 구조`, `사용 방법`, `사용 상황`, `제품 정보`는 사용자 질문과 콘텐츠 책임이 달라 독립 목적지로 구분했다.
- 조건부 페이지를 확정 페이지처럼 표시하지 않았다.
- 최종 GNB, URL, 화면 수와 레이아웃은 아직 확정하지 않았다.
