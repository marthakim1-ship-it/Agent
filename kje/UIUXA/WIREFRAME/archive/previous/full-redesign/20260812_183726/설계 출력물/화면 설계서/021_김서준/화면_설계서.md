# VC-021 김서준 화면 설계서

## 1. 프로젝트 및 설계 범위

검색·공유 링크로 개별 페이지에 진입한 사용자가 YOVIA의 맥락, 현재 질문의 답, 검증 상태와 관련 정보를 확인하는 반응형 웹 16개 화면을 설계한다. 판매·가격·재고·리뷰·효능은 범위에서 제외한다.

## 3. 공통 구성과 UI 요소

- 헤더: YOVIA 워드마크, 전역 메뉴, 현재 화면 표시. 모바일에서는 가로 스크롤 가능한 메뉴로 유지한다.
- 현재 위치: `홈 / 정보 영역 / 현재 페이지` 텍스트 경로.
- 질문·답 블록: H1 질문과 바로 이어지는 한 문장 답.
- 상태 라벨: `확인됨`, `자료 준비 중`, `가정`을 색상과 텍스트로 함께 표현.
- 근거 카드: 정보 범위, 기준일, 다음 관련 링크.
- 푸터: 브랜드 정의, 정보 정책, 홈 복귀.
- 이미지 플레이스홀더: 역할을 설명하는 대체 텍스트를 포함한다.

## 4. 화면별 상세 규칙

### 정보 화면 SCR-001~009

- 기본: 질문, 한 문장 답, 근거·상태, 다음 링크 순서로 표시한다.
- 로딩: 제목과 상태 영역 크기를 유지한 스켈레톤 및 `정보를 확인 중입니다` 문구.
- 빈 상태: SCR-014로 연결하고 제품 정보 및 이전 단계 링크 제공.
- 오류: SCR-016으로 연결하며 입력 내용이나 탐색 경로를 잃지 않게 한다.
- 자료 미확정: 내용을 추정하지 않고 SCR-015의 준비 중 상태로 연결한다.

### 행동 화면 SCR-010~013 (`가정`)

- 다음 행동은 계속 탐색을 기본 동작으로, 알림 신청을 보조 동작으로 둔다.
- 로그인 화면에는 이메일과 비밀번호 필드, 비회원 계속 탐색 링크를 둔다.
- 빈 이메일: `이메일을 입력해 주세요.`
- 잘못된 이메일: `이메일 형식을 확인해 주세요.`
- 인증 실패: `입력 정보를 확인하고 다시 시도해 주세요.`
- 완료 후 SCR-013에서 신청 범위와 취소 가능성을 안내하되 실제 정책은 확정하지 않는다.

### 예외 화면 SCR-014~016

- 콘텐츠 없음: 검색어나 필터를 탓하지 않고 가능한 상위 정보로 복귀한다.
- 자료 준비 중: 가격·재고·리뷰·효능을 임의 표시하지 않는다.
- 오류 안내: 재시도, 검색 유입 랜딩, 홈 중 최소 두 경로를 제공한다.

## 5. 표시 데이터·행동·인터랙션

| 데이터 | 상태 | 사용자 행동 | 처리 |
|---|---|---|---|
| 페이지 질문·답 | 필수 | 상세 읽기 | 고유 페이지 내용 유지 |
| 제품·사용법·원료 | 확인된 범위 | 관련 링크 선택 | 해당 정보 화면 이동 |
| 검증 문서 | 확인됨/준비 중 | 상태 확인 | 008 또는 015 분기 |
| 가격·재고·리뷰·효능 | Hold | 없음 | UI·노출 데이터 생성 금지 |
| 알림 입력 | 가정 | 제출/수정 | 012 또는 013 분기 |

## 6. 반응형 기준

- 모바일 0~767px: 단일 열, 질문·답·현재 위치를 첫 화면에 우선 배치, 버튼 최소 높이 44px.
- 태블릿 768~1199px: 본문 8열, 카드 2열, 목차 가로 배치.
- 데스크톱 1200px 이상: 고정 사이드 목차와 본문 최대폭 1180px, 카드 3열.
- 직접 진입 시 화면 폭과 무관하게 YOVIA 정의와 현재 위치를 숨기지 않는다.

## 7. 접근성 요구사항

- 문서 언어와 고유한 페이지 제목, 논리적 H1~H3 계층을 사용한다.
- 모든 링크는 목적을 단독으로 이해할 수 있는 이름을 갖는다.
- 키보드 포커스를 명확히 표시하고 건너뛰기 링크를 제공한다.
- 상태·오류는 색상만으로 구분하지 않고 텍스트와 아이콘 의미를 병기한다.
- 이미지 플레이스홀더에도 설명 가능한 대체 텍스트를 제공한다.
- 동적 오류는 `aria-live`로 알리고 오류 필드와 메시지를 연결한다.

## 8. 가정 및 추가 검증

- 로그인·알림 신청·입력 검사는 프롬프트의 분기 요건을 충족하기 위한 가정이며 실제 서비스 범위가 아니다.
- 실제 검색어, URL·메타 정책, 구조화 데이터 유형, 제품 문서, 기준일은 운영 확인이 필요하다.
- 구조화 정보 후보는 확정된 제품·문서만 대상으로 하며 구현 전에 별도 승인한다.
