# YOVIA VC-010 임재희 사이트맵

## 프로젝트 개요
키보드·보조기술·확대 환경에서도 핵심 정보와 행동을 유지하는 접근성을 모바일 우선으로 제공하는 사이트 구조다. 설계 근거는 VC010-REQ-001~006이며 입력에 없는 정책과 수치는 확정하지 않는다.

## 설계 근거와 핵심 사용자 목표
- MENU: 접근 안내, 상태 안내, 이미지 안내, 모바일 이용, 오류·복구, 검증 정보
- CONTENT: 탐색 순서, 상태 이름, 대체 설명, 컨트롤 이름, 정보 순서, 오류 메시지, 복구 행동, 검증 범위
- FUNCTION: 랜드마크, 포커스, 상태 라벨, 대체 텍스트, 접근 이름, 리플로우, 재시도·초기화, 공개 통제
- 핵심 목표: 탐색 기준을 이해하고, 근거와 적용 범위를 확인한 뒤 확정 가능한 행동으로 이동한다.
- 공개 통제: 접근성 준수·인증 주장은 NOT_VERIFIED/HOLD로 표시하고 CTA에서 제외한다.

## 전역 내비게이션 구조
- 공통: 홈, 접근 안내, 상태 안내, 제품 상세
- 상태·근거: 검증 정보
- 회원 상태별: 로그인은 **가정: 핵심 행동에 인증이 필요한 경우**만 노출한다.
- 예외: 결과 없음, 입력 오류 안내, 오류 안내에서 이전 유효 화면 또는 홈으로 복구한다.

## 계층형 사이트맵
- 1차 — 홈
  - 2차 — 제품 정보
  - 2차 — 접근 안내
  - 2차 — 상태 안내
  - 2차 — 이미지 안내
  - 2차 — 모바일 이용
  - 2차 — 검증 정보
    - 3차 — 다음 행동
    - 3차 — 로그인
    - 3차 — 결과 없음
    - 3차 — 입력 오류 안내
    - 3차 — 오류 안내
    - 3차 — 완료 안내

## 주요 사용자 여정과 검토
홈 → 탐색 → 선택 → 상세 확인 → 핵심 행동 → 결과 확인 순서를 유지한다. 로그인 여부, 입력 오류, 결과 없음, 이전 단계 이동을 조건부로 포함했다. 공유 화면은 단일 노드로 유지했고 모든 예외 화면은 복구 경로가 있다.

## 가정
- 실제 제품 데이터, 기준일, CTA와 인증 정책은 미확정이다.
- 검색·필터·계산은 입력 데이터가 확정된 뒤 활성화한다.
- 접근성 준수·인증 주장은 근거가 확보될 때까지 공개하지 않는다.
