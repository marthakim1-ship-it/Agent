# 가상클라이언트 기반 분석 결과 — VC-003 (이수민)

## 1. 가상 클라이언트

- **프로젝트 주제**: YOVIA의 확정 제품 정의와 원료·영양·알레르기·인증 정보를 근거 수준에 맞게 구분하고, 검증 전 건강·의료 효능이나 수치를 구매 유도에 사용하지 않는 신뢰 정보 체계를 분석한다.
- **제작 목적**: 구매 전 비교 사용자가 핵심 성분과 적합성을 빠르게 판단하고 상세 근거까지 단계적으로 확인하게 하되, 정보량이 구매 흐름을 가리거나 병원처럼 위협적인 인상을 만들지 않게 한다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-PER-001`, `SRC-PER-002`, `SRC-PDF-003`; `EVD-0005`, `EVD-0010`, `EVD-0013`, `EVD-0014`; 리서치 `SITE-001~SITE-200` 중 유효 197개.
- **적용 매체**: 구매 전 모바일 비교와 제품 상세 확인을 우선하는 웹. 표와 주석은 작은 화면에서 읽기 쉬운 계층으로 변환되어야 한다.

### 3.1 유사 항목 분류

- **같은 목적의 통합**: 동일한 메뉴에 연결된 Requirement는 하나의 정보 그룹으로 묶고, 각 Requirement ID와 근거는 유지했다.
- **중복 처리**: 같은 의미의 메뉴·콘텐츠·기능은 대표 레이블 아래 통합했다. 서로 다른 검증 상태나 적용 범위는 합치지 않았다.
- **제외·보류**: 보류, HOLD, NOT_VERIFIED 항목은 확정 메뉴·CTA·카피에서 제외하고 검토 상태로 남겼다.
- **노출 우선순위**: 높음 요구를 핵심 정보, 보통 이상을 보조 정보, 보류를 비공개 검증 항목으로 배치한다.
- **자료 유형**: 제품 형태·구조는 이미지, 사용 순서는 이미지·영상, 사실·주의·정책은 텍스트, 수치·상태·비교는 검증된 데이터셋으로 분류한다. 실제 자료가 없으면 대체 자산을 생성하지 않는다.

│  ├─ 원료·성분
│  │  └─ 실제 원료 목록과 역할 · 핵심 원료 요약, 상세 펼치기

│  ├─ 인증·근거
│  │  └─ 인증명, 적용 제품·범위, 발급·시험 주체, 기준일 · 근거 문서 연결과 상태 표시

- **메뉴 후보 원본 수**: 6개
- **통합 상위 그룹 수**: 3개
- **메뉴 폭 검토**: 조건부 적합 — 상위 그룹 3개로 권장 폭 5~9개보다 작지만 현재 Client의 제한된 과업 범위에 불필요한 메뉴를 추가하지 않는다.
- **메뉴 깊이 검토**: 프로젝트 → 상위 그룹 → 메뉴 → 콘텐츠·기능의 3단계로, 최대 5단계 이내다.
- **레이블 검토**: 상위 그룹과 메뉴는 명사형으로 통일하고, 같은 의미의 레이블은 하나로 합쳤다. 이름만 보고 목적을 알 수 없는 상태·기술 분류명은 사용자용 메뉴로 사용하지 않는다.
## 4. 내비게이션

- **시작 화면**: 제품 가치 문구보다 확정 제품 속성과 핵심 원료·영양·알레르기 요약으로 진입하는 후보가 필요하다 (`VC003-REQ-001`, `VC003-REQ-003`; `SITE-002`, `SITE-010`, `SITE-192`).
- **이동 경로**: 핵심 속성 요약 → 원료·영양·알레르기 상세 → 인증·시험·출처 → 제품 상세 또는 확정된 구매 행동의 흐름 후보를 둔다. 근거가 없으면 `NOT_VERIFIED` 상태에서 멈추고 구매 문구로 연결하지 않는다 (`VC003-REQ-001~004`).
- **연결 페이지**: 제품별 원료·영양 정보와 적용 인증 범위를 해당 제품 상세에 연결하는 후보가 유효하다. 리서치에서는 영양 정보 탭과 옵션 전환이 관찰됐지만 YOVIA의 제품별 데이터 구조는 추가 검증이 필요하다 (`SITE-002`, `SITE-010`, `SITE-011`).
- **검색 및 위치 안내**: 알레르기·식단 조건에 따른 제품 필터 후보는 `SITE-077`에서 관찰됐고 VC-003의 비교 문제와 연결된다. 전체 검색·브레드크럼은 직접 요구 및 충분한 근거가 없어 `not_verified`다.

### 4.1 내비게이션 유형 검토

- **글로벌 내비게이션 후보**: 제품 이해, 신뢰·안전 정보, 운영·설정. 이는 Client별 상위 탐색 그룹이며 최종 GNB 확정안이 아니다.
- **로컬 내비게이션 후보**: 각 상위 그룹 아래에 위 계층 구조의 메뉴 후보를 배치한다.
- **브레드크럼**: 직접 진입과 현재 위치 이해가 필요한 화면에서 상위 그룹 → 메뉴 → 현재 콘텐츠 경로 후보를 제공한다.
- **검색창**: 실제 문서량·검색어·색인 정책이 확인된 경우에만 적용하며, 미확정이면 `not_verified`로 유지한다.
- **풀다운 메뉴**: 하위 메뉴가 복수이고 모바일 접근성·키보드 동작이 검증된 경우에만 사용한다.
- **사이트맵**: 위 계층 구조를 후보로 사용하되 다른 Client 결과와 통합하기 전에는 최종 사이트맵으로 확정하지 않는다.
- **레이블 일관성**: 글로벌·로컬·브레드크럼·링크에서 동일한 메뉴명을 유지한다.
## 5. 화면 구성

- **헤더**: 제품, 원료·성분, 영양·알레르기, 인증·근거로 이동할 진입 후보를 검토한다. 메뉴 개수와 배치는 확정하지 않는다 (`VC003-REQ-001`, `VC003-REQ-002`).
- **내비게이션**: 모바일에서는 핵심 정보와 상세 근거를 1열 계층으로 제공하고, 탭·아코디언을 사용하더라도 중요한 알레르기·주의 정보를 숨기지 않는 후보가 필요하다. 탭·아코디언 관련 표현은 107/197, 명시적 모바일 1열·세로 흐름은 44/197에서 확인됐다 (`VC003-REQ-004`; `SITE-002`, `SITE-010`, `SITE-011`, `SITE-137`).
- **핵심 콘텐츠**: 확정 제품 속성, 실제 원료, 영양성분과 기준량, 알레르기 정보를 먼저 제시한다. 수치·배지는 실제 YOVIA 문서와 연결된 경우에만 `CONFIRMED`로 표시한다 (`VC003-REQ-001`, `VC003-REQ-002`).
- **보조 콘텐츠**: 인증 범위, 시험 조건·출처, 상세 주석과 검증 상태를 단계적으로 제공한다. 건강·의료 효능은 검증 전 제품 가치나 CTA 근처에 노출하지 않는다 (`VC003-REQ-002`, `VC003-REQ-003`).
- **푸터**: 법적 표시·인증서·시험 문서·정책 연결 후보는 실제 문서와 책임 주체가 확정된 경우에만 검토한다. 현재 YOVIA 자료는 `not_verified`이며 푸터 구조를 확정하지 않는다.

### 5.1 화면 배치 우선순위

| 화면 영역 | 배치 원칙 | 자료 유형 |
|---|---|---|
| 헤더 | 브랜드 식별과 현재 Client의 핵심 상위 탐색을 우선하고 미확정 CTA는 제외 | 텍스트·로고 |
| 내비게이션 | 현재 위치, 상위·하위 메뉴, 이전 단계와 관련 정보 연결 | 텍스트·링크 |
| 바디 | 높음 Requirement의 핵심 사실·과정·이미지를 먼저 배치 | 텍스트·이미지·영상·검증 데이터 |
| 어사이드 | 관련 자료, 기준일, 상태, 보조 행동만 배치하며 모바일에서는 본문 뒤로 이동 | 텍스트·상태 데이터 |
| 푸터 | 확정된 기업·정책·문의·저작권 정보만 연결 | 텍스트·링크 |

- **사용자 행동 경로**: 핵심 정보 이해 → 조건·근거 확인 → 관련 정보 비교 → 확정된 다음 행동 순서를 유지한다.
- **반응형 원칙**: 웹과 모바일에서 정보 의미와 이동 순서는 동일하게 유지한다. 모바일에서는 1열로 재배치하되 핵심 정보·주의·CTA의 상대적 우선순위를 바꾸지 않는다.
- **화면 전환 원칙**: 링크명과 도착 화면의 제목을 일치시키고 오류·빈 상태·보류 상태에서는 이전 유효 화면과 상시 정보로 복귀할 수 있게 한다.
## 6. 검토 결과

- **누락 항목**: 원본 6개 Requirement를 모두 2~5번의 후보 또는 보류 판단에 연결했다. 실제 영양성분표, 전성분, 알레르기·교차접촉 정보, 인증서, 시험성적서, 법적 표시 검토, 제품별 적용 범위와 기준일은 추가 입력이 필요하다.
- **중복 항목**: `VC003-REQ-001`의 정보 구분과 `VC003-REQ-004`의 단계적 확인은 하나의 정보 계층으로 연결하되, 전자는 사실 정확성, 후자는 모바일 접근성으로 별도 유지했다. `VC003-REQ-002`와 `VC003-REQ-003`은 근거 통제 원칙으로 묶되 수치·인증과 효능 주장을 구분했다.
- **사용자 관점의 개선점**: 핵심 성분·영양·알레르기는 빠르게 비교할 수 있어야 하고, 상세 근거는 필요할 때 열 수 있어야 한다. 알레르기·주의 정보는 접힌 영역에만 의존하지 않으며, 상태 라벨은 색상뿐 아니라 명시적 텍스트로 구분할 필요가 있다.
- **수정 사항**: 전체 200개 기록을 다시 분리해 `completed` 101개와 `partial` 96개, 총 유효 197개를 확인했다. `SITE-036`, `SITE-113`, `SITE-152`는 `dead/failed`로 제외했다. `partial`은 확인된 필드만 사용했고 `not_verified`는 관찰 수에서 제외했다. 타사 영양 수치·인증·건강 표현은 YOVIA의 확정 사실로 전용하지 않았다.
- **보류·충돌·근거 부족**: 실제 YOVIA 원료·영양·알레르기 자료와 인증·시험 문서가 없어 제품 수치·배지·효능은 확정할 수 없다. 장 건강 개선, 붓기 완화, 목 보호, 피부 개선 등의 효능은 검증 전 제외한다. QR 배치 추적·미생물 데이터 기능은 데이터 체계와 운영 책임이 검증될 때까지 `HOLD`다. 의료기관을 연상시키는 공포·질환 이미지는 제외한다.
- **검증 결론**: 조건부 완료. 유효 사이트 197개를 기준으로 MENU 8개, CONTENT 10개, FUNCTION 8개 후보를 도출했으며, 근거가 없는 YOVIA 수치·인증·효능·고도화 기능은 `not_verified` 또는 `HOLD`로 유지했다.
### 6.1 반복 검토 체크리스트

- **요청 반영**: 원본 Requirement ID가 요구사항 표와 정보 구조에 모두 연결되어 있다.
- **누락·중복**: 누락 입력은 별도로 기록하고 중복 후보는 대표 레이블로 통합했다.
- **탐색 가능성**: 시작 화면, 이동 경로, 연결 페이지와 현재 위치 안내를 명시했다.
- **메뉴 깊이**: 3단계로 최대 5단계 이내다.
- **항목명 일관성**: 계층 구조·내비게이션·화면 구성에서 같은 명칭을 사용한다.
- **구조 변경 영향**: 상위 그룹 변경 시 로컬 메뉴·브레드크럼·관련 링크·화면 제목을 함께 점검한다.
- **웹·모바일 일관성**: 의미·우선순위·행동 순서를 유지하고 배치만 반응형으로 조정한다.
