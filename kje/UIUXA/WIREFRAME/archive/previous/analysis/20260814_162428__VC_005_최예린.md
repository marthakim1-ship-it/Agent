# 가상클라이언트 기반 분석 결과 — VC-005 (최예린)

## 1. 가상 클라이언트

- **프로젝트 주제**: 밝고 현대적인 YOVIA의 기억 가능성을 높이면서도 패키지·요거트 질감·토핑·개봉·섭취 과정과 신뢰 정보가 장식에 가려지지 않는 제품 중심 크리에이티브 후보를 분석한다.
- **제작 목적**: 모바일·SNS에서 형성된 시각적 관심을 실제 제품 이해와 확정 행동으로 연결하고, 확정 컬러를 정보 위계와 제품군 탐색 단서로 사용한다. 합성 이미지나 미확정 맛·기능·효능은 실제 사양처럼 표현하지 않는다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-PER-001`, `SRC-PER-002`, `SRC-PDF-001`; `EVD-0001`, `EVD-0008`, `EVD-0017`, `EVD-0018`; 리서치 `SITE-001~SITE-200` 중 유효 197개.
- **적용 매체**: 모바일 웹과 SNS 발견 맥락 우선, 데스크톱 확장. 이미지가 핵심 설명과 CTA를 과도하게 밀어내지 않도록 정보 순서를 유지한다.

### 3.1 유사 항목 분류

- **같은 목적의 통합**: 동일한 메뉴에 연결된 Requirement는 하나의 정보 그룹으로 묶고, 각 Requirement ID와 근거는 유지했다.
- **중복 처리**: 같은 의미의 메뉴·콘텐츠·기능은 대표 레이블 아래 통합했다. 서로 다른 검증 상태나 적용 범위는 합치지 않았다.
- **제외·보류**: 보류, HOLD, NOT_VERIFIED 항목은 확정 메뉴·CTA·카피에서 제외하고 검토 상태로 남겼다.
- **노출 우선순위**: 높음 요구를 핵심 정보, 보통 이상을 보조 정보, 보류를 비공개 검증 항목으로 배치한다.
- **자료 유형**: 제품 형태·구조는 이미지, 사용 순서는 이미지·영상, 사실·주의·정책은 텍스트, 수치·상태·비교는 검증된 데이터셋으로 분류한다. 실제 자료가 없으면 대체 자산을 생성하지 않는다.

## 4. 내비게이션

- **시작 화면**: 실제 제품 패키지와 핵심 질감·토핑을 먼저 보여주고, 짧은 브랜드 정의와 제품 탐색 후보를 연결한다. 장식이 제품보다 먼저 인지되지 않게 한다 (`VC005-REQ-001`, `VC005-REQ-002`; `SITE-001`, `SITE-004`, `SITE-015`, `SITE-016`).
- **이동 경로**: 제품 인상 → 패키지·질감·토핑 이해 → 개봉·섭취 또는 실제 사용 장면 → 제품 정보·신뢰 근거 → 확정 행동의 후보 흐름을 둔다 (`VC005-REQ-001`, `VC005-REQ-004`, `VC005-REQ-005`; `SITE-015`, `SITE-016`, `SITE-176`).
- **연결 페이지**: 제품군 컬러와 라벨은 탐색 단서로 사용하되 컬러만으로 구분하지 않는다. 감성 콘텐츠는 관련 제품·사용 방법·제품 정보로 연결해야 한다 (`VC005-REQ-003`, `VC005-REQ-004`; `SITE-001`, `SITE-015`, `SITE-016`, `SITE-020`).
- **검색 및 위치 안내**: 제품군·맛 필터는 리서치에서 관찰됐지만 YOVIA의 확정 라인업이 없어 `not_verified`다. 전체 검색·브레드크럼은 VC-005의 직접 요구와 충분한 근거가 없어 확정하지 않는다.

### 4.1 내비게이션 유형 검토

- **글로벌 내비게이션 후보**: 제품 이해, 이용 안내, 브랜드·캠페인, 신뢰·안전 정보, 행동·지원. 이는 Client별 상위 탐색 그룹이며 최종 GNB 확정안이 아니다.
- **로컬 내비게이션 후보**: 각 상위 그룹 아래에 위 계층 구조의 메뉴 후보를 배치한다.
- **브레드크럼**: 직접 진입과 현재 위치 이해가 필요한 화면에서 상위 그룹 → 메뉴 → 현재 콘텐츠 경로 후보를 제공한다.
- **검색창**: 실제 문서량·검색어·색인 정책이 확인된 경우에만 적용하며, 미확정이면 `not_verified`로 유지한다.
- **풀다운 메뉴**: 하위 메뉴가 복수이고 모바일 접근성·키보드 동작이 검증된 경우에만 사용한다.
- **사이트맵**: 위 계층 구조를 후보로 사용하되 다른 Client 결과와 통합하기 전에는 최종 사이트맵으로 확정하지 않는다.
- **레이블 일관성**: 글로벌·로컬·브레드크럼·링크에서 동일한 메뉴명을 유지한다.
## 5. 화면 구성

- **헤더**: 브랜드·제품·사용 장면으로 진입하는 후보와 확정 CTA 후보를 검토한다. 대형 장식이나 미확정 제품 비주얼을 헤더 핵심으로 사용하지 않는다 (`VC005-REQ-002`, `VC005-REQ-006`).
- **내비게이션**: 확정 컬러를 제품군·정보 상태의 탐색 단서로 사용하고 텍스트 라벨을 함께 제공한다. 제품군 구분 방식은 165/197에서 확인됐지만 YOVIA 컬러·라인업은 추가 검증이 필요하다 (`VC005-REQ-003`; `SITE-001`, `SITE-004`, `SITE-015`, `SITE-176`).
- **핵심 콘텐츠**: 실제 패키지, 질감, 토핑, 개봉·섭취 과정을 제품 중심으로 제시한다. 제품·패키지 이미지는 170/197, 관련 질감·토핑·개봉·섭취 표현은 85/197에서 확인됐다. 타사 표현 방식만 참고하고 YOVIA 실제 자산으로 대체해야 한다 (`VC005-REQ-001`).
- **보조 콘텐츠**: 출근·등교·업무·이동 장면과 제품 정보·신뢰 근거를 연결한다. 의료적 공포 이미지, 과도한 장식, 미확정 맛·효능의 사실적 합성은 제외한다 (`VC005-REQ-004`, `VC005-REQ-006`).
- **푸터**: 이미지 사용권·자산 출처·법적 고지 연결은 실제 운영 자료가 확정될 때 검토한다. 현재는 `not_verified`이며 푸터 구성을 확정하지 않는다.

### 5.1 화면 배치 우선순위

| 화면 영역 | 배치 원칙 | 자료 유형 |
|---|---|---|
| 헤더 | 브랜드 식별과 현재 Client의 핵심 상위 탐색을 우선하고 미확정 CTA는 제외 | 텍스트·로고 |
| 내비게이션 | 현재 위치, 상위·하위 메뉴, 이전 단계와 관련 정보 연결 | 텍스트·링크 |
| 바디 | 높음 Requirement의 핵심 사실·과정·이미지를 먼저 배치 | 텍스트·이미지·영상·검증 데이터 |
| 어사이드 | 관련 자료, 기준일, 상태, 보조 행동만 배치하며 모바일에서는 본문 뒤로 이동 | 텍스트·상태 데이터 |
| 푸터 | 확정된 기업·정책·문의·저작권 정보만 연결 | 텍스트·링크 |

- **사용자 행동 경로**: 핵심 정보 이해 → 조건·근거 확인 → 관련 정보 비교 → 확정된 다음 행동 순서를 유지한다.
- **반응형 원칙**: 웹과 모바일에서 정보 의미와 이동 순서는 동일하게 유지한다. 모바일에서는 1열로 재배치하되 핵심 정보·주의·CTA의 상대적 우선순위를 바꾸지 않는다.
- **화면 전환 원칙**: 링크명과 도착 화면의 제목을 일치시키고 오류·빈 상태·보류 상태에서는 이전 유효 화면과 상시 정보로 복귀할 수 있게 한다.
## 6. 검토 결과

- **누락 항목**: 원본 6개 Requirement를 모두 2~5번의 후보 또는 보류 판단에 연결했다. 최종 패키지 이미지, 요거트 질감·토핑·개봉·섭취 촬영, 맛·제품군, 브랜드 컬러, 이미지 사용권, 합성 자산 표시 원칙, 접근성 대비, 실제 CTA는 추가 검증이 필요하다.
- **중복 항목**: `VC005-REQ-001`의 제품 자산과 `VC005-REQ-004`의 사용 장면은 제품 행동 스토리로 연결하되, 전자는 구조·과정 이해, 후자는 일상 맥락으로 구분했다. `VC005-REQ-002`와 `VC005-REQ-003`은 브랜드 일관성과 탐색 위계로 연결하되 컬러의 정보 기능을 별도 유지했다.
- **사용자 관점의 개선점**: 첫 이미지에서 제품 형태와 핵심 차이를 이해할 수 있어야 하며, 감성 장면 뒤에는 관련 제품 정보가 바로 이어져야 한다. 모바일에서는 이미지를 연속 배치해 설명과 CTA를 아래로 밀기보다 대표 이미지·짧은 설명·상세 갤러리 순으로 단계화할 필요가 있다.
- **수정 사항**: 전체 200개 기록을 다시 분리해 `completed` 101개와 `partial` 96개, 총 유효 197개를 확인했다. `SITE-036`, `SITE-113`, `SITE-152`는 `dead/failed`로 제외했다. `partial`은 확인된 필드만 사용했고 `not_verified`는 관찰 수에서 제외했다. 타사의 패키지·맛·컬러·효능 비주얼을 YOVIA 확정 자산으로 전용하지 않았다.
- **보류·충돌·근거 부족**: 최종 제품과 맛·라인업·효능 자료가 없으므로 사실적인 합성 이미지나 가상 패키지를 실제 제품처럼 공개하지 않는다. 대형 이미지와 모바일 정보 효율의 충돌은 이미지 순서·비율 제어 후보로 완화한다. 의료적 표현과 제품보다 강한 장식은 제외하며 미확정 자산은 `HOLD` 또는 `NOT_VERIFIED`로 유지한다.
- **검증 결론**: 조건부 완료. 유효 사이트 197개를 기준으로 MENU 8개, CONTENT 10개, FUNCTION 9개 후보를 도출했으며, 최종 자산·라인업·효능·사용권이 없는 시각 요소는 `not_verified` 또는 `HOLD`로 유지했다.
### 6.1 반복 검토 체크리스트

- **요청 반영**: 원본 Requirement ID가 요구사항 표와 정보 구조에 모두 연결되어 있다.
- **누락·중복**: 누락 입력은 별도로 기록하고 중복 후보는 대표 레이블로 통합했다.
- **탐색 가능성**: 시작 화면, 이동 경로, 연결 페이지와 현재 위치 안내를 명시했다.
- **메뉴 깊이**: 3단계로 최대 5단계 이내다.
- **항목명 일관성**: 계층 구조·내비게이션·화면 구성에서 같은 명칭을 사용한다.
- **구조 변경 영향**: 상위 그룹 변경 시 로컬 메뉴·브레드크럼·관련 링크·화면 제목을 함께 점검한다.
- **웹·모바일 일관성**: 의미·우선순위·행동 순서를 유지하고 배치만 반응형으로 조정한다.
