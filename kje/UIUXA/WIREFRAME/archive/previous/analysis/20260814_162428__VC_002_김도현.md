# 가상클라이언트 기반 분석 결과 — VC-002 (김도현)

## 1. 가상 클라이언트

- **프로젝트 주제**: YOVIA의 확정 파우치·빌트인 스푼·토핑 관계와 준비부터 폐기까지의 사용 과정을 실제 제품 자료로 설명하고, 물리적 성능 주장은 시험 근거가 있을 때만 공개한다.
- **제작 목적**: 사용자가 패키지 구조와 개봉·결합·취식·정리 과정을 이해한 뒤 제품 상세 또는 확정된 다음 행동으로 이동하게 한다. 시험하지 않은 누수·내압·잔여물 감소나 미확정 패키지 사양은 약속하지 않는다.
- **제공 자료**: `SRC-BRAND-001`, `SRC-PER-001`, `SRC-PER-002`; `EVD-0002`, `EVD-0004`, `EVD-0009`, `EVD-0011`, `EVD-0012`; 리서치 `SITE-001~SITE-200` 중 유효 197개.
- **적용 매체**: 모바일 웹 우선, 데스크톱 확장. 작은 화면에서도 부품명·단계·주의사항의 순서와 라벨이 유지되어야 한다.

### 3.1 유사 항목 분류

- **같은 목적의 통합**: 동일한 메뉴에 연결된 Requirement는 하나의 정보 그룹으로 묶고, 각 Requirement ID와 근거는 유지했다.
- **중복 처리**: 같은 의미의 메뉴·콘텐츠·기능은 대표 레이블 아래 통합했다. 서로 다른 검증 상태나 적용 범위는 합치지 않았다.
- **제외·보류**: 보류, HOLD, NOT_VERIFIED 항목은 확정 메뉴·CTA·카피에서 제외하고 검토 상태로 남겼다.
- **노출 우선순위**: 높음 요구를 핵심 정보, 보통 이상을 보조 정보, 보류를 비공개 검증 항목으로 배치한다.
- **자료 유형**: 제품 형태·구조는 이미지, 사용 순서는 이미지·영상, 사실·주의·정책은 텍스트, 수치·상태·비교는 검증된 데이터셋으로 분류한다. 실제 자료가 없으면 대체 자산을 생성하지 않는다.

- **메뉴 후보 원본 수**: 5개
- **통합 상위 그룹 수**: 4개
- **메뉴 폭 검토**: 조건부 적합 — 상위 그룹 4개로 권장 폭 5~9개보다 작지만 현재 Client의 제한된 과업 범위에 불필요한 메뉴를 추가하지 않는다.

## 4. 내비게이션

- **시작 화면**: 실제 제품 구조와 핵심 사용 단계를 먼저 이해할 수 있는 진입 후보가 필요하다. 감성적 편의 문구보다 확정된 제품 이미지와 구조 설명을 우선한다 (`VC002-REQ-001`, `VC002-REQ-002`; `SITE-001`, `SITE-015`).
- **이동 경로**: 제품 구조 → 사용 방법 → 사용 전후·품질 근거 → 제품 상세 또는 확정된 다음 행동으로 이어지는 탐색 후보를 둔다. 품질 근거와 사용 전후 자료가 없으면 검증 대기 상태를 표시하고 성능을 단정하지 않는다 (`VC002-REQ-002`, `VC002-REQ-003`, `VC002-REQ-005`).
- **연결 페이지**: 제품 구조·사용 방법 후보에서 확정 제품 상세로 이동할 수 있어야 한다. 구매나 문의 연결은 실제 전환 목적이 확정된 뒤 채택한다 (`VC002-REQ-001`, `VC002-REQ-002`; `SITE-015`, `SITE-018`).
- **검색 및 위치 안내**: 리서치에서 VC-002 요구를 뒷받침하는 검색·브레드크럼 근거는 확인하지 못했다. 별도 검색이나 위치 체계는 `not_verified`이며 최종 내비게이션으로 확정하지 않는다.

### 4.1 내비게이션 유형 검토

- **글로벌 내비게이션 후보**: 제품 이해, 이용 안내, 신뢰·안전 정보, 행동·지원. 이는 Client별 상위 탐색 그룹이며 최종 GNB 확정안이 아니다.
- **로컬 내비게이션 후보**: 각 상위 그룹 아래에 위 계층 구조의 메뉴 후보를 배치한다.
- **브레드크럼**: 직접 진입과 현재 위치 이해가 필요한 화면에서 상위 그룹 → 메뉴 → 현재 콘텐츠 경로 후보를 제공한다.
- **검색창**: 실제 문서량·검색어·색인 정책이 확인된 경우에만 적용하며, 미확정이면 `not_verified`로 유지한다.
- **풀다운 메뉴**: 하위 메뉴가 복수이고 모바일 접근성·키보드 동작이 검증된 경우에만 사용한다.
- **사이트맵**: 위 계층 구조를 후보로 사용하되 다른 Client 결과와 통합하기 전에는 최종 사이트맵으로 확정하지 않는다.
- **레이블 일관성**: 글로벌·로컬·브레드크럼·링크에서 동일한 메뉴명을 유지한다.
## 5. 화면 구성

- **헤더**: 제품 구조와 사용 방법으로 진입하는 탐색 후보를 우선 검토한다. 품질·시험 정보는 근거가 확보될 때 접근 가능하게 하되, 현재 최종 메뉴 구성은 확정하지 않는다 (`VC002-REQ-001~004`).
- **내비게이션**: 모바일에서 단계 순서와 라벨이 잘리지 않는 1열 흐름 후보가 유효하다. 유효 기록 중 모바일 흐름은 87/197, 명시적 1열·세로 흐름은 54/197에서 확인됐다 (`VC002-REQ-004`; `SITE-001`, `SITE-015`, `SITE-018`).
- **핵심 콘텐츠**: 실제 제품 구조 이미지, 부품 라벨, 개봉→결합→취식→정리 단계와 손–제품 상호작용을 우선 후보로 둔다. 빌트인 스푼 동일 사례는 0/197이므로 타사 캡·스파웃·컵 스푼을 동일 구조로 표현하지 않는다 (`VC002-REQ-001`, `VC002-REQ-002`).
- **보조 콘텐츠**: 사용 전후 비교, 시험 결과, 주의·안전·보관, 소재·폐기 안내는 필요하지만 현재 근거가 부족하다. `not_verified` 또는 `HOLD`로 표시하고 실제 YOVIA 자산·시험 결과가 확보된 뒤 공개한다 (`VC002-REQ-003~006`).
- **푸터**: VC-002 요구와 리서치 관찰만으로 별도 푸터 기능을 확정할 근거가 없다. 시험 출처나 정책 연결이 필요해질 수 있으나 현재는 `not_verified`다.

### 5.1 화면 배치 우선순위

| 화면 영역 | 배치 원칙 | 자료 유형 |
|---|---|---|
| 헤더 | 브랜드 식별과 현재 Client의 핵심 상위 탐색을 우선하고 미확정 CTA는 제외 | 텍스트·로고 |
| 내비게이션 | 현재 위치, 상위·하위 메뉴, 이전 단계와 관련 정보 연결 | 텍스트·링크 |
| 바디 | 높음 Requirement의 핵심 사실·과정·이미지를 먼저 배치 | 텍스트·이미지·영상·검증 데이터 |
| 어사이드 | 관련 자료, 기준일, 상태, 보조 행동만 배치하며 모바일에서는 본문 뒤로 이동 | 텍스트·상태 데이터 |
| 푸터 | 확정된 기업·정책·문의·저작권 정보만 연결 | 텍스트·링크 |

- **사용자 행동 경로**: 핵심 정보 이해 → 조건·근거 확인 → 관련 정보 비교 → 확정된 다음 행동 순서를 유지한다.
- **반응형 원칙**: 웹과 모바일에서 정보 의미와 이동 순서는 동일하게 유지한다. 모바일에서는 1열로 재배치하되 핵심 정보·주의·CTA의 상대적 우선순위를 바꾸지 않는다.
- **화면 전환 원칙**: 링크명과 도착 화면의 제목을 일치시키고 오류·빈 상태·보류 상태에서는 이전 유효 화면과 상시 정보로 복귀할 수 있게 한다.
## 6. 검토 결과

- **누락 항목**: 원본 6개 Requirement를 모두 2~5번의 후보 또는 보류 판단에 연결했다. 추가 입력이 필요한 항목은 빌트인 스푼 결합 구조, 실제 개봉·취식·정리 동선, 사용 전후 이미지, 누수·내압·잔여물 시험, 주의사항, 최종 소재·폐기 방법, 대체 구조의 확정 여부다.
- **중복 항목**: `VC002-REQ-001`과 `VC002-REQ-004`의 구조·라벨 요구, `VC002-REQ-002`와 `VC002-REQ-005`의 전체 사용 과정, `VC002-REQ-003`과 `VC002-REQ-006`의 검증·사양 통제는 서로 연결하되 각 Requirement ID와 판정은 유지했다.
- **사용자 관점의 개선점**: 정적인 팩샷만 제시하지 않고 실제 부품 관계, 손의 행동, 단계별 상태 변화를 연결해야 한다. 모바일에서도 순서를 보존하고, 성능 주장 옆에는 시험 조건과 출처를 확인할 수 있는 상태를 제공해야 한다.
- **수정 사항**: 전체 200개 기록의 상태를 다시 집계해 `completed` 101개와 `partial` 96개, 총 유효 197개를 확인했다. `SITE-036`, `SITE-113`, `SITE-152`는 `dead/failed`로 제외했다. `partial`의 미확인 필드와 `not_verified`는 관찰 수에 포함하지 않았다. 기존 초안의 축약 Requirement ID를 모두 원본 형식으로 복원하고, 별도 MENU·CONTENT·FUNCTION 및 추적성 섹션을 고정 1~6 양식 안으로 통합했다.
- **보류·충돌·근거 부족**: 빌트인 스푼 동일 사례와 누수·내압·잔여물·사용 전후·주의사항의 명시적 검증 기록은 각각 0/197이다. 타사 스파웃·캡·컵 스푼, 친환경·재활용 설명은 YOVIA의 확정 사양이나 성능 근거로 전용하지 않는다. 운전 중 취식 장면은 안전상 제외한다. 듀얼 챔버·스파우트·특수 실링과 구매 CTA는 확정 전까지 `HOLD`다.
- **검증 결론**: 조건부 완료. 유효 사이트 197개를 기준으로 MENU 6개, CONTENT 9개, FUNCTION 9개 후보를 도출했으며, 근거가 없는 항목은 `not_verified`·`HOLD`·추가 검증 필요로 유지했다.
### 6.1 반복 검토 체크리스트

- **요청 반영**: 원본 Requirement ID가 요구사항 표와 정보 구조에 모두 연결되어 있다.
- **누락·중복**: 누락 입력은 별도로 기록하고 중복 후보는 대표 레이블로 통합했다.
- **탐색 가능성**: 시작 화면, 이동 경로, 연결 페이지와 현재 위치 안내를 명시했다.
- **메뉴 깊이**: 3단계로 최대 5단계 이내다.
- **항목명 일관성**: 계층 구조·내비게이션·화면 구성에서 같은 명칭을 사용한다.
- **구조 변경 영향**: 상위 그룹 변경 시 로컬 메뉴·브레드크럼·관련 링크·화면 제목을 함께 점검한다.
- **웹·모바일 일관성**: 의미·우선순위·행동 순서를 유지하고 배치만 반응형으로 조정한다.
