## 범위와 독립 설계 원칙
개인정보 최소화 분석만을 기준으로 핵심 3화면과 전용 과업 2화면을 설계한다. 전용 컴포넌트는 **필수/선택 동의표·동등 선택 버튼**다.

### MAIN-001 — 메인페이지(홈)

| 구분 | 화면 설계 내용 |
|---|---|
| 화면명 | 메인페이지(홈) (MAIN-001) |
| 화면 목적 | 개인정보 최소화 관점의 브랜드·상품 탐색 시작 |
| 주요 콘텐츠 | 브랜드·제품 가치, 카테고리 진입, 상품 15개, 브랜드 소개 진입, 검증 상태 |
| 인터페이스 요소 | 본문 바로가기, 헤더, 전역 내비게이션, 상품 카드 15개, 상태 라벨, 푸터. 화면 고유 콘텐츠는 ‘브랜드·제품 가치, 카테고리 진입, 상품 15개, 브랜드 소개 진입, 검증 상태’이며 주요 조작은 ‘카테고리 보기, 브랜드 소개 보기’이다. |
| 레이아웃 | 본문 바로가기 → 헤더·전역 내비게이션 → 브랜드·제품 가치 → 카테고리 진입 → 상품 15개 → 브랜드 소개 → 검증 상태 → 푸터 순서로 배치한다. 모바일부터 데스크톱까지 상품 DOM 순서를 유지한다. |
| 작동 방식 | ‘카테고리 보기, 브랜드 소개 보기’를 수행한다. 지원 상태는 기본, 로딩, 빈 상태, 오류, 완료이며, 오류 발생 시 재시도·수정·이전 단계 중 적절한 복구 수단을 제공한다. |
| 연결 화면 | CATEGORY-001, BRAND-001 |
| 사용자 경로 | 직접 진입 또는 CATEGORY-001, BRAND-001에서 복귀 → 카테고리 보기, 브랜드 소개 보기 → CATEGORY-001, BRAND-001 |
| 비고·주석 | 제목, 상태 텍스트, 키보드 포커스, 오류 복구. 확인되지 않은 상품·가격·재고·정책·효능·인증 정보는 NOT_VERIFIED 또는 HOLD로 표시하고 활성 CTA로 확정하지 않는다. |

## 공통 구조·반응형
본문 바로가기, 전역 내비게이션, 상태 영역, 푸터를 공통 적용한다. 모바일 1~2열, 태블릿 2~3열, PC 3~5열이며 PRODUCT DOM 순서는 유지한다.
## 유효성·오류
필수 입력 누락은 필드 인접 문구로 알리고 오류마다 재시도·수정·이전 단계 중 하나를 제공한다.

44px 조작 영역, 명확한 포커스, 의미 있는 제목, 이미지 대체 텍스트, 색상 외 상태 텍스트, 라이브 상태 안내를 적용한다.
## Requirement 추적
- **VC014-REQ-001** (높음): 수집 항목·목적·필수 여부를 행동 전에 설명
- **VC014-REQ-002** (높음): 비필수 동의 거부 후에도 핵심 제품 정보 접근 유지
- **VC014-REQ-003** (보통 이상): 위치 권한 거부 시 직접 지역 선택 대안 제공
- **VC014-REQ-004** (보통 이상): 동의 상태 확인·변경·철회 경로 후보 제공
- **VC014-REQ-005** (보통 이상): 모바일에서 수락과 거부 선택을 동등하게 이해
- **VC014-REQ-006** (보류): 정책·보관기간·도구 확정 전 준수 문구를 단정하지 않음
## 가정·HOLD·제외
15개는 상품 슬롯 수이며 실제 라인업 수가 아니다. 미확정 상품 정보와 정책은 NOT_VERIFIED 또는 HOLD다.
