# YOVIA 카테고리페이지 작업 인수인계

## 1. 인수인계 목적

VC-001 서하린 설계에 추가된 `P-006 제품 카테고리`의 현재 상태와 15개 상품 구조, 완료 산출물, 정보 통제 기준 및 다음 작업 순서를 정리한다.

현재 완료된 스토리보드 범위는 다음과 같다.

```text
P-001 메인페이지
P-005 브랜드 소개
P-006 제품 카테고리
```

아직 개별 스토리보드 제작이 남은 기존 화면은 다음과 같다.

```text
P-002 제품 상세
P-003 사용 안내
P-004 성분·영양
```

## 2. 핵심 결정

- 카테고리 화면 ID는 `P-006`이다.
- 카테고리에는 `PRODUCT-001`~`PRODUCT-015`의 독립 상품 카드 15개가 존재한다.
- 15개는 현재 설계 슬롯 수이며 실제 출시 상품 15종 확정을 뜻하지 않는다.
- 모든 카드를 한 그리드에 평면적으로 나열하지 않는다.
- `YOVIA 팩 7종`을 하나의 주 상품 그룹으로 묶는다.
- 퓨레와 토핑은 팩과 조합하는 페어링 상품 그룹으로 분리한다.
- 가격·재고·구매·장바구니·구독 기능은 관련 정책과 화면 확정 전까지 추가하지 않는다.
- 건강·영양·친환경·제조 기술은 검증 자료가 없는 상태에서 확정 표현으로 사용하지 않는다.

## 3. 카테고리 정보 구조

```text
P-006 제품 카테고리
├─ YOVIA 팩 7종
│  ├─ 기본 팩 3종
│  └─ 시그니처·스타터 팩 4종
├─ 생과일 퓨레 스틱 5종
└─ 견과류 토핑 3종
```

필터 구조:

```text
전체 15
팩 7
퓨레 5
토핑 3
```

## 5. 시그니처 상품 근거

추가 입력 파일:

```text
프롬프트/yovia_시그니처팩.txt
```

확인된 구성:

### PRODUCT-012 — yovia 7AM 갓생 팩

```text
120g 베이스
통곡물 그래놀라·호두
블루베리 퓨레
```

### PRODUCT-013 — yovia 3PM 리프레시 팩

```text
120g 베이스
카카오닙스·코코넛
스트로베리 퓨레
```

### PRODUCT-014 — yovia 위켄드 뷰티 팩

```text
120g 또는 400g 베이스
햄프씨드·아몬드
망고 퓨레
```

### PRODUCT-015 — yovia 스타터 팩

```text
7AM 갓생 팩 2개
3PM 리프레시 팩 2개
위켄드 뷰티 팩 2개
총 6개입
```

시그니처 3종은 기획서의 `시그니처 메뉴 제안`, 스타터 팩은 `런칭 전용 상품`이므로 실제 출시 확정으로 표현하지 않는다.

## 6. 정보 통제

### 사용 가능한 정보

- 공식 브랜드명 `yovia(요비아)`
- 기본 제품 3종 명칭
- 퓨레 스틱 5개 슬롯 요구
- 견과류 토핑 3개 슬롯 요구
- 시그니처 3종의 명칭과 조합 제안
- 스타터 팩의 6개입 구성 제안
- 전체 카테고리 상품 슬롯 15개 요구

### HOLD 또는 검증 필요

- 퓨레 스틱 5종의 실제 과일 맛 이름
- 토핑 3종의 실제 조합 이름
- 제품 이미지·패키지 이미지
- 가격·할인·재고·판매 상태
- 출시일·유통기한·배송 정책
- 원재료·영양성분·알레르기
- 락토프리·무가당·저당·고단백 표시 기준
- Dual-Chamber·Easy-Peel·Gas Flushing·PLA·빌트인 스푼 실제 적용
- 패키지 양산·시험·인증 자료

### 사용 금지 표현

검증 자료 확보 전에는 다음을 상품 카드나 스토리보드에서 확정 표현으로 사용하지 않는다.

```text
혈당 스파이크 차단
소화 안전성 보장
다이어트·체중 감소 효과
질병 예방
100% 생분해
100% 친환경
경쟁 제품이 전무함
확정 가격·마진·수익률
```

## 7. 현재 설계 파일

VC-001 원본:

```text
가상 클라이언트 설계 결과/001_서하린/
├─ 사이트맵.md
├─ 사이트맵.mmd
├─ 사이트맵.svg
├─ 서비스_흐름도.md
├─ 서비스_흐름도.mmd
├─ 서비스_흐름도.svg
├─ 화면_설계서.md
├─ 화면_목록.json
└─ 와이어프레임.html
```

스토리보드 입력용 최신 복제본:

```text
설계 출력물/
├─ 사이트 구조맵/
├─ 서비스 흐름도/
└─ 화면 설계서/
```

P-006은 위 9개 설계 산출물에 반영되어 있다.

```text
스토리보드 결과/
```

카테고리 HTML 직접 확인:

```text

```

## 9. 카테고리 화면 동작

- 공통 내비게이션에서 `제품 카테고리`를 선택해 P-006에 진입한다.
- 전체 15·팩 7·퓨레 5·토핑 3 필터를 제공한다.
- 통합 와이어프레임은 JavaScript로 상품 카드를 세 그룹에 재배치한다.
- 팩 그룹에는 기본 팩과 시그니처·스타터 팩이 함께 표시된다.
- 필터 선택 시 결과 개수를 라이브 텍스트로 알린다.
- 제품 상세 이동은 현재 설계된 `P-002 제품 상세` 범위로만 연결한다.
- 가격·구매·장바구니·구독 CTA는 생성하지 않는다.

## 10. 반응형·접근성 기준

- 모바일: 상품 카드 1열
- 태블릿: 상품 카드 2열
- 데스크톱: 상품 카드 3열
- 모든 상품에 고유 PRODUCT ID를 유지한다.
- 실제 이미지가 없으므로 텍스트 플레이스홀더와 대체 설명을 사용한다.
- 필터 선택 상태는 `aria-pressed`로 전달한다.
- 결과 수는 `aria-live` 영역으로 전달한다.
- 화면 전환 후 화면 제목으로 포커스를 이동한다.
- 현재 내비게이션은 `aria-current="page"`로 표시한다.

## 11. 검증 완료 사항

- JSON 화면 수: 6개 (`P-001`~`P-006`)
- JSON P-006 상품 수: 15개
- 고유 PRODUCT ID: 15개
- 통합 와이어프레임 상품 카드: 15개
- 카테고리 스토리보드 HTML 상품 카드: 15개
- 중복 PRODUCT ID: 0건
- JavaScript 문법: 정상
- 원본과 `설계 출력물` 와이어프레임: 동기화
- 사이트맵·서비스 흐름도 SVG: P-006 반영 후 재생성
- 미검증 건강·친환경 주장: 카테고리 카드에서 제외

## 12. 다음 작업 권장 순서

### 1단계 — 퓨레·토핑 실제 명칭 확정

```text
생과일 퓨레 스틱 01~05 → 실제 과일 맛 이름
견과류 토핑 01~03 → 실제 조합 이름
```

명칭이 확정되면 JSON, 통합 와이어프레임, 카테고리 Markdown·HTML을 함께 수정한다.

### 2단계 — 제품 상세 설계 범위 결정

현재 `P-002 제품 상세`는 공통 구조 설명 화면이다. 다음 중 하나를 결정해야 한다.

```text
안 A: P-002 한 화면에서 선택한 PRODUCT ID에 따라 상품 정보 전환
안 B: 상품마다 별도 상세 화면 ID 생성
```

현재 근거와 작업량을 고려하면 안 A가 우선 권장된다.

### 3단계 — P-002 제품 상세 스토리보드 제작

- 카테고리에서 선택한 상품 ID 전달 방식 정의
- 기본 팩·퓨레·토핑·시그니처별 상세 정보 차이 정의
- 이미지·가격·영양·원료 미확정 상태 정의
- 구매 기능 없이 카테고리 복귀와 사용 안내 연결

### 4단계 — P-003 사용 안내 스토리보드 제작

- 팩 개봉·준비·섭취·정리 흐름
- 퓨레·토핑 조합 사용 방법
- 검증되지 않은 실제 패키지 작동 방식은 HOLD 유지

### 5단계 — P-004 성분·영양 스토리보드 제작

- 공식 원료·영양·알레르기 자료 확보 후 확정
- 자료가 없으면 플레이스홀더와 추가 필요 상태 중심으로 제작

## 13. 금지 사항

- 15개 상품을 다시 하나의 평면 그리드로만 나열
- 기본 팩과 시그니처 팩을 서로 무관한 제품군처럼 분리
- 퓨레·토핑의 실제 이름을 근거 없이 창작
- 시그니처 제안을 출시 확정 상품으로 표현
- 상품 가격·할인·재고·구매 버튼 임의 생성
- P-006 없이 메인에서 모든 상품을 직접 상세로 연결
- PRODUCT ID를 문서·JSON·HTML마다 다르게 사용
- 다른 가상 클라이언트의 상품 정보를 혼합

## 14. 재개 위치

다음 작업은 퓨레 5종과 토핑 3종의 실제 명칭을 확인하는 것부터 시작한다.

명칭 자료가 아직 없다면 `P-002 제품 상세`를 단일 동적 화면으로 확장하는 설계부터 진행한다.

필수 입력:

```text

가상 클라이언트 설계 결과/001_서하린/화면_목록.json
가상 클라이언트 설계 결과/001_서하린/와이어프레임.html
스토리보드 결과/카테고리페이지_스토리보드.md
```
