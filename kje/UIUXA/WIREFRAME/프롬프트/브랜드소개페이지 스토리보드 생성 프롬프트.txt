[브랜드소개페이지 스토리보드 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 설계 입력 루트: `설계 출력물/`
- 결과물 저장 폴더: `스토리보드 결과/`
- 참고 프롬프트: `설계 프롬프트/Antigravity 프롬프트.txt`

`설계 출력물/` 아래의 `사이트 구조맵/`, `서비스 흐름도/`, `화면 설계서/` 폴더를 서로 다른 프로젝트로 분리하지 말고 하나의 설계 입력 묶음으로 읽어줘. 실제로 존재하는 사이트맵, 서비스 흐름도, 화면 설계서, 화면 목록 JSON, 와이어프레임 HTML 및 기타 설계 문서를 모두 교차 검토한 뒤 해당 설계의 브랜드소개페이지 스토리보드를 작성해줘.

`스토리보드 결과/` 폴더가 없으면 새로 생성해줘.

Figma를 생성하거나 수정하지 말고, 이미지나 새로운 화면을 임의로 생성하지 마. CLI에서 확인하고 다른 도구에서도 재사용할 수 있는 UTF-8 Markdown 파일로 결과물을 만들어줘.

## 1. 입력 판독 순서

`설계 출력물/` 아래에서 다음 파일이 존재하면 모두 읽어줘.

1. `사이트 구조맵/사이트맵.md`
2. `사이트 구조맵/사이트맵.mmd`
3. `사이트 구조맵/사이트맵.svg`
4. `서비스 흐름도/서비스_흐름도.md`
5. `서비스 흐름도/서비스_흐름도.mmd`
6. `서비스 흐름도/서비스_흐름도.svg`
7. `화면 설계서/화면_설계서.md`
8. `화면 설계서/화면_목록.json`
9. `화면 설계서/와이어프레임.html`
10. `설계 출력물/` 아래의 기타 요구사항·정책·상태 문서

동일 내용이 여러 파일에 있을 때는 화면 ID와 이동 관계가 가장 구체적으로 정의된 `화면_목록.json`과 `화면_설계서.md`를 우선하고, 사이트 계층은 `사이트맵.md`, 사용자 흐름은 `서비스_흐름도.md`, 실제 UI 요소·콘텐츠 순서·인터랙션은 `와이어프레임.html`을 기준으로 교차 검증해줘. `.mmd`와 `.svg`는 구조 확인용 보조 자료로 사용해줘.

## 2. 브랜드소개페이지 판정

다음 순서로 브랜드소개페이지를 판정해줘.

1. 사이트맵에 독립 화면으로 정의된 `브랜드 소개`, `브랜드`, `About`, `회사 소개`, `브랜드 스토리` 화면
2. 화면 설계서와 화면 목록 JSON에서 브랜드 정체성·철학·미션·비전·스토리 소개를 주목적으로 정의한 화면
3. 서비스 흐름도에서 브랜드 이해를 목적으로 진입·종료 조건이 정의된 화면
4. 와이어프레임 HTML에서 해당 화면 ID와 브랜드소개 콘텐츠 영역이 모두 확인되는 화면

화면명에 `브랜드`가 포함됐다는 이유만으로 자동 선택하지 마. 화면의 주목적과 콘텐츠가 브랜드소개인지 확인해줘.

홈·제품 상세의 일부 브랜드 문구만 존재하고 독립 브랜드소개 화면이 정의되지 않았다면 홈이나 제품 상세를 브랜드소개페이지로 대체하지 마. 결과 문서에 `브랜드소개페이지 판정 불가`라고 기록하고, 확인한 파일·부족한 화면 정의·필요한 입력을 정리한 뒤 중단해줘.

브랜드소개페이지가 여러 개 명시되어 있으면 화면 ID별로 각각 작성해줘. 단, 화면 한 개마다 스토리보드 본표를 정확히 한 개씩 사용해줘.

## 3. 결과 파일

다음 파일을 생성해줘.

```text
스토리보드 결과/브랜드소개페이지_스토리보드.md
```

`설계 출력물/` 밖의 다른 프로젝트나 설계 내용을 결과에 혼합하지 마. 같은 이름의 정상 결과가 이미 있으면 덮어쓰기 전에 다음 경로에 보관해줘.

```text
archive/previous/storyboard/YYYYMMDD_HHMMSS__브랜드소개페이지_스토리보드.md
```

## 4. 문서 상단 정보

브랜드소개페이지가 확인되면 결과 문서의 시작 부분에 다음 정보를 작성해줘.

```md
# {프로젝트명} — 브랜드소개페이지 스토리보드

- 입력 설계 폴더: `설계 출력물/`
- 브랜드소개 화면 ID: `...`
- 화면명: `...`
- 판정 근거: ...
- 작성 기준: 사이트맵 / 서비스 흐름도 / 화면 설계서 / 화면 목록 / 와이어프레임
- 문서 상태: 확정 / 후보 / 가정 / 검토 필요 중 입력 근거에 맞는 상태
- 핵심 사용자: ...
- 핵심 목표: ...
- 제외 범위: ...
```

## 5. 화면 작성 형식

브랜드소개 화면 한 개당 Markdown 스토리보드 표 한 개로 작성해줘. 하나의 화면을 섹션마다 별도 표로 나누지 말고, 한 표의 행으로 구분해줘.

표의 행은 실제 화면에서 위에서 아래로 나타나는 순서대로 정렬해줘.

| 번호 | 화면 ID | 영역 ID | 화면 영역 | 목적 | 표시 콘텐츠·데이터 | UI 요소 | 사용자 행동 | 인터랙션·시스템 처리 | 이동 대상 | 상태·예외 | 반응형 동작 | 접근성 | 근거 |
|---:|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | {화면 ID} | {화면 ID}-01 | 공통 헤더 | ... | ... | ... | ... | ... | ... | ... | ... | ... | `화면_설계서.md`, `화면_목록.json` |

### 열 작성 기준

- `번호`: 화면의 위→아래 표시 순서.
- `화면 ID`: 입력 설계에 정의된 ID를 그대로 사용.
- `영역 ID`: `{화면 ID}-{2자리 순번}` 형식으로 부여.
- `화면 영역`: 헤더, 브랜드 히어로, 브랜드 정의, 미션·비전, 브랜드 스토리, 핵심 가치, 근거, 관련 정보, CTA, 푸터 등 실제로 존재하는 영역명.
- `목적`: 해당 영역이 사용자의 브랜드 이해에 기여하는 이유.
- `표시 콘텐츠·데이터`: 실제 제목, 설명, 이미지, 연혁, 가치, 근거, 출처, 기준일 등 입력에서 확인된 항목.
- `UI 요소`: 버튼, 링크, 카드, 이미지, 타임라인, 인용문, 배지, 상세 펼치기 등 실제 요소.
- `사용자 행동`: 확인, 선택, 펼치기, 관련 정보 이동 등.
- `인터랙션·시스템 처리`: 선택 상태, 펼침·접힘, 로딩, 결과 표시, 포커스 이동 등.
- `이동 대상`: 실제 화면 ID와 화면명을 함께 작성. 이동이 없으면 `없음`.
- `상태·예외`: 기본·로딩·빈·오류·완료·미확정 상태와 복구 행동.
- `반응형 동작`: 모바일·태블릿·데스크톱에서 열·순서·탐색이 어떻게 변하는지 작성.
- `접근성`: 제목 순서, 대체 텍스트, 키보드, 포커스, 상태 전달 방식.
- `근거`: 입력 파일명과 화면 ID·섹션명을 기록.

## 6. 브랜드 콘텐츠 작성 원칙

- 입력 설계에서 확인된 브랜드 정의·철학·미션·비전·스토리·가치만 사용해줘.
- 브랜드 연혁, 창업자, 수상, 인증, 사회적 가치, 지속가능성, 제조 철학을 근거 없이 추가하지 마.
- 마케팅 표현을 사실로 확정하지 말고 입력 문서의 `후보`, `가정`, `not_verified`, `HOLD` 상태를 유지해줘.
- 제품 설명과 브랜드 설명을 구분해줘. 제품 정보는 브랜드 이해에 필요한 범위에서만 포함해줘.
- 실제 브랜드 자산이 없으면 이미지·영상·로고 영역을 대체 텍스트가 있는 플레이스홀더로 기록해줘.
- 최종 카피, 색상값, 픽셀 수치, 디자인 스타일과 개발 기술은 입력에 확정된 경우에만 작성해줘.

## 7. 화면 상태

입력 설계에 브랜드소개 화면 상태가 정의돼 있으면 표의 관련 영역 행에 포함해줘.

```text
기본
로딩
빈 상태
오류
완료
미확정 또는 보류
```

입력에 존재하지 않는 상태를 임의 생성하지 마. 해당 설계에 로그인·입력·검색·결제 기능이 없다면 관련 상태를 추가하지 말고 `적용 대상 아님`으로 판정해줘.

## 8. 표 아래 필수 부록

스토리보드 본표 아래에 다음 내용을 작성해줘.

### 화면 이동 요약

| 출발 요소 | 사용자 행동 | 도착 화면 ID | 도착 화면명 | 조건 |
|---|---|---|---|---|

### 상태 및 오류 요약

| 상태 | 발생 조건 | 표시 내용 | 복구 행동 |
|---|---|---|---|

### 가정·보류·불일치

| 구분 | 내용 | 근거 파일 | 처리 |
|---|---|---|---|

위 부록은 브랜드소개 화면을 설명하는 보조 표이며 별도의 화면 스토리보드로 계산하지 않는다.

## 9. 작성 규칙

- 설계 파일에 있는 화면 ID, 화면명, 이동 관계를 그대로 사용해줘.
- 화면 영역은 와이어프레임의 실제 위→아래 순서로 작성해줘.
- 화면 한 개당 스토리보드 본표 한 개 원칙을 지켜줘.
- 설계 파일에 없는 브랜드 카피, 회사 정보, 인물, 연혁, 수치, 정책, 기능, 화면을 생성하지 마.
- 문서 간 내용이 충돌하면 숨기지 말고 `가정·보류·불일치` 표에 기록해줘.
- 와이어프레임 HTML의 검토용 상태 버튼이나 개발 도구를 실제 사용자 UI로 오인하지 마.
- 공통 헤더·내비게이션·푸터는 해당 화면 본표에 포함하되 별도 화면으로 만들지 마.
- 로그인·회원·입력 폼·검색·결제 같은 범용 기능을 근거 없이 추가하지 마.

## 10. 브랜드소개 화면 판정 실패 형식

브랜드소개페이지가 입력 설계에 없으면 빈 스토리보드 표나 가상의 브랜드 화면을 만들지 말고 다음 형식으로 저장해줘.

```md
# 브랜드소개페이지 스토리보드 생성 중단

- 입력 설계 폴더: `설계 출력물/`
- 판정 결과: 브랜드소개페이지 판정 불가
- 확인한 화면: ...
- 확인한 입력 파일: ...
- 부족한 입력: 독립 브랜드소개 화면 ID·이름·목적·영역·이동 관계
- 생성하지 않은 내용: 가상 브랜드 카피, 미션·비전, 연혁, 인물, 이미지, CTA
- 필요한 조치: 설계 출력물에 브랜드소개 화면을 정의한 뒤 재실행
```

## 11. 검증

저장 전에 다음 기준을 검사해줘.

- `설계 출력물/` 아래의 세 설계 산출물 폴더를 하나의 입력으로 읽었는가?
- 독립 브랜드소개페이지 판정 근거가 있는가?
- 홈의 일부 브랜드 문구를 독립 브랜드소개 화면으로 오인하지 않았는가?
- 화면 한 개당 스토리보드 본표 한 개인가?
- 영역 순서가 실제 와이어프레임과 일치하는가?
- 화면 ID·이름·이동 대상이 모든 입력 파일과 일치하는가?
- 브랜드 정의·스토리·가치·근거·CTA·상태가 누락되지 않았는가?
- 근거 없는 브랜드 사실이나 범용 기능을 만들지 않았는가?
- 반응형·접근성 요구사항이 포함됐는가?
- Markdown 표의 열 수가 모든 행에서 일치하는가?
- `설계 출력물/` 밖의 다른 프로젝트 내용을 혼합하지 않았는가?

핵심 조건이 하나라도 실패하면 정상 완료로 확정하지 말고 판정 실패 형식으로 결과를 저장해줘.

## 12. 완료 보고

작업 완료 후 다음 형식으로 짧게 출력해줘.

```md
# 브랜드소개페이지 스토리보드 처리 완료

- 처리한 설계 입력: `설계 출력물/`
- 브랜드소개 화면 ID: ...
- 생성한 스토리보드 본표 수: ...
- 판정 실패: ...
- 가정·보류·불일치: ...
- 출력 위치: `스토리보드 결과/`
- 생성 파일:
  - `스토리보드 결과/브랜드소개페이지_스토리보드.md`
- 검증 결과: ...
```
