[메인페이지 스토리보드 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 설계 입력 루트: `설계 출력물/`
- 결과물 저장 폴더: `스토리보드 결과/`

`설계 출력물/` 아래의 `사이트 구조맵/`, `서비스 흐름도/`, `화면 설계서/` 폴더를 서로 다른 프로젝트로 분리하지 말고 하나의 설계 입력 묶음으로 읽어줘. 실제로 존재하는 사이트맵, 서비스 흐름도, 화면 설계서, 화면 목록 JSON, 와이어프레임 HTML 및 기타 설계 문서를 모두 교차 검토한 뒤 해당 설계의 메인페이지 스토리보드를 작성해줘.

`스토리보드 결과/` 폴더가 없으면 새로 생성해줘.

Figma를 생성하거나 수정하지 말고, 이미지나 새로운 화면을 임의로 생성하지 마. CLI에서 확인하고 다른 도구에서도 재사용할 수 있는 UTF-8 Markdown 파일로 결과물을 만들어줘.

## 1. 입력 판독 순서

`설계 출력물/` 아래에서 다음 파일이 존재하면 모두 읽어줘.

1. `사이트 구조맵/사이트맵.md`
2. `사이트 구조맵/사이트맵.mmd`
3. `사이트 구조맵/사이트맵.svg`
4. `서비스 흐름도/서비스_흐름도.md`
5. `서비스 흐름도/서비스_흐름도.mmd`
6. `서비스 흐름도/서비스_흐름도.svg`
7. `화면 설계서/화면_설계서.md`
8. `화면 설계서/화면_목록.json`
9. `화면 설계서/와이어프레임.html`
10. `설계 출력물/` 아래의 기타 요구사항·정책·상태 문서

`.mmd`와 `.svg`는 구조 확인에 필요한 경우 보조 자료로 사용해줘. 동일 내용이 여러 파일에 있을 때는 화면 ID와 이동 관계가 가장 구체적으로 정의된 `화면_목록.json`과 `화면_설계서.md`를 우선하고, 사이트 계층은 `사이트맵.md`, 사용자 흐름은 `서비스_흐름도.md`, 실제 UI 요소와 인터랙션은 `와이어프레임.html`을 기준으로 교차 검증해줘.

## 2. 메인페이지 판정

다음 순서로 메인페이지를 판정해줘.

1. 사이트맵의 1차 진입 화면
2. 화면명이 `홈`, `메인`, `홈페이지`, `랜딩`인 화면
3. 기본 URL 또는 서비스 시작점으로 정의된 화면
4. 화면 목록에서 최초 진입 화면으로 지정된 화면

입력 설계에 메인페이지가 여러 개 명시되어 있으면 화면 ID별로 각각 작성해줘. 메인페이지가 명확하지 않으면 임의 선택하지 말고 결과 문서에 `메인페이지 판정 불가`와 필요한 확인 사항을 기록해줘.

메인페이지가 아닌 상세·목록·로그인·오류 화면은 독립 스토리보드로 작성하지 마. 단, 메인페이지 안에 포함되는 공통 헤더, 내비게이션, 콘텐츠 섹션, CTA, 푸터와 상태 표현은 빠짐없이 포함해줘.

## 3. 결과 파일

다음 결과 파일 하나를 생성해줘.

```text
스토리보드 결과/메인페이지_스토리보드.md
```

`설계 출력물/` 밖의 다른 프로젝트나 설계 내용을 결과에 혼합하지 마. 같은 이름의 정상 결과가 이미 있으면 기존 파일을 덮어쓰기 전에 다음 경로에 보관해줘.

```text
archive/previous/storyboard/YYYYMMDD_HHMMSS__{기존 파일명}
```

## 4. 문서 상단 정보

각 결과 문서의 시작 부분에 다음 정보를 작성해줘.

```md
# {프로젝트 또는 설계 단위명} — 메인페이지 스토리보드

- 입력 설계 폴더: `...`
- 메인 화면 ID: `...`
- 메인 화면명: `...`
- 작성 기준: 사이트맵 / 서비스 흐름도 / 화면 설계서 / 화면 목록 / 와이어프레임
- 문서 상태: 확정 / 후보 / 가정 / 검토 필요 중 입력 근거에 맞는 상태
- 제외 범위: ...
```

## 5. 화면 작성 형식

화면 한 개당 Markdown 표 한 개로 작성해줘. 메인페이지가 한 화면이면 표도 한 개만 작성하고, 임의로 여러 화면이나 여러 표로 분할하지 마.

표의 행은 실제 화면에서 위에서 아래로 나타나는 순서대로 정렬해줘.

| 번호 | 화면 ID | 영역 ID | 화면 영역 | 목적 | 표시 콘텐츠·데이터 | UI 요소 | 사용자 행동 | 인터랙션·시스템 처리 | 이동 대상 | 상태·예외 | 반응형 동작 | 접근성 | 근거 |
|---:|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | P-001 | P-001-01 | 공통 헤더 | ... | ... | ... | ... | ... | ... | ... | ... | ... | `화면_설계서.md`, `화면_목록.json` |

### 열 작성 기준

- `번호`: 화면의 위→아래 표시 순서.
- `화면 ID`: 입력 설계 파일에 정의된 ID를 그대로 사용.
- `영역 ID`: `{화면 ID}-{2자리 순번}` 형식으로 부여.
- `화면 영역`: 헤더, 히어로, 핵심 콘텐츠, 관련 정보, CTA, 푸터 등 실제 영역명.
- `목적`: 해당 영역이 사용자 목표에 기여하는 이유.
- `표시 콘텐츠·데이터`: 제목, 설명, 이미지, 상태, 출처, 기준일 등 실제 표시 항목.
- `UI 요소`: 버튼, 링크, 카드, 탭, 이미지, 배지, 표, 상세 펼치기 등.
- `사용자 행동`: 사용자가 클릭·선택·확인·이동하는 행동.
- `인터랙션·시스템 처리`: 선택 상태, 펼침·접힘, 로딩, 결과 표시, 포커스 이동 등.
- `이동 대상`: 실제 화면 ID와 화면명을 함께 작성. 이동이 없으면 `없음`.
- `상태·예외`: 기본·로딩·빈·오류·완료·미확정 상태와 복구 행동.
- `반응형 동작`: 모바일·태블릿·데스크톱에서 열·순서·탐색이 어떻게 변하는지 작성.
- `접근성`: 제목 순서, 대체 텍스트, 키보드, 포커스, 상태 전달 방식.
- `근거`: 내용을 확인한 입력 파일명과 필요하면 화면 ID·섹션명을 기록.

## 6. 화면 상태

메인페이지에 정의된 상태를 표의 관련 영역 행에 포함해줘.

```text
기본
로딩
빈 상태
오류
완료
미확정 또는 보류
```

입력 설계에 존재하지 않는 상태를 실제 기능처럼 만들지 마. 범용 프롬프트에 언급됐더라도 해당 설계에 로그인·입력·검색·결제 등이 없다면 관련 상태를 추가하지 말고 `적용 대상 아님`으로 판정해줘.

## 7. 표 아래 필수 부록

스토리보드 표 아래에 다음 내용을 간결하게 작성해줘.

### 화면 이동 요약

| 출발 요소 | 사용자 행동 | 도착 화면 ID | 도착 화면명 | 조건 |
|---|---|---|---|---|

### 상태 및 오류 요약

| 상태 | 발생 조건 | 표시 내용 | 복구 행동 |
|---|---|---|---|

### 가정·보류·불일치

| 구분 | 내용 | 근거 파일 | 처리 |
|---|---|---|---|

위 부록은 메인페이지 한 화면을 설명하는 보조 표이며, 별도의 화면 스토리보드로 계산하지 않는다.

## 8. 작성 원칙

- 설계 파일에 있는 화면 ID, 화면명, 이동 관계를 그대로 사용해줘.
- 화면 영역은 실제 위→아래 순서로 작성해줘.
- 설계 파일에 없는 브랜드 카피, 제품 정보, 가격, 정책, 기능, 화면을 임의 생성하지 마.
- 확인되지 않은 내용은 `가정`, `not_verified`, `HOLD`, `검토 필요` 중 입력 문서의 상태를 유지해줘.
- 로그인·회원·입력 폼·검색·결제 같은 범용 기능을 근거 없이 추가하지 마.
- 문서 간 내용이 충돌하면 숨기지 말고 `가정·보류·불일치` 표에 기록해줘.
- 와이어프레임 HTML의 검토용 상태 버튼이나 개발 도구를 실제 사용자 UI로 오인하지 마.
- 공통 헤더·내비게이션·푸터는 메인페이지 표 안에 포함하되 다른 화면으로 중복 생성하지 마.
- 이미지 영역은 실제 자산이 없으면 대체 텍스트가 포함된 플레이스홀더로 기록해줘.
- 최종 디자인, 색상값, 픽셀 수치, 개발 기술은 입력에 확정된 경우에만 작성해줘.

## 9. 검증

저장 전에 각 결과를 다음 기준으로 검사해줘.

- `설계 출력물/` 아래의 세 설계 산출물 폴더를 하나의 입력으로 읽었는가?
- 메인페이지 판정 근거가 있는가?
- 화면 한 개당 스토리보드 표 한 개인가?
- 표의 영역 순서가 실제 화면 순서와 일치하는가?
- 화면 ID와 이름이 모든 입력 파일과 일치하는가?
- 주요 콘텐츠·기능·CTA·상태·예외가 누락되지 않았는가?
- 모든 이동 대상이 실제 존재하는 화면인가?
- 문서와 HTML의 불일치를 숨기지 않았는가?
- 반응형·접근성 요구사항이 포함됐는가?
- 근거 없는 로그인·입력·검색·판매 기능을 만들지 않았는가?
- `설계 출력물/` 밖의 다른 프로젝트 내용을 혼합하지 않았는가?
- Markdown 표가 깨지지 않는가?

핵심 조건이 하나라도 실패하면 정상 완료로 확정하지 말고, 결과 파일에 실패 원인과 필요한 입력을 기록해줘.

```md
- 처리한 설계 입력: `설계 출력물/`
- 생성한 스토리보드 수: ...
- 메인페이지 판정 실패: ...
- 가정·보류·불일치: ...
- 출력 위치: `스토리보드 결과/`
- 생성 파일과 용도:
  - `스토리보드 결과/메인페이지_스토리보드.md`: 메인페이지의 화면 영역별 스토리보드
- 검증 결과: ...
```
