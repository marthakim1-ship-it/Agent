[0. 공통 필수 화면 및 상품 수량 계약]

모든 설계 결과에는 다음 3개 핵심 화면이 반드시 포함되어야 한다.

```text
MAIN-001      메인페이지(홈)
CATEGORY-001  카테고리 페이지
BRAND-001     브랜드 소개 페이지
```

- 세 화면은 사이트맵, 서비스 흐름도, 화면 설계서, 와이어프레임 HTML, 화면 목록 JSON에 동일한 이름과 ID로 반영해줘.
- 기존 `SCR-XXX` 체계를 함께 사용해야 한다면 세 핵심 화면과 SCR ID의 매핑을 화면 설계서와 JSON에 기록해줘.
- 세 화면을 하나로 합치거나 어느 하나를 생략하지 마.
- 메인페이지에서 카테고리 페이지와 브랜드 소개 페이지로 이동할 수 있어야 해.
- 카테고리 페이지에서 메인페이지와 상품 상세 후보로 이동할 수 있어야 해.
- 브랜드 소개 페이지에서 메인페이지와 제품 탐색 경로로 이동할 수 있어야 해.

메인페이지에는 독립적으로 식별 가능한 상품 카드 또는 상품 항목을 최소 15개 설계해줘.

```text
PRODUCT-001
PRODUCT-002
...
PRODUCT-015
```

상품 수량 계약:

- 상품 영역을 단순히 `상품 15개`라고 한 행이나 한 영역에만 적지 마.
- 최소 15개 상품 슬롯에 `PRODUCT-001`부터 고유 ID를 개별 부여해줘.
- 각 상품 슬롯에는 상품 ID, 상품명 상태, 이미지 상태와 대체 텍스트, 핵심 정보 상태, 주요 행동, 이동 대상, 검증 상태를 포함해줘.
- 실제 상품명·이미지·가격·용량·영양·효능·재고가 입력에서 확인되지 않으면 임의 생성하지 마.
- 미확정 상품 정보는 `NOT_VERIFIED` 자리표시자로 표시하고 실제 판매 상품처럼 단정하지 마.
- 실제 상품 15개를 확정할 수 없어도 상품 슬롯은 최소 15개 유지해줘.
- 모바일·태블릿·PC에서 PRODUCT ID와 DOM 읽기 순서를 동일하게 유지해줘.
- 상품 더보기나 슬라이더를 사용해도 설계 문서와 HTML DOM에는 최소 15개 상품 항목 전체가 존재해야 해.

[1. 사이트맵 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 입력 파일: [가상 클라이언트 분석 결과]
- 결과물 저장 폴더: [가상 클라이언트 설계 결과]

입력 파일의 브랜드 정보, 사용자 유형, 사용자 목표, 주요 기능, 콘텐츠와 분석 결과를 빠짐없이 읽고 사이트맵을 설계해줘. Figma를 생성하거나 수정하지 말고, CLI에서 바로 확인하고 다른 도구에서도 재사용할 수 있는 로컬 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `사이트맵.md`
   - 프로젝트 개요
   - 설계 근거와 핵심 사용자 목표
   - 전역 내비게이션 구조
   - 계층형 사이트맵
   - 페이지별 목적, 핵심 콘텐츠, 주요 기능, 연결 페이지를 정리한 표
   - Mermaid `flowchart` 문법으로 작성한 사이트맵
2. `사이트맵.mmd`
   - `사이트맵.md`에 사용한 Mermaid 코드만 포함
3. `사이트맵.svg`
   - 한글이 깨지지 않고 확대해도 읽을 수 있는 벡터 형식

작성 규칙:

- 페이지를 1차, 2차, 3차 깊이로 구분하고 상위·하위 관계를 명확히 표시해줘.
- `MAIN-001 메인페이지(홈)`, `CATEGORY-001 카테고리 페이지`, `BRAND-001 브랜드 소개 페이지`를 공통 필수 1차 화면으로 포함해줘.
- 메인페이지에는 브랜드·제품 가치, 주요 탐색 경로, 최소 15개 상품 슬롯을 정의해줘.
- 카테고리 페이지에는 카테고리 맥락, 상품 결과, 정렬·필터 후보, 빈 상태와 오류 복구를 정의해줘.
- 브랜드 소개 페이지에는 검증된 브랜드 정의, 가치와 근거 상태, 관련 제품 탐색 경로를 정의해줘.
- 세 핵심 화면이 시작점에서 모두 도달 가능하고 서로 필요한 왕복 이동을 제공하는지 검토해줘.
- 공통 영역, 회원 상태별 영역, 주요 사용자 여정, 예외 페이지를 구분해줘.
- 입력 파일에 없는 사실은 임의로 확정하지 말고 `가정`으로 표시해줘.
- 링크가 끊긴 페이지와 중복 페이지가 없도록 검토해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.

[2. 서비스 흐름도 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 사이트맵 입력 파일: [사이트맵 파일 경로]
- 추가 참고 파일: [분석 결과 또는 요구사항 파일 경로]
- 결과물 저장 폴더: [결과물 폴더 경로]

입력 파일을 모두 읽고 사이트 구조와 핵심 사용자 목표를 기반으로 서비스 흐름도를 설계해줘. Figma를 생성하거나 수정하지 말고, CLI에서 바로 확인하고 다른 도구에서도 재사용할 수 있는 로컬 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `서비스_흐름도.md`
   - 서비스 흐름 개요
   - 사용자 유형과 시작 조건
   - 핵심 정상 흐름
   - 분기, 오류, 이탈, 재진입 흐름
   - 단계별 사용자 행동, 시스템 처리, 화면, 다음 조건을 정리한 표
   - Mermaid `flowchart` 문법으로 작성한 전체 서비스 흐름도
2. `서비스_흐름도.mmd`
   - `서비스_흐름도.md`에 사용한 Mermaid 코드만 포함
3. `서비스_흐름도.svg`
   - 시작·종료, 사용자 행동, 시스템 처리, 판단 분기를 서로 다른 도형으로 구분한 벡터 형식

작성 규칙:

- 시작점과 종료점을 명확히 표시해줘.
- 주요 흐름은 `탐색 → 선택 → 상세 확인 → 핵심 행동 → 결과 확인`처럼 순서가 보이게 구성해줘.
- 필수 상품 흐름 `MAIN-001 → CATEGORY-001 → 상품 선택 → 상품 상세 후보 → 결과 확인 또는 이전 단계 복귀`를 포함해줘.
- 필수 브랜드 흐름 `MAIN-001 → BRAND-001 → 관련 제품 탐색 → CATEGORY-001 또는 MAIN-001`을 포함해줘.
- `PRODUCT-001`부터 최소 `PRODUCT-015`까지 각 상품에 유효한 다음 행동 또는 조건부 이동이 있는지 검토해줘.
- 상품 상세 화면이나 실제 상품 정보가 미확정이면 이동을 `가정` 또는 `조건부`로 표시해줘.
- 로그인 여부, 입력값 오류, 결과 없음, 이전 단계 이동과 같은 필수 분기를 포함해줘.
- 모든 화면 이름은 사이트맵의 페이지 이름과 일치시켜줘.
- 연결이 끊긴 단계나 도달할 수 없는 화면이 없는지 검토해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.

[3. 화면 설계서 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 사이트맵 입력 파일: [사이트맵 파일 경로]
- 서비스 흐름도 입력 파일: [서비스 흐름도 파일 경로]
- 추가 참고 파일: [분석 결과 또는 요구사항 파일 경로]
- 결과물 저장 폴더: [결과물 폴더 경로]

입력 파일을 모두 읽고 사이트맵과 서비스 흐름도에 등장하는 화면 전체를 대상으로 화면 설계서를 제작해줘. Figma를 생성하거나 수정하지 말고, 문서와 브라우저에서 확인 가능한 저충실도 와이어프레임 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `화면_설계서.md`
   - 프로젝트 및 설계 범위
   - 화면 ID 규칙과 전체 화면 목록
   - 화면별 목적, 진입 조건, 종료 조건
   - 화면 구성 영역과 UI 요소
   - 표시 데이터, 사용자 행동, 인터랙션, 이동 대상
   - 기본·로딩·빈 상태·오류·완료 상태
   - 유효성 검사와 오류 메시지
   - PC·태블릿·모바일 반응형 기준
   - 접근성 요구사항
   - 세 핵심 화면의 공통 ID와 기존 SCR ID를 함께 사용할 경우의 매핑
   - 메인페이지 최소 15개 상품 슬롯과 PRODUCT ID 목록
2. `와이어프레임.html`
   - 외부 라이브러리 없이 브라우저에서 단독 실행 가능한 HTML/CSS/JavaScript 파일
   - 화면별 저충실도 와이어프레임과 화면 ID·이름 표시
   - 상단 목차 또는 사이드바에서 각 화면으로 이동 가능
   - 버튼과 링크를 누르면 서비스 흐름에 맞는 화면으로 이동
   - 모바일, 태블릿, 데스크톱 레이아웃을 확인할 수 있는 반응형 구성
   - `MAIN-001`, `CATEGORY-001`, `BRAND-001` 화면 전체
   - 메인페이지의 `PRODUCT-001`부터 최소 `PRODUCT-015`까지 실제 DOM 상품 요소
3. `화면_목록.json`
   - 각 화면의 `id`, `name`, `purpose`, `entryConditions`, `sections`, `actions`, `states`, `nextScreens`를 포함한 유효한 JSON
   - 메인페이지 객체에는 최소 15개 항목의 `products` 배열 추가

메인페이지 `products` 배열의 각 항목은 다음 필드를 모두 포함해줘.

```json
{
  "id": "PRODUCT-001",
  "name": "NOT_VERIFIED",
  "image": "NOT_VERIFIED",
  "alt": "상품 이미지 미확정",
  "coreInfo": "NOT_VERIFIED",
  "primaryAction": "상품 상세 확인",
  "target": "조건부 상품 상세 화면",
  "status": "NOT_VERIFIED"
}
```

- `products` 배열은 `MAIN-001` 메인페이지 객체에 필수로 적용해줘.
- `products` 배열에는 최소 15개의 고유 PRODUCT ID가 있어야 해.
- 상품 상세 대상이 확정되지 않았으면 `target`에 조건부임을 표시하고 존재하지 않는 확정 화면 ID를 만들지 마.

작성 규칙:

- 사이트맵과 서비스 흐름도에 정의된 화면 이름과 이동 관계를 그대로 사용해줘.
- 세 핵심 화면은 `MAIN-001`, `CATEGORY-001`, `BRAND-001` ID를 우선 사용해줘.
- 메인페이지에는 공통 헤더, 브랜드·제품 가치, 카테고리 진입, 최소 15개 상품 슬롯, 브랜드 소개 진입, 상태·주의·검증 정보, 공통 푸터를 설계해줘.
- 카테고리 페이지에는 현재 위치, 정렬·필터 후보, 상품 결과, 로딩·빈 상태·오류 복구, 메인 복귀, 상품 상세 후보 이동을 설계해줘.
- 브랜드 소개 페이지에는 검증된 YOVIA 브랜드 정의, 그릭요거트 기반 간편 건강식의 범위, 브랜드 가치·근거 상태, 이미지 자산 상태, 관련 제품 탐색 이동을 설계해줘.
- 브랜드 소개에 입력에서 확인되지 않은 연혁·인증·수상·효능·환경 주장을 만들지 마.
- 화면마다 고유한 화면 ID를 부여하고 세 결과물에서 동일하게 유지해줘.
- 공통 헤더, 푸터, 내비게이션과 반복 컴포넌트는 일관되게 적용해줘.
- 이미지 영역은 대체 텍스트가 있는 플레이스홀더로 표현해줘.
- 입력 파일에 없는 상세 정책은 `가정`으로 표시하고 설계서에 따로 모아줘.
- HTML의 모든 내부 이동, 주요 버튼, 반응형 레이아웃과 JSON 문법을 검사해줘.
- 상품 카드는 키보드로 탐색 가능해야 하고 상품 ID와 검증 상태를 화면에 표시해줘.
- 모바일은 1~2열, 태블릿은 2~3열, PC는 3~5열을 사용할 수 있으나 PRODUCT ID와 DOM 순서는 유지해줘.
- `MAIN-001`, `CATEGORY-001`, `BRAND-001`이 MD·JSON·HTML에 모두 존재하고 이름과 ID가 일치하는지 검사해줘.
- 세 핵심 화면 사이에 끊긴 링크가 없는지 검사해줘.
- 메인페이지 상품 슬롯이 15개 이상이고 PRODUCT ID가 고유한지 검사해줘.
- JSON과 HTML의 PRODUCT ID 및 상품 수가 일치하는지 검사해줘.
- 상품별 대체 텍스트, 주요 행동, 이동 대상, 검증 상태가 존재하는지 검사해줘.
- 실제 근거가 없는 상품명·가격·용량·영양·효능·재고를 생성하지 않았는지 검사해줘.
- 작업 완료 후 생성한 파일의 상대 경로, 실행 방법과 함께 다음 검증 결과를 짧게 출력해줘.

```text
공통 필수 화면: 3/3
메인페이지 상품 슬롯: ...개
PRODUCT ID 고유성: 통과/실패
JSON·HTML 상품 수 일치: 통과/실패
미확정 상품 정보 처리: NOT_VERIFIED
세 핵심 화면 내부 이동: 통과/실패
```
