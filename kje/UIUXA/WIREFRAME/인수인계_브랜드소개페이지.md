# YOVIA 브랜드소개페이지 작업 인수인계

## 1. 인수인계 목적

현재 완료된 VC-001 메인페이지 설계와 스토리보드를 유지하면서, 다음 작업자가 별도 화면인 `P-005 브랜드 소개`를 설계하고 브랜드소개페이지 스토리보드까지 이어서 제작할 수 있도록 현재 상태와 작업 순서를 정리한다.

## 2. 핵심 결정

- 메인페이지와 브랜드소개페이지는 목적이 다른 별도 화면이다.
- 기존 `P-001 홈`을 브랜드소개페이지로 대체하지 않는다.
- 브랜드소개페이지는 기존 VC-001 설계에 `P-005 브랜드 소개`로 추가한다.
- 브랜드소개 스토리보드를 먼저 임의 생성하지 않는다.
- 사이트맵 → 서비스 흐름도 → 화면 설계서·JSON·HTML → SVG → 스토리보드 순서로 진행한다.
- 로그인·회원가입·검색·결제 등 입력 근거가 없는 범용 기능은 추가하지 않는다.
- 구매·구독·앱 CTA는 실제 화면과 정책이 설계되기 전까지 연결하지 않는다.

## 3. 현재 화면 구조

```text
P-001 홈
P-002 제품 상세
P-003 사용 안내
P-004 성분·영양
```

추가할 화면:

```text
P-005 브랜드 소개
```

권장 연결:

```text
P-001 홈 → P-005 브랜드 소개
P-005 브랜드 소개 → P-001 홈
P-005 브랜드 소개 → P-002 제품 상세
P-005 브랜드 소개 → P-003 사용 안내
```

## 4. 현재 핵심 파일

### VC-001 설계 원본

```text
가상 클라이언트 설계 결과/001_서하린/
├─ 사이트맵.md
├─ 사이트맵.mmd
├─ 사이트맵.svg
├─ 서비스_흐름도.md
├─ 서비스_흐름도.mmd
├─ 서비스_흐름도.svg
├─ 화면_설계서.md
├─ 화면_목록.json
└─ 와이어프레임.html
```

### 현재 스토리보드 입력 묶음

```text
설계 출력물/
├─ 사이트 구조맵/
├─ 서비스 흐름도/
└─ 화면 설계서/
```

이 세 폴더는 서로 다른 프로젝트가 아니라 하나의 설계 입력 묶음이다.

### 브랜드 정보

```text
프롬프트/YOVIA_브랜드소개페이지_제작에_필요한_브랜드_정보.txt
```

### 실행 프롬프트

```text
프롬프트/메인페이지 스토리보드 생성 프롬프트.txt
프롬프트/브랜드소개페이지 스토리보드 생성 프롬프트.txt
설계 프롬프트/Antigravity 프롬프트.txt
```

### 완료된 메인페이지 결과

```text
스토리보드 결과/메인페이지_스토리보드.md
스토리보드 결과/메인페이지_스토리보드.html
```

정적 HTML은 JavaScript 없이 회색 박스와 텍스트만 사용한다.

## 5. 브랜드 정보 상태

### 사용 가능한 정보

- 공식 브랜드명: yovia(요비아)
- 그릭요거트 기반 올인원 데스크 푸드라는 브랜드 정의
- 바쁜 20~30대 직장인·대학생·취준생이라는 핵심 고객
- 브랜드 탄생 배경과 해결하려는 문제
- 미션 후보
- 핵심 가치: Convenience, Healthy Choice, All-in-One, Everyday Efficiency
- 제품·패키지 차별화 방향
- 브랜드소개페이지 목표와 CTA 후보

### 확정 전 검증이 필요한 정보

- 브랜드명 공식 의미
- 최종 공식 슬로건
- 공식 미션·비전 문장
- 핵심 가치 공식 명칭
- Dual-Chamber·Easy-Peel·Gas Flushing·PLA·빌트인 스푼의 실제 적용
- 락토프리·무가당·저당·고단백 관련 표시 근거
- 원료·영양·알레르기·가격·출시일
- 공식 로고·컬러·서체·사진·BI 사용 규칙
- D2C 앱·정기 구독·구매 화면과 정책
- `TASTE GARDEN`과 `YOVIA`의 공식 관계

검증 전 항목은 `가정`, `기획서 기반 정리`, `추가 필요`, `HOLD` 상태를 유지한다.

## 6. P-005 권장 화면 영역

아래 영역은 브랜드 정보와 기존 설계를 검토해 확정한다. 입력 근거가 부족한 영역은 임의 생성하지 않는다.

```text
P-005-01 공통 헤더
P-005-02 브랜드 히어로
P-005-03 한 문장 브랜드 정의
P-005-04 브랜드 탄생 배경
P-005-05 미션
P-005-06 핵심 가치
P-005-07 차별화 방향
P-005-08 근거·검증 상태
P-005-09 제품 상세·사용 안내 연결
P-005-10 공통 푸터
```

성과·연혁·수상·인증·창업자 영역은 확인된 자료가 없어 현재 생성하지 않는다.

## 7. 다음 작업 순서

### 1단계 — 사이트맵 업데이트

- `P-005 브랜드 소개` 추가
- 깊이와 상위 화면 정의
- P-001·P-002·P-003 연결 정의
- 페이지 목적·콘텐츠·기능 표 추가
- Mermaid MD·MMD 일치
- 사이트맵 SVG 재생성

### 2단계 — 서비스 흐름도 업데이트

권장 흐름:

```text
P-001 홈
→ P-005 브랜드 소개
→ 브랜드 정의 확인
→ 탄생 배경·미션·핵심 가치 확인
→ 차별화 방향·검증 상태 확인
→ P-002 제품 상세 또는 P-003 사용 안내
```

- 직접 진입·홈 복귀 정의
- 로딩·빈·오류·완료 상태 정의
- Mermaid MD·MMD 일치
- 서비스 흐름도 SVG 재생성

### 3단계 — 화면 설계서 업데이트

- 전체 화면 목록에 P-005 추가
- 목적·진입·종료 조건 정의
- 화면 영역·표시 데이터·UI 요소 정의
- 사용자 행동·인터랙션·이동 대상 정의
- 기본·로딩·빈·오류·완료 상태 정의
- 반응형·접근성 기준 정의
- 브랜드 정보의 가정·보류 상태 기록

### 4단계 — JSON 업데이트

필수 필드:

```text

```

### 5단계 — HTML 업데이트

- 공통 내비게이션에 브랜드 소개 추가
- P-005 정적·상태별 와이어프레임 추가
- 문서에 정의한 행동과 HTML 기능 일치
- 화면 전환 후 제목 포커스 이동
- 이미지 플레이스홀더에 대체 설명 제공
- 검토용 상태 도구를 실제 사용자 UI와 분리

### 6단계 — 설계 정합성 검증

- P-001~P-005 ID·화면명 일치
- 깨진 이동 대상 0건
- MD·MMD 코드 일치
- JSON 문법 정상
- HTML 내부 이동 정상
- 근거 없는 구매·구독·건강 효능 없음
- SVG 한글 표시 정상

### 7단계 — 설계 출력물 반영

검증된 최신 9개 파일을 다음 폴더 구조에 반영한다.

```text
설계 출력물/사이트 구조맵/
설계 출력물/서비스 흐름도/

```

```text

```

예상 결과:

```text
스토리보드 결과/브랜드소개페이지_스토리보드.md
```

## 8. 금지 사항

- P-001 홈을 P-005 브랜드 소개로 이름만 변경
- 브랜드소개 화면 없이 스토리보드부터 생성
- 근거 없는 미션·비전·연혁·창업자·성과 생성
- 기술 제안과 실제 양산·시험 완료 사실 혼동
- 미확정 건강·영양·친환경 주장을 확정 표현으로 사용
- 설계되지 않은 구매·구독·앱 화면으로 CTA 연결
- 다른 가상 클라이언트 결과 혼합
- 문서·JSON·HTML에서 서로 다른 화면 ID 사용

## 9. 완료 조건

- P-005가 9개 설계 산출물에 일관되게 반영됨
- 브랜드 정보의 확정·가정·보류 상태가 유지됨
- P-005의 진입·종료·관련 화면 이동이 연결됨
- 상태·반응형·접근성 요구가 정의됨
- 설계 출력물에 최신본이 반영됨
- 브랜드소개페이지 스토리보드가 화면 한 개당 본표 한 개로 생성됨
