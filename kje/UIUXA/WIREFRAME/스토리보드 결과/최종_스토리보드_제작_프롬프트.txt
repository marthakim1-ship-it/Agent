[YOVIA 3개 핵심 화면 스토리보드 제작 — 최종 실행 프롬프트]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

## 1. 작업 목적

`설계 출력물` 폴더 안의 사이트 구조맵, 서비스 흐름도, 화면 설계서를 모두 읽고 서로 대조하여 YOVIA 핵심 화면 총 3장의 통합 스토리보드를 제작해줘.

필수 화면 구성은 다음과 같다.

```text
1. 메인페이지 1장
2. 카테고리 페이지 1장
3. 브랜드 소개 페이지 1장
총 화면 수: 정확히 3장
```

메인페이지에는 상품을 최소 15개 포함해줘. 각 상품은 사용자가 개별 상품으로 식별할 수 있는 독립 상품 카드 또는 동일 수준의 반복 영역으로 표현하고, 상품명·이미지·가격·효능 등 실제 정보가 입력에서 확정되지 않은 경우 임의 생성하지 말고 자리표시자와 `NOT_VERIFIED` 상태를 사용해줘.

가상 클라이언트 결과를 단순히 이어 붙이지 말고, 각 결과에서 메인·홈, 제품·카테고리, 브랜드 소개에 필요한 근거를 각각 추출한 뒤 중복을 통합하고 충돌과 미확정 사항을 분리해 3개의 독립 화면으로 정리해줘.

Figma를 생성하거나 수정하지 말고, CLI와 일반 Markdown 도구에서 바로 확인할 수 있는 UTF-8 로컬 문서로 만들어줘.

## 2. 입력 폴더와 필수 입력 파일

입력 루트:

```text
설계 출력물/
```

아래 세 입력군의 실제 하위 폴더와 파일을 재귀적으로 탐색해 모두 읽어줘.

```text
설계 출력물/사이트 구조맵/{3자리 순번}_{이름}/사이트맵.md
설계 출력물/서비스 흐름도/{3자리 순번}_{이름}/서비스_흐름도.md
설계 출력물/화면 설계서/{3자리 순번}_{이름}/화면_설계서.md
```

특정 Client 범위를 고정하지 말고 실제 존재하는 정상 설계 출력물을 기준으로 처리해줘. 누락되거나 읽을 수 없는 파일은 임의 보완하지 말고 입력 검증 결과에 기록해줘.

보조 교차 검증 파일:

```text
설계 출력물/사이트 구조맵/{3자리 순번}_{이름}/사이트맵.mmd
설계 출력물/사이트 구조맵/{3자리 순번}_{이름}/사이트맵.svg
설계 출력물/서비스 흐름도/{3자리 순번}_{이름}/서비스_흐름도.mmd
설계 출력물/서비스 흐름도/{3자리 순번}_{이름}/서비스_흐름도.svg
```

`.mmd`와 `.svg`는 화면 연결 및 구조를 확인할 때 사용하고, Markdown 문서와 충돌하면 충돌 내용을 기록해줘.

## 3. 입력 해석과 우선순위

클라이언트별 입력을 먼저 독립적으로 읽은 다음 통합해줘. 다른 클라이언트의 결과를 특정 클라이언트의 사실처럼 복사하지 마.

같은 클라이언트의 입력이 충돌하면 다음 우선순위를 적용해줘.

1. `화면_설계서.md`의 화면 목적, 영역, 상태, 접근성 정의
2. `서비스_흐름도.md`의 사용자 행동, 분기, 오류, 재진입 정의
3. `사이트맵.md`의 페이지 목적, 계층, 연결 관계
4. `.mmd`와 `.svg`의 시각적 연결 정보

클라이언트 간 결과가 다르면 다음 기준으로 처리해줘.

- 반복 확인된 공통 요구: 메인페이지 공통 영역으로 통합
- 서로 다른 사용자 목표: 한 영역 안의 탭처럼 섞지 말고 목적별 독립 섹션 후보로 구분
- 사실 또는 정책 충돌: 확정하지 말고 `충돌/추가 검증 필요`로 기록
- 가정·NOT_VERIFIED·HOLD: 확정 영역이나 활성 CTA로 승격 금지
- 서로 다른 화면 ID: 원본 ID를 근거 열에 남기되 최종 스토리보드 ID와 혼용하지 않음

## 4. 대상 출력 화면

이번 작업 대상은 정확히 3개 화면이다.

```text
최종 화면 ID: MAIN-001
최종 화면명: 메인페이지(홈)

최종 화면 ID: CATEGORY-001
최종 화면명: 카테고리 페이지

최종 화면 ID: BRAND-001
최종 화면명: 브랜드 소개 페이지

총 화면 수: 3개
```

화면을 추가하거나 세 화면을 하나로 합치지 마. 입력 설계에 세부 화면이 더 있더라도 이번 스토리보드에서는 세 화면의 영역·인터랙션·이동 대상으로 연결하고 별도 스토리보드 장으로 늘리지 마.

원본 설계서에서 홈 화면 ID가 `P00`, `SCR-001` 등으로 다르면 해당 ID를 변경하거나 통일된 사실로 간주하지 말고, 각 스토리보드 행의 `원본 근거`에 출처 폴더와 원본 화면 ID·이름을 기록해줘.

## 5. 결과물 저장

결과물 저장 폴더:

```text
스토리보드 결과/
```

다음 파일을 UTF-8로 생성해줘.

```text
스토리보드 결과/최종_스토리보드.md
```

기존 파일이 있으면 덮어쓰기 전에 다음 위치에 보관해줘.

```text
스토리보드 결과/archive/YYYYMMDD_HHMMSS__최종_스토리보드.md
```

기존 CSS·HTML·제외항목 파일은 이번 요청에서 수정하거나 삭제하지 마.

## 6. 결과 문서 고정 구조

아래 순서와 제목을 유지해줘.

```md
# YOVIA 핵심 화면 스토리보드 — 총 3장

## 1. 문서 정보와 입력 검증
## 2. 통합 설계 근거와 핵심 사용자 목표
## 3. 메인페이지 스토리보드 — MAIN-001
## 4. 카테고리 페이지 스토리보드 — CATEGORY-001
## 5. 브랜드 소개 페이지 스토리보드 — BRAND-001
## 6. 상태별 스토리보드
## 7. 화면 이동 및 인터랙션
## 8. 반응형 설계 기준
## 9. 접근성 및 콘텐츠 기준
## 10. 가정·조건부·미확정·충돌 항목
## 11. 최종 검증 결과
```

## 7. 화면당 표 작성 규칙

3개 화면별로 각각 하나의 통합 표를 작성해줘. 각 화면을 여러 스토리보드 장으로 임의 분할하지 마.

`## 3. 메인페이지 스토리보드`, `## 4. 카테고리 페이지 스토리보드`, `## 5. 브랜드 소개 페이지 스토리보드`에는 모두 다음 열을 사용해줘.

| No. | 화면 ID | 화면명 | 영역 ID | 화면 영역 | 목적 | 표시 콘텐츠·데이터 | UI 요소 | 사용자 행동 | 인터랙션·시스템 처리 | 이동 대상 | 상태·조건 | 반응형 처리 | 접근성·대체 텍스트 | 원본 근거 |
|---:|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

작성 규칙:

- 메인페이지의 화면 ID·화면명은 `MAIN-001`·`메인페이지(홈)`, 영역 ID는 `MAIN-001-A01` 형식으로 유지해줘.
- 카테고리 페이지의 화면 ID·화면명은 `CATEGORY-001`·`카테고리 페이지`, 영역 ID는 `CATEGORY-001-A01` 형식으로 유지해줘.
- 브랜드 소개 페이지의 화면 ID·화면명은 `BRAND-001`·`브랜드 소개 페이지`, 영역 ID는 `BRAND-001-A01` 형식으로 유지해줘.
- 한 행은 하나의 명확한 화면 영역 또는 사용자 과업만 설명해줘.
- 같은 영역을 클라이언트별로 중복 작성하지 말고 근거 열에 복수 출처를 병기해줘.
- 원본 근거는 `{순번_이름}/{문서명}/{원본 화면 ID 또는 관련 절}` 형식으로 기록해줘.
- 이동 대상은 입력에 실제 존재하는 화면 이름과 원본 화면 ID를 함께 적어줘.
- 클라이언트마다 이동 대상 ID가 다르면 대표 ID를 임의 지정하지 말고 클라이언트별 매핑을 기록해줘.
- 화면에 없는 제품 사양, 가격, 성능, 효능, 정책, 통계, CTA를 만들지 마.
- 실제 카피 미확정 시 `[카피 작성 필요]`, 실제 이미지 미확정 시 `[이미지 자산 필요: 대체 텍스트]`로 표시해줘.

### 메인페이지 상품 최소 수량 계약

- 메인페이지에 독립적으로 식별 가능한 상품 카드 또는 상품 항목을 최소 15개 배치해줘.
- 상품 영역을 단순히 `상품 15개`라고 한 행에만 적지 말고 `PRODUCT-001`부터 최소 `PRODUCT-015`까지 개별 상품 ID를 부여해줘.
- 각 상품 항목에는 상품 ID, 상품명 상태, 이미지 상태와 대체 텍스트, 핵심 정보 상태, 주요 행동, 이동 대상, 검증 상태를 기록해줘.
- 입력에서 실제 상품명이 확인되지 않으면 `상품명 NOT_VERIFIED 01`처럼 임시 상태임을 명확히 표시하고 실제 제품명처럼 단정하지 마.
- 입력 근거상 15개 실제 상품을 확정할 수 없더라도 카드 슬롯은 최소 15개 유지하되, 미확정 슬롯은 `NOT_VERIFIED`로 표시해줘.
- 모바일·태블릿·데스크톱에서 15개 상품의 DOM 순서와 상품 ID가 달라지지 않아야 해.
- 상품 더보기·슬라이더를 사용하더라도 최초 스토리보드에 15개 상품 항목 전체가 명세되어야 해.

### 카테고리 페이지 필수 계약

- 카테고리명, 현재 위치, 정렬·필터 후보, 상품 결과 영역, 결과 없음, 오류와 복구, 메인 및 상품 상세 이동을 검토해줘.
- 근거 없는 카테고리 체계·필터·상품 수를 확정하지 말고 `가정` 또는 `NOT_VERIFIED`로 표시해줘.

### 브랜드 소개 페이지 필수 계약

- YOVIA 브랜드 정의, 그릭요거트 기반 간편 건강식이라는 검증된 범위, 브랜드 가치·근거, 이미지 자산 상태, 관련 제품 탐색 이동을 검토해줘.
- 연혁·인증·수상·효능·환경 주장 등 입력에서 확인되지 않은 브랜드 서사를 임의 생성하지 마.

## 8. 메인페이지 필수 검토 영역

입력 근거를 확인하고 중복을 통합하되 다음 후보를 빠짐없이 검토해줘. 근거가 없는 항목은 억지로 본문 영역에 넣지 말고 가정·미확정 표로 이동해줘.

1. 본문 바로가기와 공통 헤더
2. 실제 제품 중심 히어로와 브랜드·제품 가치 제안
3. 핵심 제품 또는 제품군 탐색 진입
4. 제품 구조·사용 방법 요약
5. 맛·식감·토핑 및 제품 비교 진입
6. 용량·구성·가격의 가치 비교 진입
7. 원료·알레르기·주의 정보 요약
8. 사용 후 정리·폐기·소재·환경 근거 진입
9. 검증 상태·자산 상태·근거 안내
10. 조건부 다음 행동 또는 CTA
11. 공통 푸터와 정책·접근성·오류 복구

각 영역의 실제 채택 여부는 반드시 입력 근거로 결정해줘. 한 화면에 과도하게 많은 내용을 배치하지 말고 다음 우선순위를 사용해줘.

```text
사용자 목표와 실제 제품 이해
→ 중요한 안전·주의·검증 정보
→ 핵심 탐색과 비교
→ 사용·정리·폐기
→ 조건부 행동
```

## 9. 상태별 스토리보드

`## 6. 상태별 스토리보드`에는 아래 표를 사용하고 적용 화면 ID를 함께 표시해줘.

| 상태 | 적용 영역 | 표시 내용 | 사용자 행동 | 시스템 처리 | 다음 화면·복구 경로 | 근거 |
|---|---|---|---|---|---|---|

최소 포함 상태:

- 기본
- 로딩
- 빈 상태 또는 자료 없음
- 입력 오류
- 시스템 오류
- 완료 또는 핵심 정보 확인 완료
- `CONFIRMED`
- `CONCEPT`
- `NOT_VERIFIED`
- `HOLD`
- 조건부 CTA 비활성

오류와 미확정을 구분해줘.

- 오류: 원래 제공되어야 할 데이터를 불러오지 못한 상태
- 미확정: 데이터·근거·정책 자체가 아직 확정되지 않은 상태

## 10. 화면 이동과 인터랙션

`## 7. 화면 이동 및 인터랙션`에 다음 열의 표를 작성해줘.

| 출발 영역 ID | 트리거 | 조건 | 시스템 처리 | 이동 대상 원본 화면 | 실패·예외 | 복구 경로 |
|---|---|---|---|---|---|---|

다음을 확인해줘.

- 메인페이지에서 핵심 제품·상세·사용·검증 화면으로 이동 가능한가?
- 로그인 여부, 입력 오류, 결과 없음, 이전 단계 이동이 필요한 지점에만 포함되었는가?
- 미확정·HOLD 항목이 활성 CTA로 연결되지 않는가?
- 오류 후 홈 또는 이전 유효 화면으로 복귀 가능한가?
- 존재하지 않는 화면 ID나 끊긴 링크가 없는가?
- MAIN-001, CATEGORY-001, BRAND-001 사이의 왕복 이동이 가능한가?
- 메인페이지의 PRODUCT-001~PRODUCT-015 이상이 상품 상세 또는 조건부 행동과 일관되게 연결되는가?

## 11. 반응형 기준

- 모바일 `<768px`: 단일 열, 핵심 정보→상태·주의→탐색→행동 순서 유지
- 태블릿 `768~1199px`: 2열 사용 가능, DOM과 읽기 순서는 모바일과 동일
- 데스크톱 `≥1200px`: 최대 콘텐츠 폭 1280px, 2~3열 확장 가능
- 텍스트 200% 확대와 320px CSS 폭에서도 정보·기능 손실 없음
- 터치 대상 최소 44×44px
- 중요한 주의와 오류를 아코디언 내부에만 숨기지 않음
- 브레이크포인트는 입력에서 확정되지 않은 경우 `가정`으로 표시

## 12. 접근성 및 콘텐츠 기준

- `header`, `nav`, `main`, `section`, `footer` 랜드마크와 논리적 제목 계층을 명시해줘.
- 첫 포커스 요소로 본문 바로가기를 제공해줘.
- 모든 정보 이미지에 목적 중심 대체 텍스트를 작성하고 장식 이미지는 빈 대체 텍스트로 구분해줘.
- 상태·경고·제품군을 색상만으로 전달하지 말고 텍스트와 아이콘을 병기해줘.
- 모든 링크·버튼·필터·갤러리는 키보드로 사용할 수 있어야 해.
- 포커스 순서는 화면 의미 순서와 일치해야 해.
- 로딩·오류·완료 상태는 적절한 라이브 영역으로 전달해줘.
- WCAG 준수 또는 인증은 감사 근거가 없으면 `NOT_VERIFIED`로 표시해줘.

## 13. 가정·조건부·미확정·충돌 관리

`## 10. 가정·조건부·미확정·충돌 항목`에 아래 표를 작성해줘.

| 항목 | 구분 | 관련 클라이언트 | 현재 근거 | 메인페이지 처리 | 확정에 필요한 자료 |
|---|---|---|---|---|---|

다음을 반드시 검토해줘.

- 로그인·검색·저장·회원 기능
- 실제 제품명·라인업·이미지·맛·용량·구성·가격
- 할인·배송·번들·구독·판매 채널
- 원료·첨가물·알레르기·교차접촉·가족 및 어린이 적합성
- 소재·재활용·분리배출 지역·환경 효과
- 효능·감미료·친환경·생분해·폐기 감소 주장
- 접근성 감사·준수·인증
- CTA 목적·도착 채널·로그인 필요 여부

구분 값은 `가정`, `조건부`, `NOT_VERIFIED`, `HOLD`, `충돌`, `추가 검증 필요` 중에서 사용해줘.

## 14. 최종 검증

`## 11. 최종 검증 결과`에 다음을 기록해줘.

- 발견한 입력 폴더와 정상 파일 수
- 누락·손상 입력 파일
- 메인·홈 화면 원본 ID 매핑 결과
- 최종 스토리보드 화면 수가 정확히 3장인지 여부
- 화면별 스토리보드 영역 수
- 메인페이지 상품 항목 수와 PRODUCT ID 고유성 검사 결과
- 메인페이지 상품 수가 최소 15개인지 여부
- 중복 영역 통합 결과
- 내부 이동 대상과 끊긴 링크 검사 결과
- 가정·조건부·미확정·충돌 표시 결과
- 반응형 및 접근성 반영 결과
- 입력에 없는 사실을 확정하지 않았는지 여부
- 최종 판정: `완료`, `조건부 완료`, `수정 필요`

핵심 근거가 부족하면 임의로 채우지 말고 `조건부 완료`로 판정해줘.
