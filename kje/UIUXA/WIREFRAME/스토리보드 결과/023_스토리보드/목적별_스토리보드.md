# VC-023 차유나 — 구매 목적별 스토리보드 대안

## 1. 문서 목적

VC-023의 공통 관심사인 **냉장 유통·보관 정보**를 유지하면서 방문자가 누구를 위해 구매하는지에 따라 서로 다른 설계안을 만든다.

```text
설계안 A: 개인용
설계안 B: 선물용
설계안 C: 단체용
```

세 안은 같은 화면의 문구만 바꾼 것이 아니다. 시작 질문, 정보 우선순위, 상품 탐색 기준, 핵심 과업, 완료 조건이 서로 다르다.

## 2. 공통 사실과 제한

- YOVIA는 그릭요거트 기반 간편 건강식 브랜드다.
- 냉장·개봉·이동 상태를 사용자의 행동 지침으로 연결한다.
- 이동 편의성과 냉장 안전성을 같은 주장으로 취급하지 않는다.
- 실제 보관 온도·시간·유통기한·배송 조건은 `NOT_VERIFIED`다.
- 근거 없는 상온 보관·신선도·유통기한 주장은 `HOLD`다.
- 상품 15개는 실제 라인업이 아닌 `PRODUCT-001~015` 설계 슬롯이다.

## 3. 목적별 판단 차이

| 구분 | A안 개인용 | B안 선물용 | C안 단체용 |
|---|---|---|---|
| 구매 주체 | 본인 | 선물을 보내는 사람 | 회사·학교·행사 담당자 |
| 실제 이용자 | 본인 | 수령인 | 여러 구성원 |
| 접속 이유 | 내 생활에서 보관·섭취 가능한지 판단 | 수령인이 안전하게 받고 보관할 수 있는지 판단 | 여러 명에게 안전하게 수령·보관·배포 가능한지 판단 |
| 첫 질문 | “지금 어디에 보관하고 언제 먹을까?” | “언제 전달되고 받는 사람이 바로 냉장할 수 있을까?” | “몇 명에게 어떤 환경에서 배포할까?” |
| 중요 정보 | 개봉 전후, 휴대, 이상 상태 | 배송일, 수령 안내, 선물 포장, 알레르기 | 수량, 납기, 냉장 공간, 배포 시간, 담당 책임 |
| 탐색 기준 | 사용 상황·섭취 시점 | 수령 상황·선물 대상 | 인원·행사 유형·운영 조건 |
| 완료 조건 | 나에게 맞는 보관·섭취 방법 확인 | 수령인이 안전하게 받을 수 있는지 확인 | 도입 가능 여부와 추가 자료 목록 확인 |

## 4. 설계안 A — 개인용 보관·섭취 판단

### A-1. 접속 시나리오

사용자는 자신이 먹을 제품을 구매하기 전 또는 배송받은 직후 접속한다. 냉장고에 바로 넣어야 하는지, 개봉 후 어떻게 보관해야 하는지, 이동 후 먹어도 되는지를 확인하려 한다.

### A-2. 사용자 흐름

```text
A-MAIN 개인용 시작
→ A-CONTEXT 사용 상황 선택
→ A-PRODUCT 상품 후보 15개
→ A-STORAGE 보관 조건 확인
→ A-CHECK 이상 상태 확인
→ A-RESULT 섭취·보관·문의 행동 결정
```

### A-3. 화면 스토리보드

| No. | 화면 ID | 화면명 | 목적 | 핵심 콘텐츠 | 사용자 행동 | 다음 화면 | 완료 조건 | 근거 |
|---:|---|---|---|---|---|---|---|---|
| 1 | A-MAIN-001 | 개인용 보관 시작 | 사용자의 현재 상황을 빠르게 선택 | 구매 전, 배송 직후, 개봉 후, 이동 후 | 상황 선택 | A-CONTEXT-001 | 자신의 현재 상태 선택 | VC023-REQ-001·004 |
| 2 | A-CONTEXT-001 | 사용 상황 선택 | 필요한 보관 정보 범위 축소 | 장소, 개봉 여부, 섭취 예정 시점 | 조건 확인 | A-PRODUCT-001 | 확인할 조건 정의 | VC023-REQ-001·002 |
| 3 | A-PRODUCT-001 | 개인용 상품 탐색 | 보관 부담을 기준으로 후보 탐색 | PRODUCT-001~015 CSS 슬라이드, 보관 정보 상태 | 상품 슬롯 선택 | A-STORAGE-001 | 후보 제품 식별 | VC023-REQ-002·006 |
| 4 | A-STORAGE-001 | 보관 조건 | 개봉 전후 조건과 행동 확인 | 온도·시간·단위·기준일 `NOT_VERIFIED` | 조건 읽기 | A-CHECK-001 | 정상 보관 행동 이해 | VC023-REQ-001·004 |
| 5 | A-CHECK-001 | 이상 상태 확인 | 정상·주의·문의 조건 판단 | 포장 상태, 냄새·외관 확인 항목 `[승인 자료 필요]` | 상태 선택 | A-RESULT-001 | 현재 상태 분류 | VC023-REQ-003 |
| 6 | A-RESULT-001 | 개인 행동 결과 | 다음 행동을 명확히 제시 | 냉장 보관, 섭취 보류, 문의 후보 | 행동 선택 | 종료 또는 지원 | 행동 결정 | VC023-REQ-003·006 |

### A-4. 상품 슬라이드 역할

- 15개 슬롯을 **개인 사용 상황에 적합한 제품 후보**로 탐색한다.
- 카드의 핵심 정보는 맛·가격이 아니라 `보관 정보 확인 상태`, `개봉 후 정보 상태`, `이동 조건 상태`다.
- 실제 값이 없으므로 모든 카드는 `NOT_VERIFIED`다.

### A-5. 장단점

- 장점: 가장 짧고 모바일 사용성이 높으며 VC-023의 핵심 문제와 직접 연결된다.
- 위험: 실제 보관 데이터가 없으면 정보 가치가 제한된다.

## 5. 설계안 B — 선물용 수령·보관 판단

### B-1. 접속 시나리오

사용자는 다른 사람에게 YOVIA를 보내려 한다. 받는 사람이 배송 시점에 부재할 가능성, 냉장고에 바로 보관할 수 있는지, 알레르기·주의 정보를 어떻게 전달할지를 판단한다.

### B-2. 사용자 흐름

```text
B-MAIN 선물 목적 시작
→ B-RECIPIENT 수령 상황 확인
→ B-GIFT 상품·구성 후보 15개
→ B-DELIVERY 전달·수령 조건
→ B-GUIDE 수령인 보관 안내
→ B-REVIEW 선물 적합성 검토
```

|---:|---|---|---|---|---|---|---|---|

### B-4. 상품 슬라이드 역할

- 15개 슬롯을 **선물 적합성 후보**로 탐색한다.
- 카드에는 `선물 포장`, `수령 안내`, `냉장 배송`, `알레르기 표시`의 검증 상태를 둔다.
- 실제 선물 구성과 배송 정책은 미확정이므로 구매 CTA를 활성화하지 않는다.

### B-5. 장단점

- 장점: 개인용과 다른 수령인 관점과 정보 전달 문제를 명확히 드러낸다.
- 위험: 현재 선물 포장·배송 정책 근거가 없어 `조건부 설계` 비중이 높다.

## 6. 설계안 C — 단체용 수령·보관·배포 판단

### C-1. 접속 시나리오

회사, 학교, 행사 담당자가 여러 명에게 제품을 제공하려 한다. 인원수만큼 수령한 뒤 냉장 공간을 확보하고, 정해진 시간 안에 배포하며, 알레르기·이상 제품 대응까지 운영할 수 있는지를 검토한다.

### C-2. 사용자 흐름

```text
C-MAIN 단체 도입 시작
→ C-SCOPE 인원·행사·장소 정의
→ C-PRODUCT 단체용 후보 15개
→ C-RECEIVE 수령·검수 계획
→ C-STORAGE 냉장 보관·배포 계획
→ C-SAFETY 구성원 안내·이상 대응
→ C-DECISION 도입 가능성 판정
```

### C-4. 상품 슬라이드 역할

- 15개 슬롯을 **단체 운영 적합성 검토 대상**으로 사용한다.
- 카드에는 `대량 공급`, `보관 공간`, `배포 편의`, `알레르기 자료`, `이상 대응` 상태를 표시한다.
- 실제 공급량·단가·납기·계약 조건은 VC-023 근거에 없으므로 `NOT_VERIFIED`다.

### C-5. 장단점

- 장점: 개인·선물과 완전히 다른 수령·검수·보관·배포 책임을 설계할 수 있다.
- 위험: 공급 정책은 VC-024의 전문 범위와 겹치므로 실제 구현 전 두 Client의 Requirement를 함께 검토해야 한다.

## 8. 추천

### 1순위: A안 개인용

VC-023의 기존 Requirement만으로 가장 완결성 있게 설계할 수 있다. 접속 목적이 명확하고, 보관 조건 확인에서 이상 상태 판단까지 짧게 이어진다.

### 2순위: C안 단체용

차별성이 가장 크지만 대량 공급·납기·계약은 VC-024 자료가 필요하다. VC-023은 냉장·검수·배포 안전을 담당하고 VC-024는 공급·계약을 담당하는 결합 설계가 적합하다.

### 3순위: B안 선물용

의미 있는 목적이지만 현재 선물 포장·배송·메시지 정책 근거가 부족하다. 향후 선물 경험 전용 Client를 생성하면 독립성이 강화된다.
