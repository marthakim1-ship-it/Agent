# YOVIA 핵심 화면 스토리보드 — 총 3장

## 1. 문서 정보와 입력 검증

- 작성 기준일: 2026-08-13
- 입력 루트: `설계 출력물/`
- 확인 Client: `001_서하린`~`021_김서준` 21개
- 정상 핵심 입력: 사이트맵 21개, 서비스 흐름도 21개, 화면 설계서 21개(총 63개)
- 보조 입력: 사이트맵 MMD/SVG 각 21개, 서비스 흐름도 MMD/SVG 각 21개(총 84개)
- 누락·손상: 없음
- 공통 원본 화면 ID: 전 Client에서 `MAIN-001`, `CATEGORY-001`, `BRAND-001` 일치
- 입력 우선순위: 화면 설계서 → 서비스 흐름도 → 사이트맵 → MMD/SVG
- 제외: `스토리보드 결과/제외항목.txt`는 이번 실행 입력으로 사용하지 않음. Figma, HTML, CSS는 생성·수정하지 않음.

## 2. 통합 설계 근거와 핵심 사용자 목표

21개 독립 설계를 단순 연결하지 않고 공통 목표와 목적별 보조 요구로 통합했다. 최상위 목표는 사용자가 첫 화면에서 YOVIA를 그릭요거트 기반 간편 건강식으로 이해하고, 미확정 상품 슬롯을 사실로 오인하지 않으면서 카테고리와 브랜드 근거로 이동하는 것이다.

## 8. 반응형 설계 기준

- 모바일 `<768px`: 단일 열. 핵심 정보 → 상태·주의 → 탐색 → 행동 순서를 유지한다.
- 태블릿 `768~1199px`: 2열을 사용할 수 있으나 DOM과 읽기 순서는 모바일과 동일하다.
- 데스크톱 `≥1200px`: 최대 콘텐츠 폭 1280px, 상품은 최대 3열로 확장한다.
- 위 브레이크포인트와 최대 폭은 입력에서 확정되지 않은 **가정**이다.
- PRODUCT-001~015의 DOM 순서와 ID는 모든 폭에서 고정한다.
- 320px CSS 폭과 텍스트 200% 확대에서도 정보·조작 손실이 없어야 한다.
- 터치 대상은 최소 44×44px로 설계한다.
- 중요 주의·오류·HOLD 사유를 아코디언 내부에만 숨기지 않는다.

## 9. 접근성 및 콘텐츠 기준

- `header`, `nav`, `main`, 각 `section`, `footer` 랜드마크와 논리적 H1~H3 계층을 사용한다.
- 첫 포커스 요소는 본문 바로가기다. 포커스 순서는 DOM과 의미 순서를 따른다.
- 모든 정보 이미지는 목적 중심 대체 텍스트를 사용하고 장식 이미지는 빈 `alt`로 구분한다.
- 상태·경고·상품군은 색상만으로 전달하지 않고 아이콘과 텍스트를 병기한다.
- 링크·버튼·필터는 키보드로 조작 가능하고 보이는 포커스가 있어야 한다.
- 로딩은 `status`, 오류는 적절한 `alert`, 완료·결과 수 갱신은 방해하지 않는 라이브 영역으로 알린다.
- 실제 카피는 미확정이면 `[카피 작성 필요]`, 이미지는 `[이미지 자산 필요: 대체 텍스트]`로 표기한다.
- WCAG 준수·감사·인증은 근거가 없으므로 `NOT_VERIFIED`다.
