# YOVIA 로고 레퍼런스 자동 실행 규칙

## 1. 적용 범위

이 문서는 다음 폴더의 로고 레퍼런스 수집과 Flow 프롬프트 분석 실행을 통제한다.

```text
C:\kje\UIUXA\WIREFRAME\로고
```

모든 상대 경로는 위 폴더를 기준으로 해석한다.

## 2. 실행 문서

작업은 아래 두 문서를 순서대로 사용한다.

1. `md파일/pin.md`: Pinterest 레퍼런스 검색·선정·캡처·JPG 저장
2. `md파일/pin분석.md`: 신규 JPG 분석·Flow 영문 프롬프트 작성

실행 전에 두 파일을 UTF-8로 모두 읽는다. 파일이 없거나 읽을 수 없으면 작업을 시작하지 않고 중단 원인을 보고한다.

## 3. 실행 명령

사용자가 다음 문장을 입력하면 자동 실행을 시작한다.

```text
실행 시작
```

### 기본 실행 수량

숫자가 없으면 레퍼런스 1개를 수집하고 신규 이미지 1개를 분석한다.

```text
실행 시작
→ 1개 찾기
→ 1개 JPG 저장
→ 저장된 신규 이미지 1개 분석
→ flow.md에 프롬프트 1개 추가
```

### 숫자가 있는 실행 명령

`실행 시작` 뒤에 양의 정수가 있으면 그 숫자를 실행 수량으로 사용한다.

허용 예:

```text
실행 시작 3
실행 시작 3개
실행 시작 3개찾기
실행 시작 3개 찾기
```

위 명령은 모두 다음과 같이 처리한다.

```text
Pinterest 레퍼런스 3개 찾기
→ 검증된 신규 JPG 3개 저장
→ 신규 JPG 3개 분석
→ flow.md에 영문 프롬프트 3개 추가
```

명령에서 인식하는 수량은 `실행 시작` 뒤에 처음 나타나는 양의 정수다.

## 4. 수량 해석 규칙

1. 숫자가 없으면 `1`로 처리한다.
2. `0`, 음수, 소수는 유효한 수량으로 처리하지 않는다.
3. 숫자가 여러 개면 `실행 시작` 뒤의 첫 번째 양의 정수만 사용한다.
4. 요청 수량은 **신규로 저장할 JPG 수**이자 **신규로 분석할 이미지 수**다.
5. 검색에서 탈락한 후보와 저장에 실패한 파일은 완료 수량에 포함하지 않는다.
6. 기존 `output/` 이미지는 신규 수집 수량에 포함하지 않는다.
7. 기존 파일 중 가장 큰 번호의 다음 번호부터 연속으로 저장한다.

## 5. 고정 실행 순서

`실행 시작` 명령은 반드시 아래 순서로 실행한다.

```text
1. 실행 수량 해석
2. md파일/pin.md 읽기
3. md파일/pin분석.md 읽기
4. input/ 이미지 전체 확인
5. 레퍼런스/ 이미지 전체 확인
6. output/ 기존 JPG 목록과 최대 번호 확인
7. pin.md 기준으로 Pinterest 후보 검색
8. 후보별 선정·제외 기준 검증
9. 검증된 이미지를 output/에 JPG로 저장
10. 요청 수량만큼 정상 저장됐는지 확인
11. 저장된 신규 JPG를 다시 열어 육안 검증
12. pin분석.md 기준으로 신규 JPG만 분석
13. output/flow.md에 이미지별 영문 프롬프트 추가
14. 수집 수량과 분석 수량 일치 검증
15. 완료 보고 후 중단
```

`pin.md` 단계의 이미지 저장과 검증이 끝나기 전에는 `pin분석.md` 단계를 시작하지 않는다.

## 6. Pinterest 수집 단계

수집 단계는 `md파일/pin.md`를 그대로 따른다.

- `input/`을 형태 기준으로 사용한다.
- `레퍼런스/`를 스타일·품질 기준으로 사용한다.
- Pinterest 핀의 실제 이미지를 확인한다.
- 로그인 팝업·Pinterest UI·주변 추천 이미지가 포함된 화면 전체 캡처는 저장하지 않는다.
- 이미지 영역 캡처 또는 공개 대표 이미지(`i.pinimg.com`)를 사용한다.
- 흰색 배경, 검정 단색 또는 흑백, 평면 심벌 조건을 우선한다.
- 목업·3D·컬러 의존·중복·워터마크·잘림 이미지는 제외한다.

파일명 규칙:

```text
output/pinterest_similar_logo_01.jpg
output/pinterest_similar_logo_02.jpg
output/pinterest_similar_logo_03.jpg
```

기존 파일은 덮어쓰지 않는다.

## 7. 분석 단계

수집 단계가 정상 완료되면 `md파일/pin분석.md`를 실행한다.

- 이번 실행에서 새로 저장된 JPG만 분석한다.
- 신규 이미지 수와 동일한 수의 영문 프롬프트를 작성한다.
- 각 프롬프트는 `output/flow.md`에 누적한다.
- 이미지 파일명을 Markdown 대제목으로 사용한다.
- 한 이미지당 프롬프트는 정확히 1개다.
- 기존 파일명 항목이 있으면 중복 작성하지 않는다.
- 기존 프롬프트는 `재실행` 명령이 없으면 수정하지 않는다.

예:

```md
# pinterest_similar_logo_03.jpg

Create an original minimalist logo symbol for YOVIA ...
```

## 8. `재실행` 명령과의 관계

`실행 시작`은 신규 레퍼런스 수집과 신규 프롬프트 추가 명령이다. 기존 프롬프트를 다시 작성하는 명령이 아니다.

```text
실행 시작
→ 신규 이미지 수집 및 신규 항목만 추가

재실행
→ pin분석.md 규칙에 따라 기존 이미지 프롬프트 재분석
```

사용자가 `재실행`을 명시하지 않으면 `flow.md`의 기존 프롬프트를 교정·확장·요약·교체하지 않는다.

## 9. 부분 실패 처리

요청 수량을 모두 확보하지 못하면 다음과 같이 처리한다.

1. 검색어를 `pin.md`의 확장 순서에 따라 변경한다.
2. 같은 검색 결과를 반복 저장하지 않는다.
3. 기준을 낮춰 부적합 이미지를 저장하지 않는다.
4. 정상 저장된 신규 이미지만 분석한다.
5. 최종 수집 수량이 요청 수량보다 적으면 완료로 숨기지 않고 부족 수량과 원인을 보고한다.
6. 저장되지 않은 후보는 분석 수량에 포함하지 않는다.

핵심 입력 파일 누락, Pinterest 이미지 확인 불가, `output/` 쓰기 실패가 지속되면 작업을 중단한다.

## 10. 완료 조건

다음 조건을 모두 만족해야 완료다.

- 요청 수량을 정확히 해석했다.
- `input/`과 `레퍼런스/` 이미지를 모두 확인했다.
- 요청 수량만큼 신규 JPG가 `output/`에 저장됐다.
- 모든 신규 JPG가 정상적으로 열린다.
- 이미지에 팝업·Pinterest UI·목업·심한 워터마크가 없다.
- 기존 파일과 중복되지 않는다.
- 신규 JPG 수와 신규 Flow 프롬프트 수가 일치한다.
- `flow.md` 대제목과 실제 JPG 파일명이 일치한다.
- 모든 프롬프트가 영문이다.
- 기존 프롬프트를 무단으로 변경하지 않았다.

## 11. 완료 보고 형식

```md
# 실행 완료

- **요청 수량**: N
- **신규 수집 이미지**: N
- **신규 분석 이미지**: N
- **저장 이미지**:
  - `로고/output/pinterest_similar_logo_XX.jpg`
- **프롬프트 파일**: `로고/output/flow.md`
- **Pinterest 출처**: ...
- **제외·실패 후보**: ...
- **검증 결과**: JPG 정상 / UI 없음 / 중복 없음 / 영문 프롬프트 N개
```

## 12. 금지 사항

- `input/` 또는 `레퍼런스/` 확인 없이 검색
- 요청 수량보다 많은 이미지 저장
- 기존 `output/` JPG 덮어쓰기
- Pinterest 페이지 전체를 결과 이미지로 저장
- 로그인 팝업이나 사이트 UI가 포함된 이미지 저장
- 목업·3D·컬러 의존 이미지를 기준 통과로 처리
- 같은 이미지 또는 사실상 동일한 이미지 중복 저장
- 이미지 저장 완료 전 분석 단계 실행
- 저장되지 않은 후보의 프롬프트 작성
- 신규 이미지 수와 다른 수의 프롬프트 작성
- `재실행` 명령 없는 기존 프롬프트 수정
- 영문이 아닌 Flow 프롬프트 작성
