# 홈페이지 레퍼런스 분석 스킬 (Website Reference Analyzer)

이 스킬은 수집된 홈페이지 레퍼런스 리서치 자료를 바탕으로 4~5단계의 표준 템플릿 및 8단계 정밀 분석 논리에 따라 분석을 수행하고, UTF-8 인코딩 방식의 `.txt` 메모장 보고서를 자동 생성합니다.

---

## 1. 데이터 수집 및 탐색 규칙 (1~2단계 & 예외 처리 보완)

1. **[기본 리서치 자료 자동 탐색]**
   - 파일명에 **`[리서치 결과]`**가 포함된 모든 파일 및 `research/YOVIA_BRAND_REFERENCE_RESEARCH_200.txt` (또는 `research/batches/` 내 배치 파일들)을 기본 리서치 자료(Base Research)로 자동 탐색하여 사용합니다.
2. **[대용량 배치 로딩 지원]**
   - 500KB 이상의 대용량 텍스트 파일 탐색 시, `research/batches/batch-*.txt` 배치 파일들을 순차적으로 분할 수집하여 메모리 및 컨텍스트 부하를 방지합니다.
3. **[추가 자료 입력 명령 감지 및 저장]**
   - 사용자가 **`"리서치 자료 추가 입력"`**이라고 명령하면, 이후 입력되는 파일, URL, 텍스트를 추가 자료(Additional Research)로 인지하여 `research/additional/` 폴더에 영구 보존 관리합니다.
4. **[누적 병합 및 덮어쓰기 금지]**
   - 새로운 추가 자료는 기존 분석 자료를 덮어쓰지 않고 누적 병합합니다.
5. **[출처 분리 표기 및 URL 정규화]**
   - 보고서 작성 시 **[기본 자료 출처]**와 **[추가 자료 출처]**를 구분하여 명시합니다.
   - URL 정규화(프로토콜 `http://`, `https://` 및 끝 슬래시 `/` 정제)를 통해 동일 사이트 중복 발견 시 1개로 통합하되, 발견된 수집 출처는 모두 보존하여 기록합니다.

---

## 2. 결과물 저장 및 파일 분할 규칙 (3~5단계)

1. **[출력 저장소]**: 결과물은 프로젝트 루트 내 `output/` 폴더를 자동 생성하여 저장합니다.
2. **[파일 포맷]**: 모든 분석 결과물은 **UTF-8 인코딩 방식의 `.txt` 메모장 파일**로 생성합니다.
3. **[용량 수량 제한]**: 1개 TXT 파일당 **최대 100개 홈페이지 분석 결과**를 수록합니다. (홈페이지 1개 = 분석 결과 1개 단위)
4. **[파일명 분할 네이밍]**: 100개 초과 시 `output/홈페이지_분석_001-100.txt`, `output/홈페이지_분석_101-200.txt` 형태로 순차 네이밍하여 출력합니다.
5. **[무단절 원칙 (No Split)]**: 1개 홈페이지의 분석 전체 내용(단위 데이터)은 절대로 두 파일로 쪼개어 나누지 않습니다. (100번째 항목이 끝나면 101번째 항목부터 새 파일에 통째로 기록)
6. **[3대 영역 독립 분리]**: 아래 3개 영역을 보고서 내에서 각각 명확히 독립적으로 분리하여 작성합니다:
   - **영역 1: 홈페이지별 분석** (기본 정보 + 7개 세부항목)
   - **영역 2: 전체 비교 분석** (공통점, 차이점, 패턴, 우수사례)
   - **영역 3: 최종 인사이트** (적용 아이디어, 우선 참고 사이트, 주의점, 추가 조사 내용)

---

## 3. 5단계: 홈페이지 1개 단위 표준 분석 템플릿

각 홈페이지 레퍼런스 분석 시 다음 표준 서식을 엄격히 적용합니다:

```text
--------------------------------------------------------------------------------
[홈페이지 레퍼런스 #{{ID}}] {{SITE_NAME}}
--------------------------------------------------------------------------------
1. 기본 정보
   - 홈페이지 이름: {{SITE_NAME}}
   - URL: {{SITE_URL}}
   - 업종: {{INDUSTRY}}
   - 정보 출처: {{SOURCE_TYPE}} ([기본 자료] 또는 [추가 자료])

2. 세부 분석 (4단계 기준 적용)
   - 디자인 특징: {{DESIGN}} (컬러, 톤앤매너, 비주얼 컨셉)
   - 화면 구성: {{LAYOUT}} (레이아웃, 그리드, 영역 배치)
   - 사용자 흐름: {{FLOW}} (GNB, 정보 구조, CTA 흐름)
   - 문구와 콘텐츠: {{COPYWRITING}} (슬로건, 카피라이팅, 톤오브보이스)
   - 주요 기능: {{FEATURES}} (인터랙션, 주요 도구, 대표 기능)
   - 장점과 단점: {{PROS_CONS}} (우수한 점 및 페인포인트)
   - 참고할 부분: {{BENCHMARK}} (벤치마킹 핵심 요소)
--------------------------------------------------------------------------------
```

---

## 4. 8단계 정밀 분석 실행 프로세스 (6단계)

AI는 수집된 홈페이지 레퍼런스를 분석할 때 반드시 다음 **8단계 정밀 분석 논리**를 준수하여 실행합니다:

1. **[홈페이지별 개별 분석]**: 5단계 표준 템플릿에 맞춰 7개 항목 추출
2. **[비슷한 내용 그룹화 (Grouping)]**: 메인 카피, 제품 이미지, CTA 버튼 위치, 후기 등 요소 묶기
3. **[등장 횟수 및 비율 기록]**: 전체 대상 홈페이지 수 대비 발견 횟수 및 비율(%) 정량 기록
4. **[패턴 구분 (수치 + 가치 판단)]**:
   - **공통 패턴**: 전체 중 30% 이상
   - **반복 패턴**: 10% 이상 ~ 30% 미만
   - **특이 사례**: 10% 미만 중 참고 가치가 높은 아이디어
5. **[공통점과 차이점 도출]**: 대부분 사용 방식 / 업종별 차이 방식 / 반대 방식 / 독자적 방식 대조
6. **[패턴별 장단점 분석]**: 패턴명, 사용 홈페이지, 장점, 단점, 어울리는 상황, 주의점 기록
7. **[최종 인사이트 수립 (출처 연계)]**: 필수 참고 / 선택 참고 / 차별화 참고 (근거 출처 표기 필수)
8. **[추가 조사 항목 명시]**: 추측 금지 ➔ `[추가 조사 필요 / 확인할 내용 / 현재 부족한 근거]` 명시
